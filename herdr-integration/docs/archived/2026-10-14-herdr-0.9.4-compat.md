## 现象 / 现状

本机 herdr 已升到 **0.9.4**（`herdr status` 原文：client 0.9.4 / server 0.9.4、
`endpoint_compatible: yes`、`private_protocol: 22`、`private_protocol_compatible: yes`、
`restart_needed: no`、`server_binary_stale: no`）。本包不解析 herdr 版本、无版本感知；依赖面四类：
① 握手环境变量 `HERDR_ENV` / `HERDR_SOCKET_PATH` / `HERDR_PANE_ID`；② 三个 method
`pane.report_agent_session` / `pane.report_agent` / `pane.release_agent`；③ `seq` 单调递增与
「收到响应数据即视为送达」语义；④ 验证工具面 `herdr api snapshot`。

## 结论

**(a) 无需改动**。herdr 0.9.3 → 0.9.4 无任何影响本包的协议或命令面变化；三个 method 的报文在
protocol 22 活 server schema 与官方 add-herdr-support 文档（0.9.4 版）中逐字段吻合，真机往返验证
通过。本包维持无版本感知现状是安全的。

## 证据

- **① 发布说明**（herdr CHANGELOG，0.9.4 于 2026-10-13 发布）：Added / Changed / Fixed / Removed 全部
  与本包无关（插件更新、Windows 通知与输入、服务器生命周期、输入法与键盘等）。**无协议版本条目**；
  0.9.3 是 0.9.2 的 hotfix（终端快捷键），0.9.2 的 breaking 是 `pane.graphics.*` 下线（本包不使用）。

- **② protocol 22 活 server schema**（`herdr api schema`，2026-10-14 实测）逐 method 比对
  `src/herdr.ts`：

  - `pane.report_agent`：required `pane_id / source / agent / state`，可选 `agent_session_id / agent_session_path / message / seq / resume_argv`；state 枚举为 `idle / working / blocked / unknown`（本包只用前三个）——本包报文字段全覆盖、required 全覆盖。
  - `pane.report_agent_session`：required `pane_id / source / agent`，可选 `agent_session_id / agent_session_path / resume_argv / seq / session_start_source`——本包报文吻合。
  - `pane.release_agent`：required `pane_id / source / agent`，可选 `seq`——本包报文吻合，
    退出释放路径仍受支持。
  - `seq` 语义：schema 与官方文档均要求单调递增、只接受比上次更大的序号；`src/herdr.ts:100` 以
    `Date.now()*1000` 为起点逐条 +1，与 pi 原生一致。

- **③ 官方 add-herdr-support 文档**（[herdr.dev/docs/add-herdr-support/](https://herdr.dev/docs/add-herdr-support/)，
  文档版本 0.9.4）：状态上报 / 会话上报 / 退出释放三个动作、`HERDR_ENV=1` 且其余变量齐才上报的握手、
  `seq` 语义、「未 release 时 pane 回到 idle shell 后 herdr 自动清 agent」安全网——与本包
  `README.md`「能力」节全部吻合。

- **④ 真机往返**（2026-10-14，本 pane `wQF:p1`，`HERDR_ENV=1`）：直连 unix socket 按 `src/herdr.ts`
  同构报文发 `pane.report_agent`（idle / working 两条），均返回 `{"result":{"type":"ok"}}`；
  `herdr api snapshot` 确认 pane 状态随之翻转并复原（结束态 working，与真实状态一致）。快照另见
  `codex` agent 携带 `agent_session` 正常展示，同一 server 的会话上报通路工作正常。

- **⑤ 握手面与命令面**：`HERDR_ENV` / `HERDR_SOCKET_PATH` / `HERDR_PANE_ID` 在 0.9.4 环境变量表中
  原样存在；`herdr api snapshot` / `herdr status` 子命令仍可用。

## 附注（新集成面，值得接的另开条目，不在本条内顺手做）

- **`resume_argv`（0.9.2 新增，本包未用）**：`pane.report_agent` / `pane.report_agent_session` 均可
  携带 `resume_argv` 数组，herdr 重启后在同 pane 重开精确会话（官方文档「the same session back in
  the same pane after a Herdr server restart」）。旧版本忽略该字段、不影响现状。是否接入取决于 dsh
  是否有 CLI 会话恢复入口（需先核宿主面），建议新条目 P3。
- **`pane.report_metadata`（title / state_labels / tokens）**：展示层定制，本包无需求，不改。
- **`pane.clear_agent_authority`**：另一条清 authority 的方式；官方文档仍以 `pane.release_agent`
  为退出释放路径，本包保持现状。
- **source 前缀**：官方文档建议 source 勿以 `herdr:` 开头（该前缀属 herdr 自带集成）；本包沿用 pi
  惯例默认 `herdr:dsh`，属既有设计，不构成兼容问题，仅记录。
