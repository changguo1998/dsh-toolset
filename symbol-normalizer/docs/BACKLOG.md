## 1. 缺陷与改进

### F1. 符号审查未豁免代码段与引用示例

- **现象**：回合审查把**整回合正文**直接交给符号扫描（`src/review.ts:42-45` → `normalizeSymbols(text, rules)`），没有代码围栏 / 内联代码掩码。于是在正文里**举例说明替换规则**（如写「别名替换（`✔→✓`、`❌→✗`）」）同样命中违规 → 向人推 notice 并向模型注入 `[符号规范]` 反馈，要求把 `❌` 改成 `✗`（2026-09-29 实测，一次）。
- **影响**：讨论/记录符号规范、写文档、引用报错文本等场景反复触发提醒；模型被要求改掉它本就该引用的字符；人类侧 notice 噪音。
- **修法（择一或组合）**：
  1. 审查前掩码围栏代码块与内联代码（只审散文部分）；
  1. 命中项紧邻 `→` / `->` 或成对出现（引用示例）时不记违规；
  1. 粒度细化：对「被引用示例」只提示人类、不注入模型（`warnModel` 再分档）。
- **验收**：构造「举例说明替换规则」的回合 → 不产生模型反馈注入；真实使用 emoji 的回合仍照常提醒；单测覆盖掩码前后对照与真实违规对照。
- **状态**：待接取（2026-09-29 实测发现）。优先级 P2。

### F2. 会话开始注入「推荐符号列表 + 符号使用标准」

- **目标**：新会话开局就主动注入一次**推荐符号白名单**与**符号使用标准**，让模型从第一句起就按规范输出，减少「先违规、回合末才被提醒」的往返（现在的审查只在违规后注入，见 `src/review.ts:96`）。
- **注入内容（两者都要，且文本应从 config 生成而非硬编码）**：
  1. **推荐白名单**：`DEFAULT_RECOMMENDED` 全量（✓ ✗ △ → ← ↑ ↓ ↔ ↕ ▶ ◀ ▲ ▼ • ◦ ○ ● ■ □ ◇ ◆ ⓘ 〜 … 等）及其「几何简单、列宽确定、无填色」的选型理由；
  1. **使用标准**：禁用 emoji 与列宽不定字符（本目录 F1 的反面）；别名替换口径（`✔→✓`、`❌→✗` 等，展示层会替换但**会话记录仍原样**，故应直接用推荐符号）；不纳入清单（不治理的字符类）；使用场景口径（状态 / 方向 / 几何类用推荐符号或文字，装饰性强调不用符号）；宽度约束（每符号恒 1 列）。
- **触发点（需调研后定，二选一）**：
  1. **宿主 system prompt 面**：若 profile / agent 面可注入静态指令，则最彻底（首 token 之前生效）；需调研 dsh-base 的 agent 指令面。
  1. **rule-engine 每会话一次注入**：仿 `skill-autoload-on-unlock`（`source: tool-call` + `predicates: always` + `cooldownTurns` 极大）= 每会话首次工具调用时注入；缺点：首轮模型正文可能已产出（迟到一步）。
- **开放问题**：每会话一次的判定（cooldownTurns vs 宿主会话事件面）；上下文成本（白名单 + 标准约数行，是否压缩为一行）；与「加载 skill」规则的叠加（同回合注入两条是否合并）；开关（如 `injectAtSessionStart: true|false`，缺省行为需定）；`warnModel` 与注入内容的联动（关了模型反馈是否也关注入）。
- **落点**：`symbol-normalizer/src/main.ts`（注册注入规则或产出指令文本）+ `src/review.ts` / `src/symbols.ts`（从 rules 生成文案）+ 视调研结果决定是否动 profile / TUI kickoff。
- **验收**：新会话首轮即出现「白名单 + 使用标准」注入且每会话仅一次；改 config（如 `recommended`）后注入文本随之变化（非硬编码）；开关关闭时不注入；不改变既有回合审查行为；单测覆盖「生成文案内容」与「每会话一次」的判定。
- **状态**：待接取（2026-09-29 用户提出）。优先级 P2。
