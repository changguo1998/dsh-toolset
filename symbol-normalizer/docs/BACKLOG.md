## 待办

- **待办** **#1 同一进程内的压缩不会补注入开局指南（gate 记账后短路，要等下次重启）**：
  - **现象**：进程内首次评估时投影里还有旧指南 → 只记账、不注入；此后同一进程内发生压缩把指南挤出上下文，模型在剩余回合里不再看到符号规范（且无任何提示）。对照 rule-engine 侧：skill 规则在每次 `compaction/end` 重新按投影判定并补一次，同进程内也补。
  - **现状**：消费者 `symbol-normalizer-guide`（`src/main.ts:155-184`）第一道门 `if (gate.has(sessionId)) return null;` 命中即短路——一个进程内最多评估一次；`SymbolGuideGate` 只在注入或历史命中时记账（`src/guide.ts:57-85`），压缩不使其失效。
  - **证据（2026-10-01 会话记录）**：seq 8194–8197 的压缩把 seq 7694 的指南挤出投影（`shadowedRange` 7659–8187）后，只出现 skill 注入（8198），此后 200+ 事件（含多次回合边界）无指南注入；同进程 gate 在 turn 8168 的评估点已记账（当时 7694 尚在投影内）。
  - **期望**：与 rule-engine 的 `dedupeInRecord` 同口径——每次压缩后按可见投影重新判定，看不见就补一次（同进程内也补）。
  - **待查**：① 让 gate 在压缩后失效——`decide` 的 `context` 是否带得到压缩事件（或需经 rule-engine 新增消费者上下文）；② 或把指南改成 rule-engine 规则（正文由 config 动态生成，需「动态正文」能力，与 rule-engine BACKLOG「多条注入合并为一条」同批考虑）；③ `decide` 的评估点是否覆盖全部回合边界。
  - **落点**：`src/main.ts` 去重分支 / `src/guide.ts` 门控（或 rule-engine 侧动态正文）。
  - **验收**：同进程内压缩后指南补注入一次；补一条单测（压缩后投影无指南 → 再次 `decide` 返回注入）。
  - **来源·状态·优先级**：2026-10-01 会话中由「两类注入行为对齐」讨论衍生（裁定「不改为跨压缩不补」后核验预测时发现）。**未开工**。优先级 P2。
