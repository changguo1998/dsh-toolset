## 决策

**D1｜落点与强度？** → **只改引导文案 + README**，沿用用户裁定（偏好级 → 先用引导）。不建标点映射表、不加间距 pass、不改写模型输出、不动治理区与别名表。**`normalizeSymbols` 行为零变化**（现有 40 例测试全绿即为证据；升级路径见 BACKLOG 条目正文，备查）。

**D2｜放在指南的哪一位置、几条？** → 插在 ② 之后、白名单之前，**两条独立编号**（标点与符号属不同字符集、分开更可执行）：新 ③ 标点、新 ④ 符号间距；原 ③④⑤ → ⑤⑥⑦。理由：守住「泛化在前、具体清单在后」的既有次序；两条拆开而不是并成一条，是因为触发字符集不同（标点 vs 非 ASCII 符号），模型按条执行更不易漏。（子代理复核同意该拆分与位置。）

**D3｜文案措辞（草案，示例一律行内代码）**

- `3. 中文标点（`，。；：！？`）改用英文标点，且标点后留一个空格（`，好`写`, 好`）。`
- `4. 非 ASCII 符号（几何 / 状态 / 圈点 / 箭头等）后留一个空格，不紧贴文字（`✓完成`写`✓ 完成`）。`
- ③ 加「中文标点（…）」**范围界定**（子代理建议，已采纳）：`，`(U+FF0C) / `。` / `（` / `）` 都不在治理区（全角区只收 `0xffe0-0xffe6`，`src/symbols.ts:28`）且 `isPassable` 覆盖 `0xff00-0xff60`（`:397`）→ 不会被审查判违规；但**界定范围**能让模型知道只换标点、不动其它全角字符。该句 masked 与 unmasked 实测均 `replacedCount=0` / `unrecommended=[]`（子代理）。
- 示例括注与既有「无解释性括注」不变式的张力：③④ 的 `（…）` 是**示例**而非解释，测试只黑名单固定串（**不会红**）；`src/guide.ts:23-27` 的注释措辞随之放宽为「除示例外无解释性括注」。
- **不放**「箭头不要改成 `->`」之类表述：用户裁定的「箭头不用动」是**不要引入 `->` 替代**，文案里出现 `->` 反而可能诱导模型去改箭头（子代理复核：白名单已含 `→`，`src/symbols.ts:75-76` 明确 `->` 只是 2 列渲染兜底）；箭头在 ④ 里只承担「后加空格」这一条。
