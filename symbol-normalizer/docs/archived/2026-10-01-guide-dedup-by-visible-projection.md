## 目标

查清「恢复（重载）会话仍被注入 `[符号规范] 会话开局指南…`」的成因：是去重失效，还是别的注入路径被误认为「重载重复注入」；据此定处置（改代码 / 关闭为设计行为）。

## 调研（2026-10-01，证据取本会话记录）

方法：解压会话记录 `~/.dsh/sessions/--home-guochang-Projects-dsh-toolset--/tui-9c0c2a21-21c1-4a34-b84b-33f55064829d/session.v4.jsonl.zstd`（8219 事件），列出全部 guide 注入（`agent/inbox/spliced` 中 `source.kind === "rule-engine"` 且 `summary === "符号规范（会话开局指南）"`）与全部 `compaction/*` 事件，按 seq 对齐。

结果：

1. 指南注入共 **6 次**：seq 357 / 2017 / 3017 / 4384 / 7063 / 7694；`compaction/end` 共 **5 次**：1508 / 2767 / 4361 / 6702 / 7660。除首次（seq 357，开局）外，**每次指南注入都紧跟当次压缩**：2017>1508、3017>2767、4384>4361、7063>6702、7694>7660。
1. **纯重载（无压缩）不注入**：本轮两次进程重启后（skill 规则注入点 8054 / 8198 所在的回合）都没有出现指南注入；同一记录内的网关也未见「重载即注入」的字段。
1. 判定：现象**不是「跨重启去重未命中」**，而是「**压缩把旧指南挤出可见投影 → 去重判空 → 按设计补注入一次**」。

三个待查项的结论：

- **待查①**：`sessionMessagesOf`（`src/main.ts:89-102`）读 `sessions.get(id).deriveMessages()`，即**压缩后的可见投影**。压缩（`compaction/summary` 的 `shadowedRange`）把旧指南消息挤出投影后 `hasGuideMessage` 判空，于是再注入——属判据口径，不是「历史未就绪 / 时序读不到」。
- **待查②**：重载会话 id 不变——同一份 session 记录文件贯穿多次重启、注入 seq 连续追加，进程内 `SymbolGuideGate` 与历史门按同一 id 记账，失效不成立。
- **待查③**：记录里的 `source.summary` 与 `GUIDE_SUMMARY` **逐字一致**（扫描输出即 `符号规范（会话开局指南）`），前缀 / 空格差异不成立。

附带一致化观察：本任务期间 rule-engine 侧刚落地的 `dedupeInRecord` 用的是同一判据（按可见投影去重），效果同口径——「投影里看不见才补一次」。两个包的「压缩前后行为」由此对齐。

**预测核验（结论修正）**：原预测「压缩 8195 后回合边界会补注入一次指南」**不成立**——seq 8198 之后（截至 8427 事件、含多次回合边界）无任何指南注入。真因：`decide` 的第一道门 `if (gate.has(sessionId)) return null;` 在**本进程更早的评估点**（turn 8168，当时 7694 那条指南仍在投影里）就已记账，进程内一旦记账即短路。故指南的实际语义是「**新进程 + 评估时投影里已无指南**才补一次」，同一进程内的压缩不补——与 rule-engine 侧每次 `compaction/end` 重新判定不同，该差异已作为新条目交 `symbol-normalizer/docs/BACKLOG.md`。`dedupeInRecord` 在 seq 8198 补注入 skill 规则仍成立（8054 那条确实已不在投影内）。
