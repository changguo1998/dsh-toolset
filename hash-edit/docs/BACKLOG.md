## 待办

### #1 同一文件并发 `hash_edit` 的临时文件名冲突（同进程）

- **现象 / 现状**：`fs.ts` 的原子写临时路径为 `.<name>.hashedit-<pid>.tmp`（只带进程号）。同一进程内对**同一文件**并行发起两次编辑（示例：同一步并行工具调用、父 agent 与子 agent 同时改同一文件）会共用同一临时文件——先到者的 `writeFile` 可能被后到者覆盖，`rename` 落盘的内容与各自返回的 `result.content` 不再对应；后到者还可能因 `tmp` 已被 rename 而 `ENOENT` 失败。表现为「返回成功但文件内容不是本次编辑结果」的静默不一致。
- **前提未核实**：宿主是否并行执行同一步的工具调用、子 agent 是否与父同进程，均未实测（本条按「可能」登记）。
- **期望**：临时文件名带调用级唯一后缀（随机数 / 自增序号），或对同一目标路径串行化；保证每次调用独占临时文件。
- **疑似范围**：`hash-edit/src/fs.ts`（`applyAnchoredEditsFile` 的 `tmp` 命名与 `writeFile`，可顺带用 `wx` 独占创建防撞）。
- **落点**：`hash-edit/src/fs.ts` + `hash-edit/tests/fs.test.ts`（用同步点/钩子构造确定性并发用例）。
- **验收**：同一目标文件并发两次编辑，二者返回内容与最终文件一致（或后到者显式失败、文件保持先到者结果）；目录无临时文件残留。
- **来源·状态·优先级**：2026-10-05 文档对齐核代码时发现（未复现）；未接取；P3。
