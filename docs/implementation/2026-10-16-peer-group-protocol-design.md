# 同事模型群组的编排协议（接取条目：`docs/BACKLOG.md`「同事模型群组的编排协议」）

状态：决策　　开启：2026-10-16　　关闭：
本文件是本任务唯一的过程记录与文档变更落点；计划外的文件不改。

## 目标

条目要求：实现一套「同事模型群组的编排协议」—— 多个成员模型各跑在独立 pane 里，协议负责建组、分发议题、控制发言权、汇聚结论与收尾。

本轮范围：**只出调研与决策，不写实现代码**。经 2026-10-16 与用户逐条讨论后，条目的原始设想（pane 后端 + 星形发言权 + 轮次与汇聚）被大幅改写：**本包是纯协调层，不碰终端**，只做组、连接、指令、回报四件事。逐条过程见「决策」。

## 调研

### S1 pane 后端（后判定不进本包）

- 两条候选 pane 后端条目「基于 tmux 的交互式命令扩展」与「基于 herdr 的交互式命令扩展（herdr pane 读写）」**均未落地**：工作树分支 `feat/herdr-pane` 与 `main` 同点（`ef73477`）；`herdr-integration` 只有 3 个**出站** method（`pane.report_agent_session` / `pane.report_agent` / `pane.release_agent`，`herdr-integration/src/herdr.ts:135`、`:186`、`:228`），只上报状态。全仓 `tmux` 命中 68 处全在 `.md`，无代码无依赖。
- **命令面实测**（本机 herdr 0.9.5 / tmux 3.4）：herdr 的 CLI 与 socket 两层都具备建组 / 注入 / 读屏 / 收尾原语（`pane split|run|read|send-text|close`、`agent prompt|wait|read`、`api schema` 里的 `pane.read` / `pane.send_text` / `agent.wait` 等），且每 agent 带 `idle|working|blocked|done|unknown` 与单调 `state_change_seq`；tmux 命令面齐（`new-session` / `split-window` / `send-keys` / `capture-pane` / `kill-pane` / `wait-for` / `pipe-pane`），但**无 agent 状态概念**，就绪与结束判定只能自建（`#{pane_dead}` / `#{pane_current_command}` / `#{window_activity}` + `alert-activity|bell|silence` hook）。跨机只有 herdr 有（`--machine` / `--remote`）。
- 结论：pane 能力**没有必要进本包**（决策项 2）。该对比仅作为「本包不需要它」的依据留档。

### S2 session-channel（现行传输）

- 拓扑：专用 Redis + unix socket，键前缀 `dsh:session-channel:`（`session-channel/README.md:50-63`；`session-channel/src/keys.ts:7-105`）；`peers` 枚举在线会话（`session-channel/src/index.ts:423-431`）。
- **投递是单播**：目标须唯一命中，0 命中 `target_offline`、多命中 `target_ambiguous`；实现为 XADD 入目标 inbox，接收方在其下一回合收到，正文形如 `[CHANNEL](来源) 正文`（`session-channel/src/broker.ts:381-395`、`:414-448`；`session-channel/src/inject.ts:16`、`:69-106`）。**无广播**（`session-channel/src/index.ts:1204-1207`）。
- 委托任务表：`task:<id>` TTL 7 天，状态机 `pending → running → done/failed/canceled/timeout`，**超时读取时懒判定**（`session-channel/src/types.ts:144-146`；`session-channel/src/tasks.ts:8-11`、`:134-146`）；回收双路（`turn/end` 自动、显式回传优先）（`session-channel/src/index.ts:847-849`、`:879-921`、`:816`）。
- 共享 KV 只有**服务面**（last-value + 单调版本 + CAS），模型侧动作仅 peers / send / inbox / alias / status（`session-channel/README.md:59-60`、`:106`；`session-channel/src/index.ts:1202`、`:1459-1475`、`:1529-1533`）。
- 边界：仅本机；目标离线**直接报错、不排队**；无 TTL 游标防重投（`session-channel/README.md:102-104`）。

### S3 别名与寻址（本机实测）

- 寻址序：sessionId → 别名 → `cwd:<绝对路径>`。
- `peers` 实测 8 个在线会话：其中 **3 个同 cwd**（本 worktree 的 TUI 会话 + 两个子代理），故 `cwd:` 在本机已经会多命中；**不用 `cwd:` 作登记目标**（决策项 12）。
- 别名表实测约 200 条，两类前缀自动生成：`sub-*`（子代理）与 `ui-*`（TUI 会话）；表内绝大多数条目 `online: false`（会话已结束），在线者仅 `ui-clover`（background-daemon 会话）。→ **推断**：别名可能由会话首次用到时才生成，而非启动即分配。

### S4 宿主对等 mailbox（未挂载）

- `experimental-agent-team`（`ctx.agentTeams`）：单会话 Lead / teammate 花名册 + 持久 peer mailbox（离线排队、不丢不重）+ 共享任务 DAG（owner、依赖、CAS），成员支持 `provider` / `model` 与 `fresh|fork`。限制：单进程、单 checkout、无 worktree / 跨进程 / 远程成员。
- 其配套工具包含 `send_message` / `list_agents`，官方明写**取代同名旧版 subagent 控件** → 与已挂载的 `tool-subagent-control`（`docs/host/HOST-PACKAGES.md:74`）**工具名冲突**；且 `experimental-*` 属 2026-10-02 用户裁定的挂载面排除口径（`docs/host/HOST-PACKAGES.md:21`、`:389`）。
- 本包**不使用**它：传输已定 session-channel，且它要求成员同进程、同 checkout。

### S5 未验证项与风险

1. session-channel **服务面**是否暴露「发送指令 / 查询任务」所需方法 —— 调研只见服务面存在的证据，**具体方法名与签名要在实现前核对**。
2. **别名修补**（全机唯一 + 恢复后不变）尚未落地；本包的登记依赖这条假定（决策项 12、13）。
3. 目标唯一命中是硬约束：别名重名或别名失效会让登记指错人或报 `target_ambiguous`。
4. session-channel 仅本机 —— 跨机成员不在范围内（决策项 20）。

## 决策

### 现行决策（2026-10-16 讨论后）

**决策项 1（传输通道）**：a pane 文本（后端插件） / b session-channel / c 共享文件或 KV / d 宿主 agentTeams mailbox → **选定 b**。三条腿（主→从指令、从→主回报、成员间讨论）全走 session-channel：任务表自带 TTL 与懒超时、显式回传优先，省掉自造「未决指令表」。

**决策项 2（与 pane 后端的关系）**：a 自建适配器调 pane 命令 / b 依赖那两条后端条目 / c **完全不依赖** → **选定 c**。传输改走 session-channel 后，本包既不需要建 pane 也不需要读屏；pane 后端的两条条目与本包解耦。（此决定使先前「前置可解除 / 暂不解除」的反复作废 —— 整个 pane 依赖都不存在了。）

**决策项 3（职责边界）**：a 既启动也管理 / b **只管理，不启动不销毁** → **选定 b**。成员是「已存在且可被寻址的会话」；本包不产生、不销毁会话，成员挂了只表现为「回报到不了」。将来若有 pane 后端插件，它是本包的**上游**，经「登记」对接。

**决策项 4（连接模型）**：a 只星形 / b 只树形 / c **两种连接（主从 + 平等）** → **选定 c**。任意两个 agent 之间每种连接**至多一条**；成员彼此之间也可以有平等连接。（先前的「成员之间不直连」作废。）

**决策项 5（主从连接语义）**：**选定**：只能由主向从发指令；从做完必须回报；未回报则**不断检查，超限报错** —— 由**代码逻辑**保证，不靠提示词约定。

**决策项 6（平等连接语义）**：**选定**：双向可发，发完即走，不等回复、不重试、不留状态。

**决策项 7（每 agent 的主从上限）**：a 每个方向各一条 / b **至多一个主、可有多个从** → **选定 b**。指令来源唯一，不会出现两条主从连接争抢同一个成员、回报不知该给谁。

**决策项 8（等级）**：**选定**：主从连接带等级 —— 无主者等级 0；建立时从方等级 = 主方等级 + 1；不允许「主等级 ≥ 从等级」的连接。推论：**等级沿主→从严格递增，环构造不出来**，主从连接天然是一森林，不需要额外禁环检查。

**决策项 9（建立连接的方式与条件）**：a 隐式（第一条指令时建立） / b **显式动作** → **选定 b**：主方发起，当场校验从方是**自由代理**（无主、无从、等级 0）。因为从方必须自由，其下必为空 → **不存在子树重排**，等级只赋一次、此后永不变，森林自上而下单调生长。

**决策项 10（解除连接）**：a 允许解除 / b **不允许解除** → **选定 b**。移除成员须**逐层下推**：要移除某从代理，先由它自己移除它名下的从代理；对非叶子发起移除**被拒绝、不做级联**（决策项 18 要求拒绝带提示）。代价照实记：中间节点一旦失联，它连同整棵子树都移不掉，想清干净只能另建组。

**决策项 11（登记入口）**：a 建组时一次给名册 / b **建组与加成员分开** / c 加 TUI 命令 / d 声明式 → **选定 b**：建组只带组级参数；加成员一次一个（组 + 组内名字 + 目标）；成员集合可变，有对称的移除动作。

**决策项 12（目标写法）**：**选定**：**别名或 sessionId**，不用 `cwd:<路径>`（同目录多会话必然多命中，本机实测已成立）。组内名字由**本包自管**，不占用全机别名空间（别名表是全机一份，不是按组隔离）。前提假定：别名全机唯一且**恢复后不变** —— 该修补属 session-channel 的模块待办（S5 第 2 项）。

**决策项 13（是否要显式开始）**：a 要 / b **不要** → **选定 b**：没有开始门槛，指令随时可发，按**当前**成员集合展开。

**决策项 14（未结指令与结算）**：**选定**：每条主从连接上同时**只允许一条**未结指令（回报靠指令 id 归属）；结算一律在**检查**时懒判定，三种收场 —— 回报已到（成功）、超出等待上限（超时）、成员已被移除（失败）。移除是**纯状态改动**，不推送、不回调。

**决策项 15（「轮」）**：a 要 / b **不要** → **选定 b**：本包不建模轮次，只有「发指令」与「检查」两个动作。

**决策项 16（结论汇聚）**：a **不聚合** / b 只排版 / c 投票多数决 → **选定 a**：本包只给逐条回报；合成结论是管理者（本身是个 agent）自己的事。本包只定义**回报信封**：`成功 / 失败 / 受阻` + 正文 + 成因，**不解析正文**。

**决策项 17（可观测性与介入）**：**选定**：要一个**只读**的组状态动作（组成员、等级与主从关系、未结指令、最近一次回报）；广播与「一条命令发多人」留二期；人工介入不另设动作 —— 成员就是普通会话，人可以直接对它说话。

**决策项 18（拒绝返回）**：**选定**：**所有**拒绝都带**原因 + 下一步**，不只给失败码。例：移除非叶子 → 拒绝，并列出它还剩下的从代理名字。

**决策项 19（包名与落点）**：**选定**：新包 **`agent-group`**（第 22 个插件），**纯协调层** —— 不碰终端、不含适配器；`inject` session-channel 服务面。

**决策项 20（首期范围）**：**选定**：动作 7 个（建组 / 加成员 / 建立主从连接 / 发指令 / 检查 / 移除 / 只读查看）；数据 4 类（组、成员、主从连接含等级、未结指令与回报记录）；机制为懒判定结算 + 每连接一条未结 + 拒绝带原因。二期：广播（连带平等连接的记录与「每对至多一条」校验）、TUI 命令或面板、轮次与终止的三个细节。不做：结论聚合、「轮」、启动与销毁会话、跨机。

### 验收细化（补全条目「待细化」的验收）

1. 建组 + 加成员 + 只读查看：断言成员表含组内名字、目标、等级 0、无从。
2. 建立主从连接：断言从方等级 = 主方等级 + 1；对已认主的 agent 再建连接 → 拒绝且带原因。
3. 非自由代理不能当从：对已有从的 agent 发起收编 → 拒绝（决策项 9）。
4. 每连接一条未结指令：同一主从连接上连发两条 → 第二条被拒且带原因（决策项 14）。
5. 懒判定三收场：假传输分别构造「回报已到」「超出等待上限」「成员已被移除」→ 检查分别返回成功 / 超时 / 失败，失败带成因。
6. 移除规则：叶子可移除；非叶子被拒，提示里列出剩余从代理的名字（决策项 10、18）。
7. 等级无环：断言「主等级 ≥ 从等级」的连接一律被拒（决策项 8）。
8. 拒绝提示：抽样若干拒绝路径，断言都带原因与下一步。
