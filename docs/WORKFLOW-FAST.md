# 内容变更规范 · 快速流程（小改动）

> 职责：改动量少、逻辑简单直接的小改动的快速流程（判据、入口、验证、提交）
> 不负责：标准流程（条目 / 追踪文档 / 四点提交询问，见 `docs/WORKFLOW-STANDARD.md`）、协作命令与构建方式（见 `AGENTS.md`）
> 过期条件：流程调整时更新（简版同步在 `AGENTS.md`）

## 1. 判据与入口

- **入口判据（软性）**：综合考虑——改动量（文件数、行数）、逻辑复杂度、影响面（是否碰接口 / 契约 / 跨模块）、验证成本等；入口不设硬阈值，提交前的**硬阈值复核**见 §2。
- **判定权**：agent 判定后**先问用户**——用 `ask_user_question` 以是非题问「此改动走快速流程？」；询问里须写明依据（改哪里、多大、为何简单）。
- 入口答「否」：**不进入快速流程、不做处理**，等用户新的指示（不自动转标准流程）。
- 改动落在已登记 BACKLOG 条目范围内时：允许走快速流程，但**不更新条目状态**（入口询问中注明）。
- 同一任务只走一条流程，**可升不可降**：快速 → 标准（见 §4），不可反向。

## 2. 流程

1. 入口询问通过后开工：改 → 验证 → 硬阈值复核 → 完成询问 → 提交（中间不设询问点）。
1. 验证按类型：文档 / 注释类 = `format` 改动文件 + 自查 `git diff`；代码 / 配置类 = `npm run check` + `npm run build` + `npm run test`（免 demo / 真机人工确认）。
1. **硬阈值复核**（提交前）：对本次改动范围用 `git diff --numstat` 统计——**文件数 ≤ 3 且增删行合计 ≤ 50**。不达标即停下，用 `ask_user_question` 问「是否转为标准流程？」，三选一：
   - **转标准流程**：补 BACKLOG 条目 + 追踪文档，已有改动并入，按 `docs/WORKFLOW-STANDARD.md` 继续；
   - **维持快速流程**：继续完成询问；
   - **停手**：保留改动、不提交（不再走快速流程），等用户新指示。
1. 完成询问：用 `ask_user_question` 以是非题问「现在提交？」；**必须获明确同意才能继续**（问答面板选择同意继续，或指令中有明确的继续下一步指令）；答「否」/ 未答 / 答非所问 / 仅提问 → 变动留工作区，结束本回合等用户指令。
1. 提交一次，Conventional Commits（中文），message 说明改动。

## 3. 不做

- 免 BACKLOG 条目、免追踪文档、免归档、免回写 DESIGN / README / ROADMAP；`STATUS.md` 沿用标准流程口径（由用户择时更新）。
- 唯一记录是 commit message；未提交时仅在对话中说明。

## 4. 例外与升级

- 验证不通过：修复后重跑；修不动或需扩大范围则停下问用户。
- 过程中若明显超出判据（逻辑变复杂、影响面扩大、需动判据之外的文件 / 模块）→ **立即停下**，照 §2 三选一询问用户，不得静默继续。
- 不得用于：接口 / 契约变更、跨模块改动、需真机人工确认的改动。
