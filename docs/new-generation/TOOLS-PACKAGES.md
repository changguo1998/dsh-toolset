# 模型面工具包规划(新代)

## 目的

本文档梳理模型面工具包的包结构与分层, 及各工具包的职责与边界; 各工具包的模型面工具清单见 TOOLS.md。

## 分层口径

- 工具面取向: 工具小而专, 但「小」只作用于动作维度; 语言与格式(代码 / Markdown / 通用文本)由工具内部按扩展名与内容自动识别, 不按语言拆工具, 不按格式分包。
- 命名: 服务面 `c` + 单词 camelCase(如 cParse); 工具包 `c-` + 短名(如 c-file); 模型面工具 `c_<对象>_<动作>`(如 c_file_structure)。保留现状实现的 TUI / preference-analysis 工具沿用现名(见各节)。
- 分层: 有模型面工具的包在此列; 服务面由底座承担, 包与服务面不是一一对应关系, 服务面维度见 SERVICES-PACKAGES.md。
- 假设所需新服务面(如 cParse 统一解析底座)均已就绪, 不以建成与否调整方案。
- 语言支持渐进扩充, 通用骨架起步(先覆盖 ts / js / py / md / json / yaml / shell)。

## 一、工具包设计

### 文件交互(c-file)

- 规划: 单包 `c-file`, 9 个工具; 读侧统一(自动识别格式 / 语言), 写侧按改写方式分。文件级操作(新建 / 移动 / 删除 / 重命名)由 bash 承担, 不设专门工具。工具逐项明细见 TOOLS.md。
- 不做什么: 不做文件级增删移动(归 bash), 不按语言拆包(语言由内部识别)。

### 流程控制(c-flow)

- 规划: 分两层 — `c-flow` 是基础包, 只提供流程抽象(核心模型 + 推进 + 验收 + 审计 + 事件溯源)与其服务面; 各种固定的分解模式做成独立插件包, 经 c-flow 的服务面注册, 成为工具可取用的「固定模式」。c-flow 建在 SERVICES-PACKAGES.md 的基础能力之上, 底层用 cPush / cGuide / cConstrain。宿主的 goal 与 todo 也由 c-flow 覆盖。
- 模型面: 三个工具 — `c_flow_run`(new / continue / pause 合一, 只作用于根节点)、`c_flow_decompose`(展开任务节点, 自由分解或套用固定模式)、`c_flow_status`(只读查任务树与推进状态)。工具明细见 TOOLS.md。
- 固定模式包(c-flow-plan / 八段流程包)各留入口工具, 建根时可指定, 模型也可在 decompose 时直接套用指定模式; 模式本体在配置 / 声明里, 不逐条给子任务。
- 不做什么: 不替模型判断活干得对不对(验收在流程服务面), 不做多 agent 的分派。

### 编排合作(c-group)

- 规划: 分层 — 底座(cSync / cChannel / cSpawn)只提供服务面, 无模型面工具。模型面以管理控制工具 `c_group` 为主入口(action 分派: 组 / 成员 / 连接 / 指令与回报 / 结算), 对齐现状 agent-group 的 agent_group 形态。
- 通信与拉起: 经底座承担(cSync 同步 / cChannel 消息 / cSpawn 进程内委派经宿主 subagents), 不单独设模型面工具; 可选接入 c-flow, 直接给目标 agent 指定任务流程, 通信只做载体。
- 不做什么: 不做任务分派与协作编排的细节(留流程层), 不重复底座能力。

### 内容分析(preference-analysis)

- 规划: 保留现状包与三工具(`preference_list` / `preference_add` / `preference_remove`), 沿用现名。偏好提议一律落候选待审, 审核后生效并注入。
- 不做什么: 不直接改模型行为(建议经账簿与注入通道生效), 不跨文档定义规则来源。

### 工具咨询与揭示(c-tool, 模型面包)

- 规划: 单工具 `c_tool_query`: 查询工具完整说明与完整参数 schema, 查询命中即写会话授权并投递全文。
- 功能与对应基础服务:
  - 查询工具完整说明与完整参数 schema — cTool(catalog 全文来源)
  - 揭示写会话授权 — cMemory(授权状态经 C 级保持)
  - 揭示后保持工具说明全文(跨压缩、跨轮在场, 可撤销) — cMemory
  - 拦未揭示工具的调用 — cBoundary(工具执行前判别)
  - 揭示后放行 — cBoundary(同一判别位的放行分支)
  - 会话期工具列表冻结(仅首条消息发出前可注册, 变化破坏缓存命中) — cTool(登记层保障)
  - 白名单与门禁口径 — 本包定义(非基础包)
- 不做什么: 不改工具执行管道, 不代做审批(放行 / 拦截由 cBoundary 判别转交)。

### TUI

- 规划: TUI 是纯消费方, 不对外提供服务面; 模型面保留只读回读工具(`tui_local_log` / `notice_history`), 其余能力全部消费各插件与服务面。
- 不做什么: 不复制服务面能力(状态、记忆、消息均消费底层), 只读回读不进写路径。
