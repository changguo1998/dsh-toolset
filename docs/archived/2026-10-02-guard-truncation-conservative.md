# check 模式「截断 + 已收集无害值」静默放行（接取条目：`docs/BACKLOG.md`「check 模式『截断 + 已收集无害值』静默放行」）

## 目标（实测复现，P2 安全类）

`unknownToolPolicy: "check"` 下：5000 元素数组、仅**末元素**带危险 `command` → 遍历预算在危险键**出现之前**耗尽 → 结果为 **`ALLOW(null)` 且 0 告警**（静默放行）；`deny` 同输入为 `DENY`。而 README 同段写「上限耗尽时保守」。即：**截断**（无法完整判定）时，只要「已收集值集合非空」，check 会走 `#decideCollected`（无命中即放行）而**跳过**截断保守分支。

## 决策

- **D1（口径统一：截断即保守）**：`truncated === true` 时，**不再看已收集值是否为空** ——
  - `deny`：保守**拦**（与现状一致）；
  - `check`：保守**拦 + 告警一次**（现状仅在「零收集」时如此）。
    即「无法完整判定」一律按最保守结果处理，与 README 口径一致。
- **D2（回执）**：沿用既有截断回执文案（`超出遍历上限…`）；若同时存在已收集值，**追加一行**说明「已收集 N 项未命中，但因遍历未完成而保守拦截」（N 与去重口径沿用既有实现）。
- **D3（不回归面）**：未截断路径**逐字不变**（含 check 的规则 id/敏感层/allowPatterns 断言）；深度/节点预算语义不变；`unknownToolAllowlist` 命中的工具仍整体放行（在扫描之前判定）。
- **D4（测试）**：① 复现输入（5000 元素、危险键在末尾）→ check：**拦 + 告警 1 次**（不再是 `null`）；② 同输入 deny：拦（回归）；③ 截断且**仅无害值** → check 仍保守拦 + 告警（新口径）；④ **未截断**的同类输入（危险键在中段）→ 与现状一致（拦）；⑤ 未截断且无害 → 放行且 0 告警（防误报）；⑥ 既有截断用例若需改文案，**逐条列出原→新→原因**。
- **D5（反向验证）**：把「截断即保守」退回「零收集才保守」→ ①③ 必失败；还原全绿。
- **D6（文档）**：`security-guard/README.md` 的「上限耗尽时保守」句补明确口径（`check` 亦拦 + 告警一次；含「已收集项未被放行即因遍历未完成」的说明），并同步用例计数。
- **D7（不做）**：不改深度/节点预算数值；不加配置项；不改 `deny` 的既有行为；不动其它包。
