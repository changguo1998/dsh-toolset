## 问题（审阅实测）

脚本解析 `defineTool({...})` 的 `name` 时，会取到**本对象之外**的字符串：

- `dsh-plan-mode` 真名 `exit_plan_mode`（`lib/index.js:35`/`:231-232`）被报成 **`plan`**（取了 `:183` 的 slash 命令名）；
- 对照实验：一个带 `path` 参数、名称走常量的工具，若其**前面**存在 `name: "read"` 字面量 → 脚本报 `已覆盖 1：read / 需关注 0`、**`exit 0`（静默假阴性）**；去掉该前置字面量 → 正常进「需关注」。

后果：**漏报**（把危险面的工具算成已覆盖），且方向是「静默绿」，属安全类缺陷。

## 决策

- **D1（名称必须来自同一 `defineTool` 对象）**：解析时先按花括号配平切出**该 `defineTool({...})` 的对象体**，只在**体内**找 `name:`；体外的 `name:` 字面量一律不看。
- **D2（无解即保守）**：体内 `name` 为计算值（常量/模板/属性访问）或缺失 → 保持既有「（名称未解析）」路径（**进「需关注」行**，按参数键判门禁），**绝不**借用体外名字。
- **D3（不改判定口径）**：键类判定、三分类、退出码语义不变；只修名称来源。
- **D4（测试）**：① 复现用例：前置 `name: "read"` 字面量 + 目标工具名称走常量且带 `path` 参数 → 必须**不出现在「已覆盖」**、必须出现在「需关注」或「名称未解析」行，且 **exit 1**；② `dsh-plan-mode` 形态（`const X = "exit_plan_mode"` 体内引用）→ 名称未解析（不报成 `plan`）；③ 正常字面量名不受影响（既有 14 例回归）；④ 同一文件多个 `defineTool` 各自取自己的 `name`。
- **D5（反向验证）**：把名称来源退回「全文取最近字面量」→ ① 必失败；还原全绿（逐字节）。
- **D6（文档）**：README 差异检查小节补一句「名称只在**同一 `defineTool` 对象体内**解析，体外字面量不参与；解析不出按『名称未解析』保守列出」。
- **D7（不做）**：不做完整 AST/TS 解析（保持轻量正则 + 配平）；不改其它包；不改真实宿主报告口径（`dsh-plan-mode` 仍会进「需关注/未解析」，属正确保守）。
