# 键路径回执的两处口径与体积（接取条目：`docs/BACKLOG.md`「键路径回执的两处口径与体积」）

状态：完成　　开启：2026-10-02　　关闭：2026-10-02
本文件是本次唯一过程记录与文档变更落点；计划外文件不改。

## 背景（前条目审阅实测遗留）

1. **「与 `commandPaths` 同形」只单向成立**：多级数组渲染为 `a[][].b`，但登记表解析器 `commandPathValues`（点号分段 + 段名 `[]` 后缀 → 只支持**一层**数组）**回读不了**；外层宿主已有实例：`task_decompose` 的嵌套数组命令漏检（实测 `true/false`）。
1. **字面键名与结构路径同形**：`{"a.b": {...}}` 与 `{a: {b: ...}}` 都渲染 `a.b.path`，路径去重会把两者**合并成一条**（实测只报 `a.b.path`）。
1. **deny 回执体积不再有界**：键名去重时代上限 ~17 条；改为**键路径**去重后上限为不同路径数（≤4096），实测 300 个不同路径 → 首行 3530 字符 / 整条 3791。

## 决策（本条目 = 收口这三处，不做架构性改造）

- **D1（不回读边界：文档 + 结构性防呆测试）**：
  - `security-guard/README.md` 的键路径段补边界：**「回执里的键路径是展示形态；下标不参与（`[]` 不带序号）、多级数组为 `a[][].b`（登记表解析器只支持一层 `[]`，故不可回读）、字面含 `.`/`[]` 的键名会与结构路径同形」；并写明「**勿把回执路径直接抄进登记表 `commandPaths`**」**；
  - 新增**防呆测试**：遍历登记表 `commandPaths`（`task_decompose` 的两条）与 `TOOL_SURFACE` 暴露面，断言每条路径都能被「一层 `[]`」解析规则解析（即不含 `[][]`）；将来有人写多级数组会红。
- **D2（字面键同形：文档 + 特征化测试）**：**不改**去重算法（去重按路径串是刻意的最小实现）；补一条**特征化用例**钉住现状（`{a:{b:{path}}, "a.b":{path}}` → 只报 `a.b.path`），并在 README 同段说明该合并是已知行为。
- **D3（回执体积上限：实现）**：`formatUnknownToolReceipt` 的命中参数列表加**上限** —— 最多列 `MAX_RECEIPT_KEY_PATHS = 12` 条，其余折叠为 `等 N 处`（N = 总数 − 12）；**小列表（≤12）逐字不变**（既有断言不回归）。
- **D4（测试）**：① 多级数组渲染形态 `a[][].path`（钉住展示口径）；② 登记表 `commandPaths` 可被一层解析规则解析（防呆）；③ 字面键同形合并（特征化）；④ 环引用路径断言（`node.command`）；⑤ 体积上限：300 个不同路径 → 首行含 12 条 + `等 288 处`，且整条长度 ≤ 1000 字符；⑥ 小列表（1 / 12 条）逐字与旧版一致。
- **D5（反向验证）**：撤上限 → ⑤ 必失败；还原全绿（逐字节）。
- **D6（文档）**：README 同步（边界 + 上限 + 用例计数）。
- **D7（不做）**：不改键路径构造、不改去重算法、不让 `commandPathValues` 支持多级数组（另开条目再说）、不动其它包、不加配置项。
