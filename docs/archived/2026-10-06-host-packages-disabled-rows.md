## 决策

**口径修正 + 计数重算，不做整体重采集**（沙箱内无法重跑全量 dump，见「调研 → 重要限制」）。

1. **§0 口径补一条判定规则**：`已挂载` = 组合树里该行存在**且未被 `disabled` 关掉**；`disabled: !!js <条件>` 按 profile 上下文求值（先例 `hmr`：`!ctx.get("profileContext")` → profile 运行下为**启用**，仍算已挂载）。
1. **§1 摘除两个误标行**（`tool-ralph`、`skill-badge`），计数 **102 → 100**；`§0 小计自洽性`、`:48`、`§6 采集说明` 里的 102 派生数字同步，并写明「2026-10-06 修正：原 102 含 2 行被 `disabled: true` 关掉的行」。
1. **§2 两行改标**：`- tool-ralph` / `- skill-badge` 的「（已挂载）」→「（**未启用**：`dsh-base` 行 `disabled: true`）」，便于读者知道它们**随包分发但 fff 不加载**；分类小计 `agent 与编排` 18 → 17、`技能 / 命令 / Web / 集成` 11 → 10。
1. **不加新条目**：`skill-badge` 与本条目同因同文件同计数，合并处理（若拆开，§1 计数会处于「101 但两类误标只修了一个」的自相矛盾态）。这是本次唯一的范围扩张，已在 BACKLOG 条目「来源」列注明。

### 为什么不选「把该节口径改成『行在位（含 disabled）』」

条目验收给了两条路。选「修计数」而不是「改口径」的理由：该节标题是「**现成可用**（fff 已挂载）」，读者（含本仓的 agent）拿它判断「这个能力现在有没有」——把口径放宽成「行在位」会让 `tool-ralph` 这类**默认关闭**的行继续被当成可用能力（本仓已因此错判两次）。口径必须答「现在能不能用」。
