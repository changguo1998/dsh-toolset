## 决策

- **D1（顶层解析）**：在 `defineTool` 体内按**括号深度**扫描：只接受深度 0 的 `name:`（字面量或表达式），深度 ≥1 的（嵌套对象/数组内）一律忽略。扫描需**字符串 / 注释感知**（`'` `"` 模板串、`//`、`/* */`），避免字符串里的 `{` 影响深度。
- **D2（无顶层名 → 保守）**：体内无顶层 `name:`（或为计算值）→ 既有「（名称未解析）」路径（不借用任何嵌套名）。
- **D3（测试）**：① 复现用例：`defineTool({ meta:{ name:"read" }, name: T, parameters:{ path } })` → **不得**报成已覆盖/`read`，必须「（名称未解析）」且 `exit 1`；② 顶层字面量 + 嵌套同名 → 取顶层；③ 顶层缺失但嵌套有字面量 → 未解析（不被嵌套顶替）；④ 既有 119 例回归。
- **D4（反向验证）**：把「顶层限定」退回「体内任意 `name:`」→ ①③ 必失败；还原全绿（逐字节）。
- **D5（文档）**：README 名称解析段更新（「体内 + **顶层**」），并把 (b)(c)(d) 作为已知过度保守项写清。
- **D6（不做）**：不做完整 AST 解析；不改正则/字符串误配平（记残余）；不动其它包。
