## 1. 缺陷与联调

**#1 真机联调未做（两个会话各挂本插件跑通全流程）**（〔进行中: 2026-10-19〕 2026-10-17 登记）：**现象 / 现状** —— 本批只做了单测（纯模型 / 动作层假传输 / 接入面假宿主），没有在真机两个会话间跑过 `create_group → add_member → link → send → check → remove`；`<会话目录>/agent-group.json` 的真实落点、镜像行能否用 memory 的 `search({kind: "agent_group"})` 查到，都只有单测依据。**期望** —— 起两个会话（各挂 session-channel / session-paths / agent-group），一个建组并把另一个加为成员，跑完整流程；确认状态文件生成且为 0600，memory-base 已挂时能按 `kind` 检索到镜像行。**落点** —— 无代码改动（除非联调暴露问题）。**验收** —— 上述流程在真机上走通，回报正文与成因在 `check` 结果里正确出现。**优先级** —— P1（首次上真机前的必做项）。

## 2. 二期能力（设计决策项 20 的「二期」）

**#2 广播与平等连接**（〔进行中: 2026-10-19〕 2026-10-17 登记）：**现象 / 现状** —— 首期只有主从连接（单向指令 + 必须回报）；平等连接（双向、发完即走、不留状态）与广播（一条指令发多人）都没有实现，`link` 只建主从。**期望** —— 按决策项 4 / 6 / 20 落地：平等连接不记等级、不记未结指令；广播按当前成员集合展开并汇总每条送达结果；「任意两个 agent 之间每种连接至多一条」的校验。**落点** —— `src/model.ts`（连接类型与校验）、`src/core.ts`（新动作）、`src/types.ts`、测试。**验收** —— 每对 agent 两种连接各至多一条；广播的逐条送达 / 失败可区分；平等连接不产生未结指令。**优先级** —— P2。

**#3 TUI 命令或面板**（〔进行中: 2026-10-19〕 2026-10-17 登记）：**现象 / 现状** —— 只读查看只有模型侧工具 `status`；人要看组状态得让模型调工具。**期望** —— TUI 侧命令（如 `/group`）或状态列，复用服务面 / 工具结果。**落点** —— `TUI/src/app/**`（归 TUI 模块的实现）。**优先级** —— P3。

**#4 轮次与终止的三个细节**（〔进行中: 2026-10-19〕 2026-10-17 登记）：**现象 / 现状** —— 决策项 15 / 20 明确首期不建模轮次；等待上限（`timeoutMs`）目前是每条指令的参数（缺省 30 分钟），没有「全组预算」「检查间隔」「关闭组的边界语义」。**期望** —— 用户另行裁定后落地；在此之前用 `timeoutMs` + `check` 手动控制。**优先级** —— P3（等用户定）。
