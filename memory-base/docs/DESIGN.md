# memory-base 设计

> 阅读顺序：§0 判定标准（先读）→ §1 定位 → §2 分层与路由 → §3 各层契约 → §4 分类 → §5 闸门 → §6 提升与审阅 → §7 检索与索引 → §8 容量与频率 → §9–§10 Schema 与迁移 → §11–§13 边界 / 差异清单 / 已知边界。
>
> 本文描述**目标架构**（2026-10-08 定稿方向）：按**生命周期作用域**分层的记忆系统，包名 `memory-base`（2026-10-08 由 `knowledge-base` 改名）。现状实现（单库 `knowledge.db` + 调用方闸门）与目标的差异见 §12；`README.md` 仍描述当前实现，实施落地后同步。

## 0 判定标准（先读这一节）

**分类标准（一条）**：看这条内容**服务谁**——只服务本次会话 → **S**；服务本项目 → **P**；跨项目成立 → **U**。拿不准就落 S（入口层，代价最低，反正会随会话消失）。

**顺序标准（五条）**：

| 判定什么 | 顺序 |
| --- | --- |
| **写入** | 自动路径：一切先落 S，再逐级提升（禁跳级）。用户明确指令（提问确认后）：直达目标层。**例外：内容索引（§7.2）按被索引内容的层直接建表**（不承载结论）；**同层内的无冲突改写（§6.1）直接改正式行**，不算跨层提升 |
| **提升** | I → S → P → U，一级一级；每跳先出候选，审阅通过才落上层 |
| **检索** | 跨层 × 跨分类一起搜（记忆层 = S / P / U；**I 是原文索引，走单独入口**）；排序 = U > 当前项目 P > 其他项目 P > S，同项目优先，再按分数。跨项目 P **默认不读、只能由用户显式发起**；`kind` 可收窄分类 |
| **淘汰** | 只在超限时按缺口删：低 `importance` → 久未引用 → id 小；不跨层。**U 层不自动淘汰**（1 MB 软上限，超限只告警）。S / I 的 7 天兜底过期是**寿命**，不算「时间衰减淘汰」 |
| **审阅** | I → S 由 agent；S → P 由 agent 可代批；P → U **必须用户本人**；**冲突一律交用户裁定**（`conflict_with != null` 的候选不受代批；限 P / U 层——S 是会话工作集，不做矛盾裁定） |

**底线（两条）**：① 原文不入库——只存概括 + 回指；② 文档已有的事实只存指针（`docRef` + 结论），不复制。

§1–§13 是这些标准的展开与理由；**细则与本节冲突时以本节为准**。

## 1 定位与取舍

DSH 进程内集成的**分层长期记忆**。层不是按时间长短切，而是按**这条记忆为谁服务、该活多久**切：

| 生命周期 | 作用域 | 含义 | 寿命 |
| --- | --- | --- | --- |
| **会话** | `sessionId` | 本次会话内发生的事（做了什么、报了什么错、定了什么） | 随宿主会话目录（宿主删会话即消失）+ 7 天兜底 |
| **项目** | `project`（工作目录） | 该项目跨会话仍成立的事实、约定、教训 | 项目存续期 |
| **用户** | 全局 | 跨项目成立的偏好、习惯、通用事实 | 永久 |

**三条设计原则（用户 2026-10-08 给定）**：

1. **每个生命周期有对应的库**——会话库 / 项目库 / 用户库各一个 SQLite 文件、各有属主与保留策略；
1. **逐步概括提升层级**——会话细节 → 项目结论 → 用户事实，每升一层只留概括与回指；
1. **层级越高，写入标准越严格**——会话级几乎照单全收（反正是短命的），项目级要求跨会话价值，用户级要求跨项目价值，或用户显式确认。

六个取舍：

- **按作用域分库，而不是按时间分表**：分层的目的是**寿命与写入标准**（随会话目录 / 项目存续 / 跨项目永久），**不是检索隔离**——检索跨全域（§7）。
- **概括即提升；自动路径逐级 + 审阅**：自动写入（事件直写、巩固提升、agent 自主记录）的唯一入口是会话层，升级是一次重写（细节 → 结论），**每一跳都要审阅通过**才落上层。**用户明确指令不受此限**——它直达目标层，视为已审阅（§5）。
- **原文不入库，只留回指**：原文在 T0（宿主会话日志 / spill 文件）；本仓各层存概括 + `session_id` / `seq` / locator。
- **文档优先序**：记忆补文档之缺，不替文档做副本（§7.1）。
- **职责：只做存储与基本管理**（分层、路由、提升、淘汰、注册），不做知识加工——分类语义与内容归上层插件（§4）——故目标名 `memory-base`（`@dsh-toolset/memory-base`，目录 `memory-base/`，服务键 `ctx.get('memory')`）。「knowledge」的语义留给上层消费方。
- **`digest.db` 不是记忆层**：它是 T0 的**索引**（工具输出的摘要 + 行 / 字符区间，用于事后定位回原始字节），随会话失效。把它算作记忆层级会混淆「查得到原文」与「记住了结论」两件事。

## 2 分层模型

| 层 | 库（文件） | 存储位置 | 属主 | 内容 | 写入标准（严格度递增） | 保留 |
| --- | --- | --- | --- | --- | --- | --- |
| **T0** 原始 | 宿主会话库 / spill 文件 | 宿主会话存储 / spill 目录 | 宿主 | 事件原文、大输出原文 | 宿主自管 | 宿主策略 |
| **I** 索引（**I**ndex） | `digest.db` | 宿主会话目录（与 S 同级） | `output-compress` | 工具输出摘要 + 切片区间 + locator | 结构校验 + 去重 + 隐私底线 | 会话目录消失（宿主删会话）/ 7 天兜底 / 100 MB |
| **S** 会话（**S**ession） | `session.db` | 宿主会话目录 | `memory-base` | 本会话的事件要点（不设长度上限） | + 类型白名单 + 会话内去重 | 会话目录消失（宿主删会话）/ 7 天兜底 / 50 MB |
| **P** 项目（**P**roject） | `project.db` | 项目根 `.dsh/` | `memory-base` | 项目级事实 / 约定 / 失败教训（不设长度上限） | + 跨会话价值判据 + 项目内去重 | 项目存续 / 200 MB |
| **U** 用户（**U**ser） | `user.db` | `~/.dsh/memory-base/` | `memory-base` | 跨项目偏好 / 习惯 / 通用事实（不设长度上限） | + 跨项目价值判据或用户确认 + 跨项目去重 + 隐私**二次**检查 + 近似替换 | 永久 / 1 MB（软上限：超限只告警） |

表中「写入标准」列只列该层**增量**标准，完整闸门（含隐私与审阅）见 §5 表；层名：**S**ession / **P**roject / **U**ser 是三个生命周期作用域的首字母；**I**ndex 是索引层（不是作用域）。`memory-base` 是本包名（§12 #9 改名已落地）。

```
T0 原始（宿主日志 / spill；本仓不复制）
    │ 派生（确定性摘要 + 切片）
    ▼
I  digest.db        会话索引：查得到原文，随会话失效
    │
    ▼
S  session.db       写直达：白名单事件 → 会话要点
    │ 提升①：会话结束 / 压缩时，概括为项目结论
    ▼
P  project.db       跨会话复用的项目事实
    │ 提升②：跨 ≥2 个项目成立，或用户确认
    ▼
U  user.db          跨项目的用户事实（最严）
```

### 2.1 数据路由（包内职责，调用方不感知）

- **模型侧与用户侧只见一个面**：目标服务键 `ctx.get('memory')`，动作分四组——调用方**不传文件路径、不关心一次会话会碰几个库**：

| 组 | 动作 | 谁用 |
| --- | --- | --- |
| **读** | `search(opts)`（跨层 × 跨分类；`scope` / `kind` / `crossProject`）、`getSummary()`、`whenReady()` | agent / TUI / 第三方插件 |
| **写** | `remember(input)`（新增 / 替换；`origin: user` 直达目标层，自动路径落 S）、`forget(ids)`（删除，独立动作） | TUI 命令 / agent |
| **提升与审阅** | `promote(items)`（下层 push，幂等键）、`review(id, action)`（`approve` / `reject` / `edit`）、`resolveConflict(id, decision)`、`listCandidates(opts)`（列出待审候选；`getSummary` 只给计数） | `output-compress` / TUI 面板 / agent |
| **注册与维护** | `registerKind(spec)`（`kind` + 扩展列 + 写入前钩子 + 查询路由规则）、`consolidate(opts?)` / `lastConsolidation()`、`rescanDenied({scope, apply})`、`migrate({from, mode})`、`checkContent(text)`（只读判定，供库外写入者叠加 profile 规则） | 分类插件 / 运维 / `output-compress` |

- **路由在包内**：写按 `origin`（`user` / `auto`）与目标层路由；读按 `scope` 跨全域路由；提升在库之间搬运。调用方看到的是「一条记忆 + 它的作用域」，不是「一个库」。
- **路径由层级与作用域键推导**：S / I → 会话目录；P → 项目根 `.dsh/`；U → `~/.dsh/memory-base/`。仅根目录可经配置覆盖。
- **会话目录就用 dsh 自己的**：S / I 直接落在宿主为该会话维护的目录里，**不自建** `<dshHome>/memory-base/sessions/`，也不复制宿主的目录结构规则；路径优先取宿主暴露面（`ctx.sessions.get(id)` 的会话对象 / `ctx.sessionQuery.listSessions()` 记录中的目录信息）；取不到时按宿主的会话存储约定拼接（`<sessionsRoot>/<projectKey(cwd)>/<sessionId>/`，`sessionsRoot` 由配置给）——**实施时先核实宿主是否暴露会话目录路径**，结论写回本节，解析不到即告警，**不静默改路径**。
- **随会话目录生灭**：宿主删除会话 → 目录消失 → S / I 一并消失；`session/disposed` 不删数据（只做提升收尾，见 §3.2）。**核实（2026-10-08）**：宿主 0.2.0-rc.2 未暴露「删除会话」的 API / 命令，持久化只管理自己的 `session.<version>.jsonl.zstd` 与 `session.lock`，不对目录内其他文件做清理；故当前硬删除**实际只有 7 天兜底**（或用户手动删目录），本包文件与宿主文件同目录共存属未获宿主承诺的用法。

## 3 各层契约

### 3.1 I 索引层（`digest.db`，`output-compress`）

- 触发：宿主 spill 通知或阈值（≥ 16 KB）；沙箱内确定性派生程序产出 `headings` / `keyLines` / `slices` / 指纹。`keyLines` / `slices` 存**行号 + 字符区间 + 指纹**，`preview` 是**固定上限的截断预览**（属概括，不是正文）；**`is_error` 布尔值写入时落库**，供巩固期复算 I → S 判据。
- 写入：过本层闸门（结构 + 去重 + **隐私底线**，见 §5）；不再直写 memory-base 的库。原先的硬约束「不建表、不写 FTS」随之作废——它只对「写别人的库」成立。
- 保留：`session/disposed` **不清除**本会话索引（它只触发 S → P 的提升收尾）；硬删除只有两条路——宿主删除会话（目录消失）与 7 天兜底；100 MB 上限。**清理由属主 `output-compress` 自管**（启动后 + 每次写入后自查），memory-base 的巩固链只处理 S / P / U。
- 字段：`referenced_at`——**刷新点 = 属主自己的索引检索 / 回读入口**（`searchDigests` 命中或按 locator 回读时 UPDATE）；I 层**不参与记忆检索**，故不用 `last_referenced`。
- 定位：供 `read` 按行 / 字符区间回 spill 文件；**不参与记忆检索**，升级为记忆要走提升接口。

### 3.2 S 会话层（`session.db`）

- 内容：本会话的事件要点（工具结果、决策、审批、待办、目标变更、压缩摘要），不设长度上限（写多少存多少，概括由提升动作决定）；按 §4 分类入表，未归类的落配置的兜底分类。
- 写入：**自动写入的唯一入口**——`SessionHooks` 白名单事件直写，agent 自主的 `remember` 也落这里，**I 层经 `promote` 的候选同样落本层**（会话级几乎照单全收——寿命短，严格没有收益），闸门在库核心（§5）；用户的明确指令可直接写 P / U，不经此层。
- 键：`(session_id, content_hash)` 唯一——会话内去重，跨会话默认不可见。
- 保留：`session/disposed` **不清 S**——该时刻只做提升收尾（把够格的会话项推入 S → P 审阅队列），让 resume 能接回会话记忆；硬删除只有两条路——宿主删除会话（目录消失）与 7 天兜底；50 MB 上限按 §8 的统一顺序淘汰（`importance` → `last_referenced` → `id`）；超限时可先就地压缩降级（§8）。
- 检索：跨全域检索的一员（排序加权最低，但默认可命中）。

### 3.3 P 项目层（`project.db`）

- 内容：项目级结论——约定（「本项目用 `npm run check`」）、结构事实（「索引在 `src/app`」）、失败教训（「pnpm v11 不跟踪 `file:` 依赖」）。不设长度上限，带 `title` 与来源（`session_id` 列表）。
- 写入：自动路径只接受 S 层**提升候选经审阅通过**（§6），不接受事件直写；**用户明确指令**（`origin: user`）可直达本层。
- 键：`(project, content_hash)` 唯一——项目内去重，跨项目不串（解决现状「A 项目写过、B 项目查不到」的漏检）。
- 分类（§4）：本层不预设分类，具体分类由上层插件注册后才有表。
- 保留：项目存续期内不设 TTL；200 MB 上限内按 `importance` → `last_referenced` 淘汰。
- 检索：跨全域检索的一员；同 project 的结果加权靠前。

### 3.4 U 用户层（`user.db`）

- 内容：跨项目成立的东西——偏好（「回答简洁」）、习惯（「提交信息用中文」）、通用事实。不设长度上限。
- 写入：自动路径只接受 P 层**提升候选经审阅通过**（§6）；**用户明确指令**（`origin: user`，如 `/memory add`）可直达本层。其余自动写入一律拒绝**正式入库**；候选写入本层 `candidates` 表（与记忆表分离、不参与检索），审阅通过才转入正式分类表。
- 近似替换：**同类内**归一化后相同、或短者为长者子串 → 视为替换（更新既有行，不新增）——这是**去重**，与 §6.1 的「结论冲突」是两件事。
- 分类（§4）：本层不预设分类（「偏好」等分类由相应插件注册），分类集合与其他层同构。
- 保留：**永不自动淘汰**；1 MB 为**软上限**：超限只告警并计数，不拒写、不自动删（记忆不因容量被静默丢弃）。
- 检索：跨全域检索的一员、排序加权最高；全量小表直接读，不做 FTS。

## 4 分类：注册制（不由本包限定）

本包只提供**分类机制**，不规定有哪些分类——「偏好」「技能沉淀」这类逻辑区分的**内容与语义归各自的上层插件**，本包只负责存储与基础管理。

- **注册制**：上层插件向本包**注册分类**（`kind` 名 + 扩展列 + 可选写入前钩子 + 可选**查询路由规则**），本包按注册信息建表。**未注册的 `kind` 拒写并回报**。注册入口 = 服务面 `registerKind`（第三方插件在 `apply` 时调用）；**兜底分类由配置声明并在首次启动时注册**，不需第三方认领。
- **不限定表名**：每个分类一张表，表名由注册方给出，本包**不硬编码任何具体分类名**。本包只提供**基类列**：`id` / `content` / `docRef` / `docHash` / `content_hash`（去重键）/ `importance` / `last_referenced` / `created_at` / `origin` / `session_id` / `project` / `promoted_from` / `promoted_to` / `reviewer` / `title` / `sources`（来源 id 与 `session_id` 列表）/ `projects`（U 层的跨项目集合）/ 。扩展列由注册方声明（**候选字段不在此列**——它们属 `candidates` 表）。
- **兜底分类**：未指定 `kind` 的内容落**配置指定的兜底分类**（名字来自配置，缺省 `default`），本包不为它赋予语义。
- **跨层同构**：同一分类在 S / P / U 三层都可有表且结构一致；提升只换作用域与概括程度，`kind` 随行。
- **自动纳入检索**：分类一经注册，其表自动进入该层的检索并集（§7「层 × 分类」），调用方无需逐表查询。
- **按需建表 / 扩展 = 加表**：空表不建；新增分类是向后兼容的 schema 变化（不迁移既有数据），改列 / 删表才走版本迁移（§9）。
- **事件与分类的绑定由注册方声明**：注册时说明它关心哪些事件类型、映射到哪个 `kind`；没有注册方认领的事件落兜底分类（§3.2 的事件直写按此入表）。
- **schema 变更归注册方**：分类的表结构与扩展列由注册方声明与维护版本，本包只提供基类列并执行迁移（§9）。
- **I 层不参与分类**：只有一张 `digests` 表（索引不是记忆）。

## 5 写入面与闸门（原则 1 + 3 的落地）

- **文档指针化**：带 `docRef` 的内容只存结论 + 指针 + `docHash`，不复制文档正文（哪些分类适用由注册方决定）。
- **各层都不设长度门槛**：上限、下限都没有（I / S / P / U 一致）——内容不因长度被截断或拒绝；唯一的形态底线是**不接受空内容**（trim 后为空即拒写）。控制手段是概括与容量淘汰，不是入口的长度闸。
- **分类闸门**：`kind` 必须是**已注册分类**；未注册的拒写并回报。**兜底分类也是一个注册项**（名字来自配置）；用户直写未给 `kind` 时落兜底分类，**U 层不允许兜底**（必须显式给已注册分类）。**候选入队时同样过这道闸**：`kind` 未注册（或 U 候选落兜底）→ 不入队、计数并回报，避免成为「落地才失败」的死候选。
- **入口唯一（限自动路径）+ 逐级 + 审阅**：自动写入都先落 S 层，P / U 只经由提升进入（**候选写目标层 `candidates` 表，不算落地**；未过审的候选留在该表、随库寿命淘汰），每跳产生候选、审阅通过才落库并留痕（审阅人 / 时间 / 依据）；未过审的候选留在下层，不阻塞新写入。**用户明确指令不走这条链**——直达目标层，记 `origin: user`。
- **闸门在属主库核心**：每个库只被一个包写，过滤点落在库的写入函数内（现状「闸门挂在 `hooks.ts`，换个调用方就绕过」作废）。三条既有旁路（`writeBack` / `backfill` / `memory.add`）自动继承；其中 `writeBack` / `backfill` 的**目标层只能是 S**（`origin: auto`），要落 P / U 必须走提升。
- **标准按作用域加严**（每行的标准在下一行继续生效）：

| 层 | 类型 | 去重键 | 价值门槛 | 审阅 | 隐私 |
| --- | --- | --- | --- | --- | --- |
| I | 无 | 库内 `content_hash` | 无 | 无（属主自写） | **底线**：六类形态模式 |
| S | 事件白名单 | `(session_id, content_hash)` | 无 | 事件直写免审；**I → S 由 agent 审** | 底线 + profile 扩展 |
| P | 提升来源约束 | `(project, content_hash)` | 价值证据：命中过 / 决策类 / 教训（§6） | **agent 可代批**（用户亦可；用户指令免审） | 底线 + 概括文本二次检查 |
| U | 已注册分类（`kind` 必填） | 跨项目去重 + 同类**近似**替换 | 跨 ≥2 项目成立**或用户确认** | **必须用户本人**（agent 的 `approve` 无效；用户指令免审） | 底线 + 概括文本二次检查 |

- **隐私底线必须自足**：`output-compress` 与 `memory-base` 各持一份相同的六类形态模式常量（两包**不得**建立 npm 依赖）+ 一条**跨包一致性测试**（漂移即测试红）。profile 自定义 `denyPatterns` 属扩展面：能取到 `ctx.get('memory').checkContent()` 就叠加，取不到只用底线。
- **存量回扫**：**S / P / U** 三层可按当前规则重扫已有行（I 层归属主自管）（`rescanDenied({scope, apply})`），默认只出报告（条数 + 分类，不回显内容），`apply: true` 才删。
- **`importance` 赋值**：由写入方给——用户直写可显式指定；自动路径取注册方写入前钩子的建议值，无建议时缺省 3（clamp 1..5）。它**只用于淘汰排序与候选优先级，不作为价值闸**（缺省 3 会让门槛恒真，故 P / U 的门槛由「价值证据」承担）。
- **可观测**：各层计数（`accepted` / `deduped` / `skipped{reason}` / `promoted` / `evicted` / `conflicts` / `bytes`），`getSummary()` 汇总。

## 6 提升与审阅（会话 → 项目 → 用户）

提升 = 读下层的行产出**候选** → **审阅通过** → 过上层闸门 → 入库 → 在下层标 `promoted_to`。候选未过审则留在 `candidates` 表里，随所在库的寿命淘汰；不做跨库事务。**概括时点（2026-10-08 定）**：「重写为概括」在**入队时**由服务面完成（审阅者审的是将要落上层的内容，LLM 建议分类先于审阅存在、审阅可改）；LLM 面不可用时候选照常入队但**不得转换落上层**（拒绝并计数，下次巩固重概括）——「失败不提升、不降级成机械摘要」的闸落在转换步。

| 链路 | 触发时机 | 判据（全部满足） | 产物 |
| --- | --- | --- | --- |
| I → S | 索引写入后（属主 push；重推在属主巩固时） | `is_error` **或**被回查引用过（`referenced_at > created_at`） | 会话要点（LLM 概括）：title + 结论 + 建议分类 + 回指 I 层 id |
| S → P | 会话结束（`session/disposed`）或 `compaction/end` 后 | 本会话内**被检索命中过**，**或**属决策类事件（`plan/mode` / `goal/change` / `approval/decided`），**或**是失败教训（判定者 = 注册方的事件绑定或审阅者；未注册时该分支不成立，由 OR 其他分支兜住） | 项目结论：title + 结论 + 来源 `session_id` 列表 |
| P → U | 巩固（启动后 / compaction 后） | 同一事实在 **≥ 2 个不同 project** 出现（由 U 行 `projects` 累积判定），**或**用户显式确认；且通过隐私二次检查。**两条分支都只产出候选，落地必须用户本人批** | 用户事实 + 分类（`kind`）+ 项目集合 |

- **候选寿命与丢弃**：候选随其所在库的寿命消失（会话目录删除 / 库删除）；另有 `candidates` 表独立上限——超限时**先清最旧候选**（容量兜底优先于「默认保留」）；`promotion_state: pending` 与 `conflict_with != null` 都按候选处理。
- **候选单独成表**：每个库有一张 `candidates` 表（**与记忆表分离**）——字段 `id` / `target_tier` / `kind` / `fact_key` / `content_hash` / `title` / `content` / `sources` / `projects` / `promotion_state` / `conflict_with` / `reviewer` / `created_at`。候选**不是记忆**：不参与检索、不计入该层条目与容量统计，只有审阅通过才写入正式分类表。跨项目的 `projects` 累积就发生在这条 U 候选行上（U 库对所有项目可见），无需跨项目读 P。
- **跨项目证据只在本项目内累积**：每个项目的会话只投「自己这一票」；同一事实（机械判据 = §3.4：归一化相同，或短者为长者子串且占比 ≥ 0.8；不做语义合并）在不同项目各自命中时并入**同一条 U 候选行**的 `projects` 集合（每项目一票），达 ≥2 即标为「跨项目事实」并优先提审——**不需要跨项目读取 P**（`crossProject` 只服务用户主动查询）。
- **跨包链路（I → S）经服务面**：`output-compress` 只推送候选，调 `ctx.get('memory').promote(items)`；**LLM 概括由本包在服务面内完成**；服务缺失即不提升（索引行留到兜底过期），不报错、不绕过；概括失败由本包计数并在下次巩固重试。
- **`promote` 契约**：入参 = 候选列表（来源层 / 来源 id / `kind` / title / content / `projects`）；**幂等键 =（`target_tier` + `kind` + `fact_key`）**，`fact_key` = **来源内容按 §3.4 归一化后的哈希**——重复 push 只更新同一条候选；**同一事实从不同项目推上来也落同一行**（`projects` 各记一票）；返回每条的结果（入队 / 拒收原因）。
- **失败语义**：上层闸门拒绝 / 容量不足 / 服务缺失 → 不提升并计数；下层行不动。
- **分类随行**：提升只换作用域与概括程度，`kind` 不变（§4）；候选的建议分类由**注册方提供的规则**给出（本包不内置语义映射，没有建议就落兜底分类；**U 候选例外——必须给出已注册分类，否则不入队**），审阅可改。
- **概括由 LLM 完成**：提升的「重写为概括」是一次 LLM 调用，走**宿主 LLM 面**（`ctx.llm`，与 `command-template` 同一姿势；提供方 / 模型可配）；输入 = 下层候选 + 来源回指，输出 = 上层条目的 title + 结论 + 建议分类；**LLM 面不可用即视为调用失败**；调用失败则**不提升**并计数，**由属主在下次巩固时重推**（本包不主动读 I）——不降级成机械摘要，避免同一层混两种质量。
- **自动路径禁止跳级**：自动写入没有任何直写 P / U 的入口（agent 自主的 `remember` 也先落 S 层，再逐级提升）。
- **用户明确指令例外**：`/memory add|replace|remove`、或会话中明示「记住 X」并由 agent 转写，直达目标层且**免审阅**（用户即审阅人）；但仍过该层闸门（隐私底线 / **近似替换去重** / 软上限）；若与既有条目**结论矛盾** → 走 §6.1 的冲突裁定（提问用户），不自动替换，并留痕 `origin: user`。
- **来源必须可证**：除用户**直接动作**（TUI 命令 / 面板选择）外，任何要记成 `origin: user` 的路径**必须先向用户提问确认**——问答面板的肯定回答即授权凭据；agent 未提问的转写一律按自动路径走（逐级 + 审阅），不得自标。
- **审阅与留痕**：每跳产出候选（写入目标层 `candidates` 表，`promotion_state: pending`，跨重启可续），**逐条处理**（一次一条，带候选内容 + 依据 + 建议分类）——需用户审的走面板逐条提问，agent 审的逐条记录判断依据；通过才落上层，并记 `reviewer` / 时间 / 依据到上层行与下层行的 `promoted_to`。同一条内容不得跨过未审的层级。
- **审阅通过后的转换**（单事务）：① 用候选内容写上层正式行 → ② **有下层来源行时**才标 `promoted_to` → ③ 候选标 `approved` 并清理。任一步失败则整体回滚，候选保持 `pending`（不产生半写）。
- **`resolveConflict(id, decision)` 的两条路径**：候选来自提升且有下层来源行 → 走上面的①②③；候选来自**用户直写引发的冲突**（无下层来源行）→ 只做「更新两条正式行 + 清理候选」。`decision` 取值 = `accept-new` / `keep-old` / `merge` / `edit`。
- **审阅权限按跳定**：**I → S** = 用户不审、**由 agent 审**；**S → P** = **agent 可代批**（用户亦可；**`conflict_with != null` 的候选除外**，冲突一律用户裁定）；**P → U** = **必须用户本人**（agent 对 U 候选的 `approve` 无效并回报）。`reject` / `edit` 各跳都可用。

### 6.1 更新语义：冲突交用户裁定（2026-10-08 定）

- **冲突不自动合并**：新证据与既有结论**矛盾**时（LLM 概括或审阅时发现），产出**冲突候选**（写 `candidates` 表，带 `conflict_with`）并按条提问用户；用户裁定后由服务面动作 `resolveConflict(id, decision)` 落地——**把两条的内容都更新**为一致结论，不留「新旧并存」的状态。
- **不引入 `supersedes` / `superseded_by`**：版本链由「双向更新」代替；既然不允许新旧结论并存，也就不需要过期标记与隐藏规则。
- **无冲突的自动改写照旧**：S 层 5 分钟合并窗口、U 层同类替换、重新概括仍自动执行（它们都不产生矛盾结论）。
- **删除是独立动作**：删除只作用于目标行；**下层来源行不受影响**（不删、不改、不标记）——回指链允许自然悬空。
- **没有撤销机制**：提升错了就**再更新一次**（覆盖既有条目），不留 `revoked` 记录。
- **适用层**：冲突裁定适用于 **P / U 层条目**；S 层是会话工作集，不做矛盾裁定，随寿命消失。
- **自动改写与审阅的边界**：审阅针对**跨层提升**（产生新结论）；**同层内的无冲突改写**——S 合并窗口、U 近似替换、上层重新概括——属自动维护，不产生矛盾结论，因此不额外过审（出现矛盾即升级为上面的冲突裁定）。

## 7 检索与索引（跨全域）

- **作用域键只用于写入归属与排序加权**：`session_id` 由宿主事件给；`project` 派生链 = 显式配置 > 会话 `header.cwd`（宿主 `SessionHeader.cwd`，进程内经 `ctx.sessions.get(id).header.cwd` 可读——现状只是本包把回调类型窄化成了 `{ id }`）> `process.cwd()` > `default`；用户层无作用域键。
- **检索跨全域 = 层 × 分类**：默认覆盖本会话 S + 当前项目 P + 全局 U（I 层是原文索引，走单独入口），且每层内**所有已注册分类表**都在并集里——不是只查某一类；结果带 `scope` / `project` / `kind` 标签与来源回指，按「U > 当前项目 P > 其他项目 P > S，同 project 优先，再按分数」加权。
- **跨项目 P 默认不读、可显式开**：一次查询只碰本会话 + 当前项目 + U；要读其他项目的 `.dsh/project.db` 需显式开关（`crossProject: true`，或 TUI `/memory search --all-projects`）——**只能由用户显式发起，agent 不得自行开启**——候选项目根由宿主会话索引里的 distinct `header.cwd` 去重派生，目录已删 / 无库的跳过并计数（代价：逐个打开库，没有全局索引）。
- **检索前先判分类**：调用方给了 `kind` → 只查该分类的注册表（`doc_index` 不是注册分类，默认不参与，需显式指定其固定标签）；没给 → 由各分类的**查询路由规则**决定参与集合（规则未声明的分类作通配一起参与）——例如「技能类」查询不把日志类分类拉进来，避免 N 库 × M 表的全量扫描。
- **收窄用两个维度**：`scope` 限层、`kind` 限分类（可组合）；默认两个维度都不排除（本会话可见的层 × 参与判定的分类集合）。
- **U 层对所有项目可见是设计意图**（不是泄漏面）：它承载跨项目成立的偏好 / 习惯；不按项目或分类做可见性限制，敏感内容靠隐私底线与写入审阅拦在库外。
- **回指链**：U → P → S → I → T0（原文），逐级可回。

### 7.1 文档优先：记忆补文档之缺

项目事实与约定以**文档为权威源**（git 版本化、有属主与过期条件、多人共享），记忆**不替文档做副本**：

| 内容 | 归属 | 理由 |
| --- | --- | --- |
| 项目事实 / 约定（构建命令、目录、流程、结构） | **文档优先**：记忆只存 `docRef`（路径 + 章节）+ 一句结论 | 复制一份就会在文档改动后给出过期答案——比没有更糟 |
| 用户偏好 / 编程风格 | 记忆（U 层） | 属于人，不属于仓库，文档无承载 |
| 问题处理经验 / 失败教训 / 技能 | 记忆（P / U 层） | 写进文档是噪声 |
| 会话过程态（未定稿的判断、临时决定） | 记忆（S 层） | 文档不该记流水账 |

机制：

- **指针化写入**：带 `docRef` 的内容只存结论 + 指针 + `docHash`，不复制正文（哪些分类适用由注册方决定）。
- **检索标注**：结果带 `docRef` 的条目显式标「以文档为准」，调用方去读原文。
- **失效即标记**：`docHash` 与当前文件不一致 → 条目标 `stale`；文件消失 → 状态更新为 `missing`。两种情况都**不自动改写、不自动删除**（文档是权威，记忆不自作主张）。

### 7.2 内容索引：与被索引内容同层同寿命

**原则**：索引不是独立层，它**建在被索引内容所属的库里**，与该层同寿命——内容活多久，索引活多久。

| 被索引内容 | 归属层 | 索引落在 | 索引寿命 |
| --- | --- | --- | --- |
| 工具输出原文（spill / 会话文本） | T0（会话期） | `digest.db`（I） | 随会话失效（§3.1） |
| **项目文档**（仓库内 md / 说明文件） | **P** | `project.db` 的 `doc_index` | 项目存续 |
| 用户私有文档（用户自有长期文件） | U | `user.db` 的 `doc_index` | 永久 |

**关键约束**：会话里读到的**项目文档**，索引记在 **P 库**，不复制进 S 库——文档是 P 级内容，不因为「这次会话读过它」就降成会话级。

其余条款：

- **表结构**：`doc_index`（`docRef` / 章节标题 / 行范围 / `docHash` / 摘要行）+ FTS5——复用既有的 FTS5 + TRIGGER 机制；**FTS 只索引章节标题与摘要行，不索引文档正文**（正文留在文件里）。
- **解析复用 `md-logic`**：它的 CommonMark 节树已带行范围，拿来切片；`md-map` 的锚点 / 引用关系可选一并入库。
- **维护挂巩固链**：启动后 + `compaction/end` 后增量扫（按 `mtime` + `size` + `docHash` 判变），与 §8.1「事件驱动、不轮询」一致。
- **命中行为**：返回**路径 + 行范围 + 摘要行**，调用方去读原文；正文不入库（与 §1 一致）。
- **参与检索**：`doc_index` 与分类表同属该层检索并集，命中带 `scope` 标签与一个固定的文档索引标签（标签名由实现定，本包不硬编码）；**给了 `kind` 时它默认不参与**（不是注册分类），要文档来源需显式指定该标签。
- **边界**：只索引配置给该层的 glob；**U 层默认不索引任何 glob**，需显式配置，且一旦索引，其摘要与 U 层其它内容一样对所有项目可见（§7 的设计意图，不是泄漏）；状态与 §7.1 同一套（`present` / `stale` / `missing`），检索默认不返回 `missing`；首次全量扫一次。

## 8 容量、淘汰与频率

- **寿命由作用域定，容量只是兜底**：会话层主淘汰 = 宿主删会话目录 + 7 天兜底（`session/disposed` 只做提升收尾，见 §3.2）；项目层主淘汰 = 容量；用户层不淘汰。
- **不限制单条内容大小**：写入不因「太长」被截断或拒绝；控制体积靠提升时的概括与逐库容量淘汰，不靠入口闸门。
- **口径 = 字节**（`page_count × page_size`）：实测旧库 601 MB 里 366 MB（61%）是 trigram FTS 索引，token 估算量不到主要成本。
- **逐库独立上限**（§2 表）；S / P / U 的触发点 = 写入后 + 巩固（启动后 / compaction 后，10 分钟节流）；**I 层由属主 `output-compress` 自管**（启动后 + 每次写入后自查）。
- **淘汰顺序**：`importance` 升序 → `last_referenced` 升序（`0` 视为最旧）→ `id` 升序；按**缺口**淘汰（作废现状「每轮最多 50 条」）。
- **不跨层淘汰**：会话库超限不牵连项目库；项目库满了不动用户库。
- **默认值可调**：逐库上限、排序权重、提升阈值、合并窗口、兜底过期、节流间隔都是配置项，先按本文缺省跑（用户 2026-10-08：「先用默认，不好用了再改」）。
- **文档失效**：`docRef` 的 `docHash` 与当前文件不一致 → 该条标 `stale` 并计数，等审阅或用户决定更新。
- **降级（就地压缩）** 只对 S 层生效：超限时先按统一顺序把正文压缩（保留可检索足迹），仍超限才硬淘汰；`importance = 5` 与被提升过的行**跳过降级、仍参与硬淘汰**（否则 S 层上限不可满足）。

### 8.1 更新频率（事件驱动 + 节流）

**现状实测（2026-10-08，只读）**：写入 2,284 条/天、163 条/会话（峰值 7,775 条/天）；淘汰 **0 条**（TTL 30 天 + `importance ≤ 2`，而库只有 23 天 → 从未触发）；命中刷新 **0 次**（`last_referenced > created_at` 全库为零 → 检索面几乎没被调用）。即现状是「只写不减、只涨不升」。

**设计原则：事件驱动，时间只做节流下限**——进程内没有常驻调度器，定时轮询既不可靠也白跑（没有新输入时重算纯浪费）。

| 动作 | 触发 | 节流 / 上限 |
| --- | --- | --- |
| S 层写入 | 每条白名单事件（实时） | 合并窗口：同一会话、同一 `kind`、**同一事实**（判据同 §3.4）的要点在 5 分钟内合并（压掉 163 条/会话的碎片） |
| I → S 提升 | 属主 `output-compress` push（索引写入后）+ 属主巩固时重推未成功候选 | 每轮 ≤ 20 条候选 |
| S → P 提升 | 会话结束（`session/disposed`）+ `compaction/end` 后 | 每轮 ≤ 20 条候选（防审阅疲劳） |
| P → U 提升 | 巩固时 | 每轮 ≤ 10 条候选 |
| 容量淘汰 | 写入后（超限即削）+ 巩固时 | 巩固节流 `minIntervalMs` 10 min（现状缺省沿用） |
| 兜底过期（S） | 启动后 + 巩固时（按 `created_at` 计龄，7 天） | 无 |
| 兜底过期 / 容量（I） | **属主 `output-compress` 自管**（启动后 + 每次写入后） | 无 |
| 文档失配标记 | 检索命中该条时**懒校验** `docHash` + 巩固时批量 | 无 |
| 审阅 | 人或 agent 拉起（`/memory review`） | **默认保留**：提升候选与**冲突候选**都不自动拒绝 / 不自动丢弃，积压不阻塞写入；`candidates` 表**独立小上限**（每层 5 MB，超限先清最旧候选） |

- **重新概括按增量，不按时间**：上层条目新增来源 ≥ 3 条，或距上次概括新增命中 ≥ 3 次 → 触发一次重写（把新经验并入旧结论）；否则不重算。
- **命中信号的现实性**：命中类判据（`last_referenced > created_at`）在检索面未被调用时恒为假——所以 S → P 的判据保持**或**语义（命中 **或** 决策类事件 **或** 失败教训），不允许任何自动提升只依赖命中。
- **不按时间衰减删除**：`last_referenced` 与年龄只用于**排序与提示**（P 层容量淘汰顺序、复核清单），不单独触发删除；寿命只由作用域与容量决定（§8）。

## 9 Schema 与版本

- **一库一指纹**：`application_id`（`'DIGE'` / `'SESS'` / `'PROJ'` / `'USER'`）+ `user_version`；文件 0o600、父目录 0o700。
- **版本不匹配不再整库重置**：改为「按迁移链升级；无可用迁移则**拒绝打开**并报错」。现状的「DROP 后重建」在 GB 级库上等于数据全失。
- **迁移最小面**：v1（旧 `knowledge.db`）→ 目标布局按 §10 处理，不做字段级搬运。
- **跨进程**：`journal_mode = wal`；`ConsolidationLock` 仍是进程内互斥，跨进程需文件锁（既有残余边界）。
- **可空加列例外（2026-10-08）**：向后兼容的**可空列追加**（如基表的 `promoted_to` / `origin` / `reviewer` 等审阅留痕列）按「加表式」处理——幂等 `ALTER TABLE ADD COLUMN`（`pragma_table_info` 探测）、不 bump 版本；改**既有列**的类型 / 约束 / 删列才走版本迁移。

## 10 存量迁移与维护

- **v1 存量清空（用户 2026-10-08 裁定）**：旧 `knowledge.db`（601 MB / 52,786 行，全 `default`）与其 91 条凭据形态条目（`key=value` 90 + `sk-` 3）**一律清空**。落地为显式迁移动作（服务面 `migrate({from: "v1", mode: "drop"})` + 文档说明），**不静默删**、不自动执行。
- **清空后防复发**：靠 §5 的分层闸门 + `rescanDenied()` 常规维护。
- **不备份**：旧库**直接删除**（用户 2026-10-08 裁定）——不做 `VACUUM INTO`、不留 `.bak`；删除仍由**显式调用**触发，不静默删。

## 13 已知边界与观察项

- CJK 检索仍依赖 `LIKE` 兜底（分词器限制）；trigram 只在 P 层保留（占 61% 空间的索引不再复制到每层）。
- 概括由 **LLM** 完成（§6）；机械部分只剩事件要点抽取、近似替换与命中计数——「语义相似即同一知识」的自动合并仍不做。
- 隐私底线是形态匹配、命中即整条拒绝（不打码）；无熵检测、无规则语言。
- S 层 5 分钟合并窗口是**进程内内存态**，重启即失效（最多多出几条碎片，不丢数据）。
- `referenced_at` 只统计**经索引入口**（`searchDigests` / 按 locator 回读）的引用；用宿主 `read` 工具直接打开 spill 文件不计（属主无法感知）。
- 一个 dsh 进程内多目录不隔离（`cwd` 同源）；跨进程共享库的锁仍是进程内互斥。
- U 层目前只有 `/memory` 读取面，尚未注入 system prompt。
- 「文档里是否已有权威内容」由写入方 / 审阅者判断，记忆不做全库文档扫描比对（没有文档索引）。
- 删除不传播：高层条目删掉后，它的下层来源行与指向它的回指链允许悬空（§6.1）。
- 分类的语义、扩展列与写入前判定归注册方；本包不解释内容（不内置分类名单与语义映射）。
- 分类不在本包内做语义判定：自动路径的建议分类来自注册方规则（可含 LLM），本包不内置映射；用户直写显式给 `kind`，未给则落配置的兜底分类（**U 层例外**：必须显式给已注册分类，不允许兜底），分类漂移靠闸门拦。
- 跨项目检索没有全局索引：候选来自宿主会话索引里的 distinct `cwd`，项目目录被移动 / 删除后其 P 库不可达（跳过并计数）。
- 项目根 `.dsh/` 里的 P 层库是**项目内文件**：需要提醒用户加进 `.gitignore`（或由安装 / 文档提示），否则会被提交。
- 提升审阅需要人（或 agent）动作：候选积压不阻塞写入，随所在库的寿命过期或被 `candidates` 表容量淘汰（先清最旧）；用户明确指令免审。
- 「用户明确指令」的判定看调用来源标记（`origin: user`，在用户发起的命令 / TUI 动作上生成），agent 自主写入不得自标为 `user`。
- 观察项：trigram 是否进一步退化为可选；官方 `sessionQuery` 的 FTS5 是否开启并与 P 层做分工验证；记忆的备份 / 导出面（当前不做专门接口，需要时用 SQLite 原生手段）；LLM 概括的模型 / 成本 / 提示词演进。
