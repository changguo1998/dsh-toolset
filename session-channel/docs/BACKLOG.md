## 1. 缺陷

**#2 自动别名分配在词表耗尽后静默失效**（〔进行中: 2026-10-17〕 2026-10-17 登记，来源：`docs/implementation/2026-10-17-group-transport-surface.md` 调研 9）：**现象 / 现状** —— `#autoAlias`（`src/index.ts:360-378`）只在会话首见时试一次，冲突重试上限 `AUTO_ALIAS_TRIES = 8`（`src/alias-words.ts:166`），耗尽后**静默返回**（无日志、无计数，调用方不可观测）；词表 `AUTO_ALIAS_WORDS` 共 148 词。2026-10-17 只读实测本机别名表 295 条 = `ui-*` 146 + `sub-*` 148 + 显式 `docs` 1 → **`sub-` 命名空间已 100% 占满**（新子代理永远拿不到自动别名），`ui-*` 占 146/148（8 次重试全撞的概率约 0.9）；11 个在线会话中只有 1 个有别名。别名键无 TTL（`src/keys.ts:28-31`），已结束会话的名字不回收，命名空间只增不减。**期望** —— 让自动别名重新可用且失败可见：扩词表或加序号后缀 / 按未占用集合确定性挑选 / 首见后允许节流重试 / 失败记日志（或经 `status()` 暴露）。**接取时裁定** —— ① 词表规模与命名规则（2026-10-01 的既有裁定是「词表 ≤8 字符不缩减」，扩规模与加后缀都需重新确认）；② 是否给别名键加 TTL 或做会话结束回收 —— 与 `docs/archived/2026-10-01-auto-alias.md:21`「不随会话结束清理」的既有决策冲突，且会破坏「同 sessionId 恢复后同名」（群组编排若用别名登记就依赖它）。**落点** —— `src/alias-words.ts`、`src/index.ts`（`#autoAlias` 与触发点）、`tests/alias.test.ts`、`README.md`（别名口径）。**验收** —— 命名空间未满时新会话必得别名；命名空间满时失败可见（日志或状态面）；既有别名不受影响；`tests/alias.test.ts` 相关用例同步。**估时** —— 0.5 至 1 天（含测试与文档）。**优先级** —— P2（群组编排若改为按别名寻址则升 P1；当前处置是按 sessionId 登记，不阻塞）。**2026-10-17 用户裁定处置**：词表扩到 ≥ 256 词 + 自动别名加 4 位哈希后缀（`sha256(sessionId)` 前 4 位 hex），由任务「群组编排所需的传输面：服务面核对 + 别名持久性与自动别名分配」一并做（本条已随之接取）；既有 295 条旧格式别名不动。〔待办: 2026-10-17 登记〕

**#3 工具返回体含 `undefined` 字段, 触发宿主 `INVALID_TOOL_OUTPUT`（`send` 与 `status` 必现）**（〔进行中: 2026-10-17〕 2026-10-17 登记，来源：用户实测报错 + 本轮只读定位）：**现象 / 现状** —— 调 `session_channel` 的 `send` 经常报 `Error: tool "session_channel" returned invalid output: value is not lossless JSON`。根因是**工具返回体里带了值为 `undefined` 的字段**：① `src/broker.ts:444-447` 的 `delivered = waitMs > 0 ? await waitForAck(...) : undefined` 随后 `return {ok: true, messageId, delivered, target}` —— 工具面缺省不传 `waitMs`（`src/index.ts:1248-1250`，描述写「缺省不等」），故**不带 `waitMs` 的 send 必失败**，带了就正常（这解释「经常」而非「总是」）；② `src/index.ts:296` 在后台重试连上后写 `this.#status.error = undefined`，而 `status()`（`:529-531`）直接展开该对象，故**经历过一次重试的进程里 `action=status` 也必失败**（首连成功不写该键，故不是每次都中）。宿主侧依据：工具返回体过 `snapshotToolValue`（`dsh-tools/lib/index.js:2577`）→ `dsh-util-values` 的 `walkJsonValue`，**嵌套 `undefined`（以及 `NaN` / `Infinity` / `-0` / 非平凡原型）一律拒绝**，抛 `ToolOutputError`（code `INVALID_TOOL_OUTPUT`）；`JSON.stringify` 会丢这个键，但校验发生在序列化之前。已实测对拍：同一返回体 `delivered: undefined` → 拒绝，改成布尔 → 通过。**期望** —— 四个模型侧工具（`session_channel` / `channel_delegate` / `channel_task` / `channel_task_result`）的返回体一律是 lossless JSON：在 `execute` 出口统一做一次递归去 `undefined` 的归一（**2026-10-17 用户裁定选此口径**；服务面返回值不动，插件内消费方不受影响），并逐字段核一遍另三个工具的返回体（`DelegateResult` / `TaskRecord` / 任务查询结果的可选字段是否也需按需拼装）。**落点** —— `src/index.ts`（四个工具出口归一；`#status.error` 的清零方式改为 `delete` 或 `status()` 按需拼装）、`src/broker.ts`（`sendMessage` 的返回按需拼 `delivered`）、`tests/`（新增用例：工具返回体过一遍 lossless JSON 判定，覆盖「`send` 不带 `waitMs`」与「重试后 `status()`」两态）、`README.md`（工具返回口径一句）。**验收** —— 不带 `waitMs` 的 `send` 返回 `{ok: true, messageId, target}` 且**无 `delivered` 键**；经历一次后台重试后 `action=status` 正常返回；四个工具的返回体对同一判定全部通过；`npm --prefix session-channel run test` 全绿。**估时** —— 0.5 小时以内（归一函数 + 两处根因 + 用例）。**优先级** —— P1（`send` 是群组编排与跨会话协作的必经面，现在不带 `waitMs` 就不可用）。**2026-10-17 用户裁定处置**：本内容并入任务「群组编排所需的传输面：服务面核对 + 别名持久性与自动别名分配」同批做（本条随之接取）；修法经同日裁定取**出口统一归一**（备选的「逐处按需拼字段」被否）。〔待办: 2026-10-17 登记〕

## 2. 功能

**#1 补群组编排（agent-group）所需的传输面：服务面核对 + 别名持久性**（〔进行中: 2026-10-17〕 2026-10-17 登记，来源：`docs/implementation/2026-10-16-peer-group-protocol-design.md` 的 S2 / S3 / S5）：**现象 / 现状** —— ① **服务面方法名与签名未核实**：群组编排首期只经 `inject` 用服务面做「投递指令」「收取回报」两个操作，而设计只核到「服务面存在」这一层（`README.md:59-60`、`:106`），签名要在实现前逐条对。现服务面（`src/index.ts` 的 `provide("sessionChannel")`）已暴露 `peers` / `send` / `inbox` / `aliasSet` / `aliasList` / `aliasClear` / `kvSet` / `kvGet` / `kvList` / `kvDelete` / `delegate` / `taskStatus` / `taskList` / `taskCancel` / `taskResult` / `status` —— **投递与收取大概率已够用，缺口待核对**。② **别名的自动分配时机与持久性未定**：唯一性在写入时已强制（重名报 `alias_taken`，`force` 可覆盖；同一会话改别名会先清旧名，`src/broker.ts:158-188`），但群组登记还依赖「恢复后不变」这条无代码依据的假定（S5 第 2 项）；实测别名表约 200 条、`sub-*` / `ui-*` 前缀自动生成，绝大多数 `online: false`，设计推断「别名可能首次用到才生成，而非启动即分配」。目标唯一命中是硬约束 —— 0 命中 `target_offline`、多命中 `target_ambiguous`（`src/broker.ts:381-395`、`:414-448`），实测本机已有 3 个会话同 cwd。**期望** —— ① 出一份「服务面核对表」：群组编排两个操作对应的现有方法（或缺口与新增签名），写进 `README.md` 服务面清单；② 落定别名的自动分配时机与持久性（恢复会话后名字不变、不因重连而漂移），或在文档里明确不保证并给出替代寻址口径（登记只用 sessionId + 显式 `alias set`）。**接取时裁定** —— 若判定别名持久性不做，则退化为「只用 sessionId + 显式别名」口径，并同步给 agent-group 侧。**落点** —— `session-channel/src/index.ts`（服务面）、`src/broker.ts`（投递、寻址与别名）、`README.md`（服务面清单与寻址口径）、`session-channel/tests/`。**验收** —— 核对表逐条可查（存在即记签名，缺失即补并加用例）；别名用例：同机两次分配不同名、恢复会话后名字不变（或文档明写不保证）、重名请求被拒且报 `alias_taken`。**估时** —— 核对 0.5 小时；若需新增服务面方法 +0.5 天；别名持久性修补 0.5 至 1 天。**优先级** —— P2（群组编排的前置；先做核对再定是否含实现）。〔待办: 2026-10-17 登记〕
