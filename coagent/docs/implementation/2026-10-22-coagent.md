## 目标

新增插件 `coagent`，在 `subagent` 之外提供一条**独立进程**的 agent 拉起与编排能力，交付七个动作：`spawn`（在 herdr pane 里起 `dsh headless "<task>"` 或长驻交互会话，可指定 profile / cwd / 模型）、`list`（认领与状态）、`send`（一次性或经 `channel_delegate` 派任务）、`wait`（等结果 / 退出码）、`cancel`（取消任务或按键中断）、`close`（收尾并清理 pane）、`read`（看屏或读日志，仅作诊断）。

核心诉求是**上下文零继承**：coagent 是全新进程 + 全新会话，不接收任何父会话历史；换来的是更高的控制自由度（读屏、实时插话、按键中断、独立 profile / 模型、跨 cwd、并行多实例）。

边界：不替代 `subagent` / `subagent_fork`（进程内、轻量、需共享上下文的场景仍归它们）；不修改 `herdr-use` / `session-channel` / `agent-group` 的服务面，只作为消费方；不引入新的凭据或权限模型（沿用 `DSH_HOME`，隔离问题另行裁定）。

**本阶段范围（2026-10-23 用户裁定）**：条目六个待定项尚未对齐，故本轮**只做调研与设计**——把动作面、状态机、失败路径与验收方案写进本文档，供人工裁定后再进入实现；不写实现代码、不做真机验收、不提交实现、不收尾。

## 调研

> 来源：宿主包（`@deepseek-ai/dsh` 安装目录）源码与 README、本仓库各包源码、以及本次实际命令输出；`推断` 表示未经代码或命令直接证实。

### 1. 宿主面：headless 一次性执行

- **入口与任务来源**：`dsh --profile headless "<task>"`；任务也可从 stdin 读（位置参数省略或为单个 `-`），空任务在运行前即报错；`--help` 打印帮助后退出、不跑任务（`@deepseek-ai/dsh-headless/README.md`「Running a one-shot task」「Help and task errors」）。
- **事件流**：`--json` 把 stdout 换成 NDJSON——首事件 `session`（带本次会话身份）、末事件 `final`（正文不截断）；中间为 `status` / `text` / `thinking` / `tool_call` / `tool_result`，除 `final` 外字符串与对象键截到 8 KiB、单行 32 KiB（同 README「Machine-readable output」）。运行期之外失败写 `error` 事件且无 `final`。
- **会话恢复**：`--session-id <id>` 采纳已持久化会话；无此会话直接失败。采纳要求组合里有 `sessionPersistence` 与 `sessionQuery`，并拒绝子代理 / 分叉会话、未记录工作目录、preset 与本 profile 不一致、以及同进程内同 id 已有 agent 在跑的四种情形（README「Choosing the session identity」）。
- **退出码**：完成的 `turn/end` → 0；其他（中止 / 出错 / 该区间无回合）→ 1，并另写 `dsh: <code>: <message>` 到 stderr（README「Exit mapping」）。回合内失败仍会给 `final`（可能为空）→ 成败要同时看退出码与 `final` 文本。
- **工作目录**：新会话记录 fs provider 解析出的目录；实际 `cwd` 由子进程启动目录决定（README「Choosing the session identity」）。
- **模型选择**：headless 读宿主共享的 `agentDefaultModel` 选择，命令行**没有**模型参数（README「Run flow」）；该服务每进程一个缺省，配置字段只有 `provider` / `model` / `reasoningEffort`（`@deepseek-ai/dsh-agent-default-model/README.md`「Summary」「One process-wide default」）。故"按子进程指定模型"只能走 profile 配置或 `--patch` overlay。
- **相关环境变量**：`DSH_PERMISSION_MODE`（沙箱档，见 §3）、`DSH_TOOLS_MODE`（PTC 模式，headless patch 透传）；`DSH_` 前缀属"只能由继承环境提供"的 bootstrap 变量，`.env` 不能设置（`dsh-app-boot/lib/index.js:3662-3690` 的 `BOOTSTRAP_PREFIXES` 与 `isBootstrapOnly`）。

### 2. 宿主面：profile 启动与 DSH_HOME 写盘

- 每次启动都会写 `$DSH_HOME/profiles/<name>`：`package.json` 缺失时按模板 `initProfile`（`dsh-app-boot/lib/index.js:1066-1071`）、`removeLinkProjections(dir)` 先删 `.dsh-module-fallback` 及 `node_modules` 里指向它的软链（同文件 `:637-643`，调用点 `:1072`）、`mkdir(profileDir, { recursive: true })`（`:439`）。
- 本次实测：在只读沙箱内执行 `dsh headless --help` 直接失败，报 `Read-only file system '/home/guochang/.dsh/profiles/headless/.dsh-module-fallback'`（本次命令输出）→ 印证启动期确实对该目录做删除式操作。
- 推论（有代码依据）：多个子进程**同时**用同一 profile 启动会互相删改同一 `.dsh-module-fallback`，存在竞争；共享 `DSH_HOME` 还意味着 sessions、logs、storages、凭据库都是同一份。
- 本机 `dsh` 解析到 fnm 的 multishell 垫片（`/run/user/1000/fnm_multishells/.../bin/dsh` → 真实 `lib/bin.js`），该垫片目录随 shell 会话存在；herdr pane 的 shell 环境是否有同一 PATH **未验证**。→ 子进程命令必须用绝对路径并显式带上 PATH，不能依赖 pane 的 PATH。

### 3. 宿主面：approval 与权限模式

- base 的 `sandbox-policy` 缺省 `mode = $DSH_PERMISSION_MODE ?? 'workspace-write'`；approval 三档映射为 `read-only` → `ask`、`workspace-write` → `ask`、`danger-full-access` → `never`（`dsh-base/cordis.patch.yml:240-277`）。
- `ask` 档把请求交给部署里的 answerer；**没有终止 answerer 时结算 `unavailable` 并 fail-closed**，`never` 档在服务内部直接拒绝（`dsh-user-approval/README.md`「Summary」「Known Limitations」）。
- headless bundle 不挂 UI / answerer（`dsh-headless/cordis.patch.yml` 全文只有 startup、runner、hmr 与 credentials 三行禁用）→ 子进程在 `ask` 档下一律失败关闭。
- 结论：无人值守的子代理要真正能动手只有两条路——把 `DSH_PERMISSION_MODE` 提到 `danger-full-access`（等于关掉 approval），或接受"越界操作被拒"。设计必须显式暴露这个选择，不能默认放大权限。

### 4. 宿主面：凭据链

- 本地凭据库优先级：存储文件 > 启动环境 > 项目 `.env` > `$DSH_HOME/.env`；存储文件仅本用户可读，但 agent 工具进程以同一用户运行，**无法把密钥与 agent 隔开**（`dsh-credentials-local/README.md`「Summary」）。
- headless patch 把 `credentials` / `authorization` / `deepseek-account` 三行置 `disabled: true`，注释写明"一次性任务用启动期凭据而不是交互式存储"（`dsh-headless/cordis.patch.yml` 末三行）。
- 官方给的恢复写法：在 headless profile 的用户层或 `--patch` overlay 里补三行 `disabled: false`（`dsh-headless/README.md` §Credentials）。
- 本次实测：父进程环境里没有任何 `*_API_KEY` 类变量（`printenv` 变量名筛选为空）→ 子进程若用 headless 缺省组合，只能靠 `$DSH_HOME/.env`；否则必然认证失败。这条决定了"默认拉起要带凭据 overlay"。

### 5. 底座：herdr-use 的库面与可注入性

- **双出口**：工具面注册单个 `herdr_use`；库面 `createHerdrPlugin` 返回的 handle 带 `deps`，也可手工构造 `DispatchDeps` 直接调 `dispatchAction(action, args, deps, exec)`——它是唯一执行入口（`herdr-use/src/actions.ts:1187-1200`、`herdr-use/README.md:113-116`）。
- **DispatchDeps 全字段**：必填 `config` / `runner` / `reader` / `registry`；可选 `callerPaneId` / `callerTabId` / `resolveSession` / `guardCheck` / `clock`（`herdr-use/src/actions.ts:60-79`）。手工构造不注册工具、不挂退出清理，前置条件比 `createHerdrPlugin` 少很多。
- **不可直接调 `createHerdrPlugin`**：它会再注册一次 `herdr_use`（与既有工具重名），且要求二进制可解析 + 服务端探活成功（`herdr-use/src/main.ts:271-345`）→ coagent 只能手工组装 deps。
- 动作面要点（coagent 依赖的部分）：
  - `pane_create` 只有 `direction` / `cwd` / `label` 三个可选参数，落点固定为本会话 workspace 活动 tab 的 pane；成功后登记并 `pane rename` 打标（`actions.ts:398-467`）。
  - `pane_run` 是一次提交（文本 + 回车），回执只有 `{pane_id, command}`，**没有退出码与输出**（`actions.ts:971-1001`）；`pane_send_text` 不回车且空串视为未给；`pane_send_keys` 传键名数组（`actions.ts:887-969`）。
  - `pane_info.running` 的唯一判据是 `foreground_processes.length > 0`，`shell_pid` 不参与；"空闲 shell 是否计入前台进程"没有代码证据（`actions.ts:1084-1101`，渲染文案见 `tools.ts:225-226`）。
  - `pane_wait` 的 `match` / `regex` / `stable` 三选一；**超时以 `ok:false` + `code:"timeout"` 返回、不抛错**（`actions.ts:744-885`）；它会长期占住该 pane 的串行队列（`actions.ts:1152-1155`）。
  - `pane_read` 走 socket，回执带 `revision` / `truncated`；库面 `payload.text` 是完整文本，200 行 / 16000 字符的截断只在工具层（`actions.ts:709-732`、`tools.ts:34-59`）。
  - `pane_close` 只关 pane 并注销，不关 tab、不关 workspace；对非自建 pane 需同时 `allowForeignPanes: true` 与 `force: true`（`actions.ts:1106-1142`、`1206-1227`）。`pane_label` 能改已有 pane 的 label，空串即清除，清除同时注销归属（`actions.ts:1012-1048`）。
- **登记表与 workspace 绑定**：`PaneRecord` / `TabRecord` / `WorkspaceBinding` 全部是进程内存态、不落盘（`herdr-use/src/registry.ts:22-50`）；workspace 约定 label 为 `<cwd 目录名>/<会话 id 末 8 位>`，每次动作前先 `workspace list` 按 label 精确匹配复用、没有才新建（`herdr-use/src/workspace.ts:88-98`、`:142-174`）。
- **退出清理**：`createExitCleanup().closeAllSync()` 同步关掉登记过的 pane，workspace 已空则一并关闭，最后清表；挂在 dispose 与 `process.once("exit")`（`registry.ts:230-267`、`main.ts:370-401`）。
- **库面不经过审批门与沙箱门**（两者只盖工具面）→ 消费者自己按会话模式决定能否调用（`herdr-use/README.md:149`）。
- **coagent 的复用口径（本设计采用）**：手工组装 `DispatchDeps`——`resolveConfig` + `resolveHerdrBin` / `readHerdrHandshake` / `probeHerdrServerSync` + `createDefaultRunner` + `createPaneReader` + `new PaneRegistry` + `makeGuardChecker` + 自备 `resolveSession`。workspace 复用判断：coagent 用自己的 registry 时，label 相同仍会匹配到同一个 workspace，故 pane 与用户会话并列可见；但两个 registry 的串行锁互不相通，**首次并发建 workspace 可能各建一个**（推断，见决策项 9）。

### 6. 底座：session-channel 的任务面

- **服务面 17 方法**（`SERVICE_FACE_METHODS`，`session-channel/src/index.ts:1780-1799`，注册体 `:1837-1866`）。coagent 用得上的：`peers` / `statusOf` / `send` / `delegate` / `taskStatus` / `taskList` / `taskCancel` / `taskResult`；`state` 只是工具 action 不是服务方法。
- **PeerInfo**：`sessionId` / `pid` / `instanceId` / `cwd` / `profile` / `startedAt`（`types.ts:32-45`）；`profile` 取 `config.profile ?? process.env.DSH_PROFILE ?? ""`（`index.ts:1243`）。心跳 5 s、在线键 TTL 15 s（`constants.ts:7,10`），`peers()` 顺带清理 pid 已死的在线键（`broker.ts:137-155`）。
- **可见性前提**：同一 Redis 端点即可见（缺省 `$XDG_RUNTIME_DIR/dsh-session-channel.sock`，`client.ts:37-52`，与 `DSH_HOME` 无关）；但会话必须先被目标进程的 `session/event` 看到（**不做启动枚举、事件无回放**），且单进程最多跟踪 32 个会话（`index.ts:426`、`:543-553`）。→ 刚起的子会话可能要等它产生第一条事件才进 `peers`。
- **delegate 流程**：校验 → 写 `pending` 记录（`deadline = now + timeoutSec`）→ 走 send 注入（正文 `TASK <id>: ...`）→ 返回**尚未终结**的任务记录；`timeoutSec` 是执行 deadline（读时懒判定 `timeout`），注入等待只有 `waitMs`（`index.ts:776-863`、`tasks.ts:134-145`）。
- **六态与写入方**：`pending` = delegate；`running` = worker 侧 `user/message` 文本匹配 `TASK <id>:` 时写；`done` = worker `turn/end` 自动回收（**每次最多回收 1 个、只收队首且 running 的**）；`done` / `failed` = 显式 `taskResult`；`canceled` = `taskCancel`（**不通知 worker**）；`timeout` = 读时懒判定（`taskStatus` 会落表并通知，`taskList` 只落表）（`index.ts:1011-1114`、`:866-958`）。
- **覆盖规则**：终态可被终态覆盖——`taskResult` 能把 `canceled` / `timeout` 翻成 `done` / `failed` 并再通知（`tasks.ts:102-132`）→ coagent 的"已取消"必须是本地粘性状态，忽略迟到结果。
- **上限**：结果 64 KB（超限置 `resultTruncated`）、任务正文 8 KB、回传通知 8 KB（`tasks.ts:14-23`）。
- **无阻塞等待接口**（`delegate.waitMs` 只等注入回执）→ 只能轮询 `taskStatus`；建议 0.5 至 2 s 起步、长任务退避到 5 s，终态至少读一次以结算超时。
- **注入语义**：目标空闲时 `followup` 立刻开新回合；忙时排到当前回合之后（`inject.ts:87-106`）。寻址 `cwd:<path>` 只去尾部斜杠、不 realpath，同 cwd 多会话必然歧义；同一 sessionId 双进程在线也算歧义（`broker.ts:439-484`）。

### 7. 底座：agent-group 的写面与只读面

- 写面只在工具 `agent_group`（10 个动作），服务面 `provide("agentGroup")` **只有只读** `status(managerSessionId, groupName?)`（`agent-group/src/main.ts:436-487`）。
- 成员状态四态（`offline` / `idle` / `working` / `stuck`）是消费方按 session-channel 状态牌现算的（`agent-group/README.md`「成员状态视图」）。
- 传输 = `delegate` + `taskStatus`，成员寻址 = `peers` + `aliasList`，离线不排队（`agent-group/README.md`「传输接入」）。
- 结论：coagent **不能在插件内复用组的写面**——组状态按 `managerSessionId` 落文件，另有工具那一个写入者，两个写入者会互相覆盖。可行的集成只有：交付稳定 sessionId 让模型自己 `add_member`，或读 `agentGroup.status` 展示归属。

### 8. 证据：pane 里命令退出后发生什么

- herdr-use 全包**没有退出码概念**，`ActionResult` 无 `exitCode` / `finished` 字段（`herdr-use/src/types.ts:251-276`）。
- 间接证据显示 pane 保留并回到 shell：渲染对"无前台进程"写的是"pane 停在 shell 提示符"（`tools.ts:225-226`）；herdr-integration 记录 herdr 侧存在"pane 回到空闲 shell"状态（`herdr-integration/README.md:27`）；dsh 被 `kill -9` 后 pane 仍在并带 label（`docs/archived/2026-10-16-herdr-pane-design.md:334`）。
- 结论：**pane 不随其中的命令退出而关闭，也不提供退出码** → coagent 必须自建结果通道（文件 + 事件流），屏幕只能作诊断。

## 决策

> 决策项 1 至 6 对应条目六个待定项；7 至 10 是实现前必须一并定下的附加项。选项后的字母即选定项。

**决策项 1：一次性与长驻的默认策略**

- 选项：a 按任务长短自动判定；b 显式 `mode` 参数，缺省 `oneshot`；c 只做一次性，长驻留待后续。
- 选定：**b**。
- 理由：两种模式的**结果回收、取消手段、观测面完全不同**（文件 + 退出码 vs 任务表 + 忙闲牌），"任务长短"无法在拉起时可靠估计；显式参数让模型知道自己控制的是哪种进程。缺省 `oneshot` 是因为它与条目描述的 `dsh headless "<task>"` 主路径一致，长驻只需多给 `mode=session` 与 `profile`。
- 被拒代价：a 把长任务误判成一次性 → 观察超时后没有任务表可查；把短任务误判成长驻 → 留下常驻进程与 pane，还要额外清理与 token 消耗。c 砍掉的正是"零继承 + 多点派发"这个与 `herdr_use` 手写命令的差异点。

**决策项 2：结果回收主路径**

- 选项：a 一次性走 `--json` 的 NDJSON 文件 + 退出码文件，长驻走 `channel_delegate` 任务表轮询；b 统一用屏幕解析（`pane_read` / `pane_wait`）；c 任务内联 argv + 直接读 stdout。
- 选定：**a**。
- 理由：stdout 是官方文档化的契约（首 `session`、末 `final`，`final` 无损），落文件后不受 TUI 重绘、滚动截断与 ANSI 影响；退出码文件补上 herdr 不提供的信号（§8）；长驻必须走任务表才有 cancel / timeout / 64 KB 结果上限这些语义。
- 被拒代价：b 的屏幕是展示态，`pane_read` 缺省 200 行 / 16000 字符就截断，不能当结果契约。c 受 argv 长度与引号限制，中途也看不到进度。

**决策项 3：DSH_HOME 与凭据隔离**

- 选项：a 固定共享 `DSH_HOME`；b 缺省共享，另开 `dshHome` 参数由调用方给一个**已准备好**的隔离 home（插件不自动引导）；c 自动引导隔离 home（复制 profile 目录 / `dsh plugin add`）。
- 选定：**b**，另加凭据三档 `auth`：`inherit`（缺省，headless profile 补 overlay 恢复凭据库）/ `env`（不补 overlay，靠继承环境或 `.env`）/ `none`（明确不给凭据，用于本地模型）。
- 理由：共享时 profile 目录写竞争真实存在（§2），但"要不要隔离"是部署决策，不该由插件替用户决定；隔离 home 只做**前置检查**（profile 是否存在且可写），失败给可执行提示，不自己造 home。凭据档与 home 解耦：`dshHome` 隔离解决"文件分家"，`auth` 解决"给不给凭据"。
- 被拒代价：a 没有隔离出口，满足不了条目的"凭据隔离"诉求。c 要跑 pnpm 或复制带相对链的 `node_modules` 与 `.dsh-module-fallback`，慢且易碎，等于把部署问题塞进工具调用里。
- **诚实边界**：共享 `DSH_HOME` + `auth: inherit` 等于子进程拿到与父会话同一套凭据，权限面确实放大；`dshHome` 隔离也**不能**把密钥与 agent 分开（同用户可读，§4）——真正的凭据隔离要靠操作系统账号或容器，本插件不承诺。

**决策项 4：并发上限与 pane 治理**

- 选项：a 不限 + 靠模型自觉；b 每会话 `maxLive`（缺省 4）超限直接拒绝、不排队，配 `maxRecords` 记录配额与 stale 懒清理；c 上限 + 排队。
- 选定：**b**。
- 理由：子进程是烧 token 的常驻物，无上限最危险；排队会把压力藏起来（模型以为已经拉起，实际在等），而拒绝能立刻给出可执行理由（先 `wait` / `close` 再重试）。记录配额避免会话目录无限膨胀：超出先清最老的**已关闭**记录文件，索引里留一行墓碑。
- 被拒代价：a 一次 fan-out 就能起几十个 dsh 进程。c 的排队与 `wait` 超时叠加会产生"排队中被判超时"的歧义。

**决策项 5：失败 / 超时 / 崩溃残留的判定与清理**

- 选项：a 以 pane 存活为唯一判据；b 证据优先级 = 退出码文件 > NDJSON 尾事件 > pane 存在性 > 时间；`lost` 作为独立状态；`keep` 决定是否保留现场；父进程退出按 `closeOnExit` 处理；c 不判定，让用户看屏。
- 选定：**b**。
- 理由：herdr 没有退出码（§8），只能由子进程自己写；NDJSON 尾事件能区分"跑完但失败"与"根本没起来"；`lost` 与 `failed` 分开是因为清理动作不同（前者关 pane + 留日志，后者留日志 + 可重试）。`closeOnExit` 缺省 `running`：父进程正常退出时关掉未终结子进程的 pane，已终结记录按 `keep` 保留。
- 被拒代价：a 分不清"进程被杀"与"命令跑完、pane 回 idle"。c 与"收结果"这个核心诉求冲突。
- **已知不可覆盖**：父进程被 `kill -9` 时退出钩子不跑（herdr-use 同样如此），残留只能由下次 `list` 按 label 标 stale 再 `close`。

**决策项 6：是否复用 agent-group 的等级语义**

- 选项：a 插件内复用 `GroupService` 写组状态；b 只交付稳定 `coagent_id` + `sessionId`，由模型调 `agent_group` 组网，coagent 只读展示归属；c coagent 自造一套父子等级。
- 选定：**b**。
- 理由：组状态按 `managerSessionId` 落文件、工具是唯一写入者（§7），第二个写入者会互相覆盖；一次性子代理没有"回报 / 未结指令"语义，等级对它没有意义。`list` 里读 `agentGroup.status`（可选、失败降级）足够回答"它属于哪个组"。
- 被拒代价：a 两个写入者 + 管理者语义冲突（coagent 的调用方 vs 组工具的调用方）。c 与既有组语义重复且不互通。

**决策项 7（附加）：工具面形态**

- 选项：a 单工具 `coagent` 按 action 分派七动作；b 每个动作一个工具；c 复用 `herdr_use` 加 action。
- 选定：**a**。
- 理由：与 `herdr_use` / `agent_group` / `session_channel` / `task_*` 的既有形态一致；工具表只多一行，模式差异可以集中写在描述里。c 不成立——`herdr_use` 已注册，不能扩它的动作表。
- 被拒代价：b 七个工具名挤占全局工具表，参数校验与错误码还会分散。

**决策项 8（附加）：子进程命令构造**

- 选项：a 任务内联进 argv；b 任务写文件 + 生成 `run.sh`（`trap` 落退出码）+ `pane_run("sh <run.sh>")`；c 用 `pane_send_text` 逐行键入。
- 选定：**b**。
- 理由：任务可能含引号、换行或超长（argv 上限与引号风险），文件 + `sh` 脚本把注入面压到"一个路径"；脚本里的 `trap` 让 ctrl+c / SIGTERM 也能落退出码，正好补 herdr 的缺口；`pane_run` 只发一行命令，避免多行键入的时序问题。脚本与日志都放记录目录（0700）。
- 被拒代价：a 有引号与长度风险（headless 本来就支持 stdin，没必要冒险）。c 多行键入要多次 `send_text` + 回车，回显污染与时序都不可控。

**决策项 9（附加）：workspace 复用口径**

- 选项：a 复用 herdr-use 工具路径的 registry；b 自建 `PaneRegistry`，靠同一 label 匹配同一 workspace，首次并发竞争记为已知限制；c 给 coagent 单独建一个 workspace。
- 选定：**b**。
- 理由：不改 herdr-use 服务面是本任务边界（a 要在 herdr-use 加 `provide`，属跨包改动）；workspace label 只由 cwd 与会话 id 决定（§5），自建 registry 仍能匹配到同一个 workspace，用户能在同一 workspace 里看到 coagent 的 pane。竞争窗口只在"同一会话第一次并发使用两套 registry"，代价是最多多出一个空 workspace，可在 `close` 时按 label 兜底。
- 被拒代价：c 把 coagent 的 pane 放到另一个 workspace，用户看不见屏，失去"看屏"这个核心价值。

**决策项 10（附加）：状态落盘位置**

- 选项：a 只放进程内存；b 放会话目录（`sessionPaths.sessionDirFor(父会话)` 下，索引文件原子写 + 每记录一目录）；c 放 memory-base。
- 选定：**b**。
- 理由：重启后要能 `list` 到残留并按 label 清理（herdr-use 登记表不落盘正是这个痛点）；会话目录天然按会话隔离且已有 0700 约定；memory-base 是知识库不是运行态。`sessionPaths` 服务缺席时降级到 `$DSH_HOME/coagent/<父会话 id>/` 并告警一次。

## 规划

### 1. 动作面与回执契约

**公共约定**

- 工具名 `coagent`，单工具按 `action` 分派七个动作（决策项 7）：`spawn` / `list` / `send` / `wait` / `cancel` / `close` / `read`。
- 回执一律普通对象：成功 `{ok:true, ...}`；失败 `{ok:false, error, reason, next?}`，`error` 是稳定码、`reason` 给人看、`next` 给下一步（口径同 `agent_group` / `session_channel`）。
- 每个动作都要求调用方会话（`exec.agent.session`）；取不到 → `session_unavailable`。
- `coagent_id` 形如 `c-<8 位 hex>`，创建时生成、永不复用；pane label 固定 `coagent/<coagent_id>`。
- 同一 `coagent_id` 的动作串行化（进程内按 id 排队）；`cancel` / `close` 幂等；`wait` 可并发，但它只推进**认定**、不改由子进程决定的事实。

**动作适用性**

| 动作 | oneshot | session |
| --- | --- | --- |
| `spawn` | ✓ | ✓（必须给 `profile`） |
| `list` | ✓ | ✓ |
| `send` | ✗ `not_applicable`（提示用 `wait` / `read`） | ✓ |
| `wait` | ✓ | ✓ |
| `cancel` | ✓ | ✓ |
| `close` | ✓ | ✓ |
| `read` | ✓ | ✓ |

**`spawn`**

| 参数 | 类型 / 取值 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `mode` | `oneshot` / `session` | `oneshot` | 决策项 1 |
| `task` | string | — | oneshot 必填；session 可选，给了就在认领成功后自动派一条 |
| `profile` | string | oneshot：`headless`；session：**必填** | 子进程的 dsh profile |
| `cwd` | 绝对路径 | 父会话 cwd | 必须存在且是目录；子进程文件沙箱以它为根 |
| `model` | `{provider, model, reasoningEffort?}` | 继承 profile | 写成 `--patch` overlay（§1 调研：命令行没有模型参数） |
| `auth` | `inherit` / `env` / `none` | `inherit` | headless 时 `inherit` 生成恢复凭据库的 overlay（决策项 3） |
| `permissionMode` | `read-only` / `workspace-write` / `danger-full-access` | `workspace-write` | 写进子进程环境 `DSH_PERMISSION_MODE` |
| `dshHome` | 绝对路径 | 共享当前 `DSH_HOME` | 给了就做"含该 profile 且可写"的前置检查 |
| `resume` | 会话 id | — | oneshot → `--session-id`；session → `--resume` |
| `timeoutSec` | 正整数 | `1800` | oneshot 的缺省等待上限 / session 的任务 deadline |
| `label` | string | `coagent-<id>` | 仅展示用，pane label 另有固定格式 |
| `keep` | boolean | `false` | 完成 / 关闭后是否保留 pane 与日志 |
| `env` | 字符串映射 | `{}` | 追加环境变量；`DSH_HOME` / `DSH_PERMISSION_MODE` 只认专用参数，`env` 里给了就拒绝 |

成功回执：`{ok:true, coagent_id, mode, state, pane_id, session_id?, cmd, paths:{dir, run, stdout, stderr, exit, overlay?}, label}`。
失败码：`task_required` / `mode_invalid` / `auth_invalid` / `permission_mode_invalid` / `model_invalid` / `cwd_invalid` / `dsh_home_invalid` / `profile_missing` / `dsh_bin_not_found` / `herdr_unavailable` / `limit_exceeded` / `pane_create_failed` / `record_write_failed`。

**`list`**

- 参数：`coagent_id?`（单查）、`state?`（过滤）、`probe`（`live` 缺省 / `none`）、`limit`（缺省 20）。
- 回执：`{ok:true, items:[{coagent_id, mode, state, profile, cwd, pane_id, session_id?, started_at, elapsed_ms, last_event?, task_id?, task_status?, stale?}], live, max_live}`。
- 行为：读索引；对非终态记录按证据优先级探测一次（决策项 5），顺手推进状态；`probe=live` 的探测次数以 `maxLive` 为预算上限，超出部分标 `stale?` 留给下一次。

**`send`（仅 session）**

- 参数：`coagent_id`、`text`、`deliver`（`task` 缺省 / `message`）、`timeoutSec`（缺省 1800）、`waitMs`（缺省 3000）、`wait`（boolean，缺省 false）、`waitTimeoutMs`（`wait=true` 时用，缺省 60000）。
- 回执：`{ok:true, coagent_id, session_id, task_id?, delivered?, state, result?}`。
- 行为：`deliver=task` 走 `delegate`（有任务表、可 cancel、可超时）；`deliver=message` 走 `send`（发完即走，不留任务）。`wait=true` 内部转一次 `wait`。
- 失败码：`not_applicable` / `not_found` / `channel_unavailable` / `delegate_failed` / `target_offline` / `target_ambiguous` / `text_too_large`（后三者原样透传 session-channel 的稳定码）。

**`wait`**

- 参数：`coagent_id`、`timeoutMs`（缺省 60000、上限 600000）、`until`（`terminal` 缺省 / `idle`）、`includeText`（缺省 true）、`maxChars`（缺省 12000）、`tailEvents`（缺省 5）。
- 回执：`{ok:true, coagent_id, state, waited_ms, timed_out, exit_code?, text?, text_truncated?, task_id?, task_status?, last_events?, next?}`。
- 语义：oneshot 等退出码或 `lost`；session 等当前未结任务的终态、`until=idle` 则等忙闲牌回到 `idle`。**等待超时只改回执（`timed_out:true`），不改状态**——避免"模型以为进程结束了"。

**`cancel`**

- 参数：`coagent_id`、`force`（缺省 false）、`reason?`。
- 行为：session 先 `taskCancel(未结任务)`，再按需 `ctrl+c`；oneshot 发 `ctrl+c`（脚本 `trap` 会落 130），`force=true` 时直接 `pane_close`。本地状态置 `canceled` 且**粘性**（忽略任务表里迟到的 `done` / `failed`，§6 的终态覆盖规则）。
- 回执：`{ok:true, coagent_id, state:"canceled", canceled_task?, pane_closed, notes?}`；已终态时 `{ok:true, already_terminal:true}`。

**`close`**

- 参数：`coagent_id`、`force`（缺省 false）、`keep`（缺省取记录里的值）。
- 行为：优雅收尾——session 先给 `/quit`（或 `ctrl+c`）并等 ≤ 5 s，再 `pane_close`；oneshot 直接 `pane_close`。记录置 `closed`；`keep=false` 时删日志与脚本、索引留墓碑。
- 回执：`{ok:true, coagent_id, state:"closed", pane_id, removed_files, notes?}`；重复调用幂等（`already_closed:true`）。

**`read`**

- 参数：`coagent_id`、`from`（`screen` 缺省 / `stdout` / `stderr`）、`lines`（缺省 200）、`maxChars`（缺省 16000）、`tail`（缺省 true）。
- 回执：`{ok:true, from, text, truncated, bytes}`。
- `screen` 走 herdr `pane_read`（`recent-unwrapped`）；`stdout` / `stderr` 读文件尾。session 模式的 `stdout` 是 TUI 全屏转义，回执里提示优先用 `screen`。

**错误码总表**

| 类别 | 码 |
| --- | --- |
| 参数 | `invalid_action` / `invalid_params` / `task_required` / `mode_invalid` / `auth_invalid` / `permission_mode_invalid` / `model_invalid` |
| 环境 | `session_unavailable` / `session_paths_unavailable` / `herdr_unavailable` / `dsh_bin_not_found` / `channel_unavailable` |
| 前置 | `cwd_invalid` / `dsh_home_invalid` / `profile_missing` / `limit_exceeded` / `not_found` / `not_applicable` |
| 执行 | `pane_create_failed` / `inject_failed` / `delegate_failed` / `record_write_failed` |
| 状态 | `already_terminal` / `pane_missing` / `lost` / `herdr_timeout` |

**与底座错误的映射**：herdr 的 `pane_not_found` / `timeout` / `socket-error` 归一到 `pane_missing` / `herdr_timeout` / `herdr_unavailable`，原文进 `reason`；session-channel 已有稳定码（`target_offline` / `target_ambiguous` / `text_too_large`）原样透传，其余 `{ok:false, error}` 只有可读文案的，归到 `delegate_failed` 并把原文放进 `reason`。

### 2. 状态机与失败路径

**两层状态**：coagent 记录态（本包判定，9 个）与任务态（session-channel 的任务记录，6 个）分开记，避免"任务超时"被误读成"进程结束"。

- 记录态：`starting` / `running` / `ready` / `busy` / `done` / `failed` / `canceled` / `lost` / `closed`。
- 任务态：`pending` / `running` / `done` / `failed` / `canceled` / `timeout`（原样透传，见 §6）。

**各态的判定证据**

| 状态 | 判定证据 |
| --- | --- |
| `starting` | 索引已写、`pane_run` 已返回 ok；尚无进程或会话证据 |
| `running`（oneshot） | `exit.code` 不存在，且（`pane_info.running` 为真 或 `stdout.ndjson` 有新增行） |
| `ready`（session） | 已在 `peers` 里认领到 `session_id`，且没有未结任务 |
| `busy`（session） | 存在未结任务（`task_status` ∈ `pending` / `running`） |
| `done`（oneshot） | `exit.code` 为 0，且 NDJSON 里有 `final` 事件 |
| `failed`（oneshot） | `exit.code` 非 0，或出现 `error` 事件，或退出码为 0 但无 `final`（契约违背） |
| `canceled` | 本地 `cancel` 已记录（粘性，不被迟到的任务终态回滚） |
| `lost` | `exit.code` 不存在且进程证据消失（连续两次探测 `running` 为假，或 pane 不存在）；session 模式另加"已认领但 `peers` 掉线且未 `close`" |
| `closed` | `pane_close` 成功（或 pane 已不存在）+ 记录已收尾 |

**转移表**

| 起始态 | 事件（驱动者） | 目标态 |
| --- | --- | --- |
| — | `spawn` 通过全部前置、pane 建成、`pane_run` 成功（spawn 动作） | `starting` |
| `starting` | 探测到前台进程或 NDJSON 首行（list / wait / read 的探测） | `running` |
| `starting` | 认领到 `session_id`（list / wait 的 peers 轮询） | `ready` |
| `starting` | 退出码已落 + 非 0 / `error` 事件（探测） | `failed` |
| `starting` | 认领超时（session）或进程证据消失（oneshot） | `lost` |
| `running` | 退出码 0 + `final` 事件（探测） | `done` |
| `running` | 退出码非 0 / `error` 事件 / 无 `final`（探测，退出后二次确认） | `failed` |
| `running` | 进程证据消失且无退出码（连续两次探测） | `lost` |
| `ready` | `send(wait=false)` 或 `send(wait=true)` 成功建任务（send 动作） | `busy` |
| `busy` | 任务进终态（wait / list 读 `taskStatus`） | `ready`（结果留在记录里，任务态另记） |
| `ready` / `busy` | `peers` 掉线且 pane 不存在（探测） | `lost` |
| `starting` / `running` / `ready` / `busy` | `cancel`（cancel 动作） | `canceled` |
| `done` / `failed` / `canceled` / `lost` | `close`（close 动作） | `closed` |
| 任意非 `closed` | 父进程正常退出且 `closeOnExit=running` 命中未终结记录（`process.once("exit")`） | `closed`（`reason: parent-exit`） |

**八条失败路径**

| 编号 | 场景 | 判定证据 | 状态落点 | 清理动作 | 回执与幂等 |
| --- | --- | --- | --- | --- | --- |
| F1 | spawn 前置失败（cwd / profile / dshHome / 二进制 / herdr / 配额） | 动作内的前置检查结果 | **不落记录**（避免污染 `list`） | 无（pane 尚未创建） | 具体错误码 + `next`（如 `limit_exceeded` 列出在跑 ids 并提示先 `wait` / `close`）；可重复调用、无副作用 |
| F2 | 启动即失败（命令不存在 / profile 缺失 / 认证失败 / preset 不匹配） | `exit.code` 非 0 + `stderr.log` 里的 `dsh: <code>: <message>` | `failed` | 按 `keep` 决定是否保留 pane（缺省 false → 关 pane 留日志） | 回执带 stderr 末尾 10 行；`wait` / `read` / `close` 可重复 |
| F3 | 崩溃失联（OOM / `kill -9` / 面板重启） | `exit.code` 缺失 + 连续两次 `running` 为假或 pane 不存在 | `lost` | 关 pane（若 `keep=false`）、保留 `stderr.log` | 回执写明判定证据与日志路径；`close` 幂等 |
| F4 | 观察超时（`wait` 超时 / session 任务 deadline） | 本地计时器；或 `taskStatus` 懒判定出 `timeout` | `wait` 超时**不改状态**；任务超时只改任务态 | **不自动杀进程**（可能仍在工作只是没回传）；提示用 `cancel` 或 `close` | 回执 `timed_out:true` 或 `task_status:"timeout"` + `next` |
| F5 | 会话认领失败（session 模式在 `claimTimeoutMs` 内没在 `peers` 里找到） | `peers` 轮询超时（缺省 60 s） | `lost` | 保留 pane 供 `read`（缺省不关，用户可能要看 TUI 的报错） | 回执列可能原因（profile 未挂 session-channel / Redis 端点不同 / 子会话尚未产生事件）+ `next: read` |
| F6 | 取消竞态（取消与完成同时、取消后迟到结果） | 本地 `canceled` 粘性 + 任务表可能之后变 `done` / `failed` | 保持 `canceled`，迟到的任务态写进 `late_task_status` | 不改判、不再发第二次中断 | 回执 `raced:true`；重复 `cancel` 返回 `already_terminal` 或保持 `canceled` |
| F7 | pane 被外部关闭（用户关 pane / workspace 被关） | `pane_info` 返回 `pane_not_found` | 有 `exit.code` → 按退出码落 `done` / `failed`；否则 `lost` | 记录收尾，不再尝试关 pane | `next: read`（读日志）或 `close`；`close` 幂等 |
| F8 | 父进程退出 | 正常：`exit` 钩子；`kill -9`：钩子不跑 | 正常：未终结记录 → `closed(reason=parent-exit)`；崩溃：留在原态 | 正常：同步 `pane close`（每 pane 3 s 上限，同 herdr-use）；崩溃：下次 `list` 探测到 pane 不存在 → `lost` → `close` 归档并标 `stale` | 崩溃路径无回执；`list` / `close` 幂等 |

**并发与 pane 治理**

- `maxLive`（缺省 4）：统计非 `closed` 记录；达到上限时 `spawn` 直接 `limit_exceeded`，**不排队**（决策项 4）。
- `maxRecords`（缺省 50）：索引条数上限；超出时删除最老的 `closed` 记录文件，索引留墓碑行（`coagent_id` / `state` / `closed_at`）。
- `staleAfterSec`（缺省 21600，即 6 小时）：非终态记录超过该时长未推进 → `list` 标 `stale:true`；只标记，不自动杀。
- **两把锁**：`spawn` 用一把进程级"建 pane / 建 workspace"排他锁（与决策项 9 的竞争窗口对应）；其余动作按 `coagent_id` 串行。
- 探测预算：`list(probe=live)` 最多发起 `maxLive` 次 `pane_info`，其余记录沿用上次证据并标 `stale`。

**状态落盘**

- 目录：`sessionPaths.sessionDirFor(父会话 id)` 下的 `coagent/`；缺服务时降级到 `$DSH_HOME/coagent/<父会话 id>/` 并告警一次（决策项 10）。
- 索引：`index.json`（`{version:1, records:{...}}`），`0700` 目录，写临时文件后 `rename` 原子替换；每次状态推进写一次。
- 每条记录一个目录 `<id>/`：`run.sh`（0700，`trap` 落退出码）、`task.txt`（headless 从 stdin 读）、`overlay.yml`（`--patch`，模型与凭据恢复）、`stdout.ndjson`、`stderr.log`、`exit.code`、`meta.json`（供人排查的完整命令与环境快照，不含密钥）。
- 重启恢复：不在插件启动时扫盘；`list` 与其它动作首次触达时读索引，再做一次 `pane_list` 按 label 前缀 `coagent/` 对账——对不上且非终态的记录标 `lost`，让残留可被 `close` 清掉。

### 3. 验收方案

**单测：注入面与隔离**

- 三个注入点：herdr 侧的 `HerdrRunner`（记录 argv、返回可控信封）与 `PaneReader`（可控 `revision` / 文本）；通道侧的 `ChannelFace`（`peers` / `statusOf` / `delegate` / `taskStatus` / `taskCancel` / `send`）；时钟与轮询间隔（可控，避免真实 sleep）。
- 每个用例用 `os.tmpdir()` 下的临时会话目录，不碰真实 `$DSH_HOME`、不需要 herdr 二进制、不需要 Redis；`node --test` 直接跑。
- 断言口径：状态与回执字段（不比对整段文案）+ 产生的外部副作用（`pane_run` 的 argv 里不含任务正文、`exit.code` 读取路径、`pane close` 只对未终结记录发生）。

| 用例 | 输入构造 | 断言 |
| --- | --- | --- |
| T1 oneshot 成功 | fake 建 pane / run 成功；预写 `exit.code=0` 与含 `final` 的 NDJSON | `state=done`；`text` 等于 `final.text`；`run.sh` 路径出现在 `pane_run` 的 argv 里且任务正文**不在** argv 中 |
| T2 启动即失败（F2） | `exit.code=1` + `stderr.log` 含 `dsh: auth: ...` | `state=failed`；`reason` 含 stderr 尾行；`keep=false` 时有 `pane close`；重复 `close` 幂等 |
| T3 崩溃失联（F3） | 无 `exit.code`；`pane_info` 连续两次 `running=false` | `state=lost`；两次探测都发生；`stderr.log` 保留；`close` 幂等 |
| T4 观察超时（F4） | 无 `exit.code`；`wait(timeoutMs=极小)` | `timed_out=true` 且 `state` 不变；随后写入 `exit.code=0` + `final`，下一次 `wait` 得 `done` |
| T5 认领失败（F5） | `mode=session`；`peers` 恒空 | `state=lost`；`reason` 列出三类可能原因；pane 未被关闭；`next` 指向 `read` |
| T6 取消竞态（F6） | 建任务 → `cancel` → 之后 `taskStatus` 返回 `done` | `state` 保持 `canceled`；`late_task_status=done` 记进记录；重复 `cancel` 不重复发中断 |
| T7 pane 被外部关闭（F7） | `pane_info` 返回 `pane_not_found`；分"有 / 无 exit.code"两例 | 有退出码按码落 `done` / `failed`，无则 `lost`；不再尝试 `pane close` |
| T8 父进程退出（F8） | 触发 `exit` 钩子（`closeOnExit=running`），一条未终结 + 一条已 `done` | 只对未终结记录同步 `pane close`；记录标 `closed(reason=parent-exit)`；已终结记录不动 |
| T9 前置失败（F1） | `cwd` 不存在；再由 4 条在跑记录触发上限 | 分别返回 `cwd_invalid` / `limit_exceeded`；**索引文件未被写入**；`limit_exceeded` 回执列出在跑 ids |
| T10 session 成功 | `mode=session`；`peers` 首次空、第二次出现匹配 peer | `state=ready`；`send` 后 `delegate` 被调一次且 `task_id` 入库；`taskStatus=done` 后回 `ready` 并带结果 |
| T11 重启恢复 | 预置索引含非终态记录；`pane_list` 不含其 pane | `list` 把该记录标 `lost`；`close` 能归档 |
| T12 配额与 stale | 51 条 `closed` 记录；一条非终态记录时间戳调早 7 小时 | 最老记录文件被删、墓碑保留；该记录 `stale=true` |

**真机脚本：`coagent/scripts/verify-coagent.mjs`**

- 前提：herdr 二进制可解析 + 服务端在跑 + 已 `npm run build`；凭据可用（脚本先跑一次 headless 极小任务做自检，失败即中止并打印原因）。
- 开关：`--keep`（保留 pane 与日志）、`--with-session`（加跑 session 模式，需要 `--session-profile <name>`，缺省 `fff`）、`--task <text>`（覆盖缺省任务）。
- 步骤与断言：
  1. **oneshot 全链**：`spawn` 一个确定性任务（如"只输出数字 2"）→ `wait` ≤ 120 s → 断言 `state=done`、`exit_code=0`、`text` 含 `2`；`read(from=stdout)` 能读到 `final` 行。
  2. **上下文零继承（机械验证，三条判据）**：任务文本固定为"输出你收到的第一条用户消息原文以及你的 session id"——① 输出里不含父会话任何标记（父 session id、`[CHANNEL]` 前缀、传给子进程的任务原文以外的父会话内容）；② 输出里的 session id 与父会话 id 不同；③ 用 `sessionPaths.sessionDirFor(子 session id)` 读子会话日志，`user/message` 事件恰为 1 条且内容等于任务文本。任一条不成立即失败（这条替换人工"肉眼看"）。
  3. **并行与单独取消**：`spawn` 两条带等待的长任务 → `list` 显示两条 `running` → `cancel` 其中一条 → 断言该条 `canceled`、另一条仍 `running` → `close` 两条。
  4. **残留检查**：`close` 后 `pane_list` 不含 `coagent/` 前缀的 pane；`session_channel.peers` 不含子会话；索引里全部记录为 `closed`；`keep=false` 时记录目录只剩墓碑。
  5. **session 模式（`--with-session`）**：`spawn(mode=session, profile=fff)` → 60 s 内认领 → `send` 一个短任务 → `wait(task_id)` 得 `done` → `close`；断言子 session id 与父不同、pane 已关、`peers` 已消失。
- 失败处理：任一步断言失败立即非 0 退出并打印回执、日志路径与 `list` 快照；`finally` 里无条件 `close` 本次创建的记录（`--keep` 时跳过关闭但打印 ids）。
- 定位：真机脚本**不进 CI**（同 herdr-use 的 `scripts/verify-herdr-use.mjs`），由人工在验收阶段跑。

**本阶段（设计）能验证与不能验证的部分**

- 能：本设计的所有判定规则都能用假的 runner / reader / channel 覆盖；文档里的每条宿主与底座事实都有代码或命令证据。
- 不能：真机链路（拉起、认领、收结果、无残留）要等实现后才有对象可验；本阶段不跑。
