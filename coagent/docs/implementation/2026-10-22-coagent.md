## 目标

新增插件 `coagent`：在 herdr **终端**的**交互 shell** 里发 `fffdsh`，拉起一个**独立进程、上下文零继承**的长驻 dsh 会话，认领它并把 `terminal_id` / `session_id` 交给调用方；结束时可优雅停止并清理。

**职责只有两段**（2026-10-23 人工裁定）：**拉起**与**收尾**。

- 拉起：选 `cwd` → 经 herdr-use 服务面 `create`（新 tab，缺省前台）→ 在终端里 `run` 一行 `fffdsh` → 经 session-channel 的 `peers` 认领新会话 → 回执 `terminal_id` + `session_id`；任一步失败即回滚（`close(terminal_id)` **一次**关掉整个终端），并落一条 `failed` 记录（失败码 + 屏摘要）。
- 收尾：`run(terminal_id, "/quit")` 等进程退出，或直接 `close(terminal_id)` 关整个终端 → 注销记录与目录。

中间的一切**不实现**：派任务 / 收结果走 session-channel（`channel_delegate` / 任务表），编排与等级走 agent-group（模型自己调 `agent_group`），看屏 / 插话 / 按键走 herdr-use 的十个工具（`herdr_read` / `herdr_text` / `herdr_key`）。见「对接口径」。

边界：**不自己建终端、不自己起进程**（一律经 herdr-use 服务面）；**不做一次性任务**（`subagent` 已覆盖）；不改 `herdr-use` / `session-channel` / `agent-group` 的源码——coagent 需要的 herdr-use 共用服务面由主分支约定契约并分派任务（已定稿）；不做 TUI 面板。

## 调研

> 来源：用户的 shell 函数实际定义、宿主包源码、本仓库包源码、本次命令输出；`推断` 表示未经代码或命令直接证实。旧版调研里关于 `dsh headless` 一次性执行、NDJSON 回收、`DSH_HOME` 隔离与凭据三档的内容已随职责收缩作废（见「决策」作废项），只保留与本设计直接相关的事实。

### 1. 用户入口：`fffdsh` 是交互 shell 函数

- 本次实测 `bash -ic 'declare -f fffdsh'` 拿到完整函数体，四段逻辑：① 用 `grep -qE '^[A-Za-z_][A-Za-z0-9_]*API_KEY=.+'` 检查**当前 shell 环境**里有 `*_API_KEY`，没有就打印 `fffdsh: 环境中缺少 API_KEY。` 并返回 1；② 没有显式 `--profile` 时遍历 `~/.dsh/profiles/fff/node_modules/@dsh-toolset/*` 的软链，按 `src` 内容哈希与 `.fff-build-hash` 比较，缺构建或哈希不符就 `npm run build` 重建，最后 `dsh --profile fff "$@"`；③ 退出码 75 视为重启请求，从 `$DSH_RESTART_FILE` 取会话 id 后以 `--resume <id>`（取不到则 `-c`）重启；④ 其它退出码原样返回。
- 它是**函数**而不是可执行文件：`sh -c 'fffdsh'`、非交互 shell、`exec` 直接调用都拿不到它（函数不在非交互 shell 的命名空间里）→ 这就是「必须在终端的交互 shell 里发 `fffdsh`」的硬依据。
- 缺省 profile 是 `fff`（主会话 profile），函数不设置 `DSH_HOME` → 与用户手起 dsh 完全一致：同 profile、同 `DSH_HOME`、同凭据库、同审批配置。
- 前置条件的现实影响：终端的 shell 若没导出 `*_API_KEY`，`fffdsh` 在启动 dsh 之前就失败（屏上有固定文案）→ 「spawn 成功」必须以屏上出现 dsh 界面 / `peers` 出现会话为准，不能只看命令是否送达。
- 首次启动可能触发多个包的 `npm run build`（逐包比对哈希），耗时可达数分钟 → 认领超时不能按秒级假设。

### 2. herdr 终端与交互 shell

- **终端模型（2026-10-23 新契约）**：一个终端 = `herdr_create` 内部执行 `tab create` 建出的**一个 tab + 它自带的 root pane**；`terminal_id` 取 root pane id，`tab_id` 只存 herdr-use 的登记表、不出工具面。关闭只有 `close(terminal_id)`（关整个 tab）。工具面不再出现 pane / tab / workspace 概念。
- 终端里没有前台进程时停在 shell 提示符 → 终端天然就是交互 shell 的入口。
- herdr 不回报终端内命令的退出码，`ActionResult` 没有 `exitCode` / `finished` → 「起没起来」只能靠屏文本 + session-channel 的在线键判定。
- `herdr_run` 是一次提交（文本 + 回车），文本作为单个 argv 元素交给 herdr、**不过 shell**，最终由终端里的 shell 解释；空串按未给处理。

### 3. herdr-use：服务面（新契约）与旧缺口

- **新契约（2026-10-23 定稿，I 组实现中）**：工具面是十个具名工具（`herdr_list` / `herdr_read` / `herdr_info` / `herdr_wait` / `herdr_create` / `herdr_close` / `herdr_label` / `herdr_text` / `herdr_key` / `herdr_run`，无 `action` 参数）；同轮 `ctx.provide("herdrUse", service)`，服务面方法用 camelCase（`create` / `list` / `read` / `info` / `wait` / `label` / `text` / `key` / `run` / `close`）加通用 `dispatch`，与工具面共用**同一份登记表、同一把写锁、同一套会话绑定**。本包只消费其中六个：`create` / `run` / `read` / `info` / `close` / `list`，另用 `isRegistered` 做可选自检。
- 旧缺口（重构前，仍解释「为什么必须走服务面」）：库面要自己组装 `DispatchDeps`，会得到**第二份 `PaneRegistry`**——workspace label 相同能匹配到同一个 workspace，但两把写锁互不相通，herdr-use 的退出清理也不认 coagent 建的对象。这正是裁定「必须走服务面」的原因。
- 契约要点（写进本包结构声明与单测断言）：① 登记表与锁必须是工具路径那一份；② 会话上下文可传 `{session: {id, cwd}}`，不必伪造工具 `exec`；③ 回执统一 `ActionResult`，错误码已改 terminal 口径（`terminal-required` / `terminal-not-registered` / `ambiguous-terminal`，删 pane / tab 系列）；④ 文本截断只在工具渲染层，服务面返回完整文本；⑤ 服务面不经 `tools/pre-execute`（进程内可信 API，消费方自负策略）。
- 本包用到的参数面：`CreateOptions` = `foreground?` / `cwd?` / `label?`（coagent 固定 `foreground: true`）；`ReadOptions` = `source?` / `lines?` / `format?`；`close` 只收 `terminal_id`，**没有** `closePane` / `closeTab`。

### 4. session-channel：认领与交接

- `peers()` 返回 `sessionId` / `pid` / `cwd` / `profile` / `startedAt`，`profile` 取 `config.profile ?? process.env.DSH_PROFILE ?? ""` → 认领匹配键是 `profile` + `cwd` + `startedAt >= spawn 时刻`，再用「不在已有记录里」排除旧会话。
- 可见性前提：会话必须先被**它自己进程**的 `session/event` 看到（不做启动枚举、事件无回放），心跳 5 s、在线键 TTL 15 s → 刚起的子会话要等它产生第一条事件才进 `peers`；这就是认领要轮询、拿不到就判 `lost` 的原因。
- 交接面（本包只写进文档、不实现）：`delegate({to: sessionId, task, timeoutSec})` 建任务并注入，`taskStatus` 轮询拿结果（无阻塞等待接口），`taskCancel` 取消但不通知 worker，终态可被迟到的 `taskResult` 覆盖——这些语义由调用方承担。
- 忙闲牌 `statusOf(sessionId)` 可作展示字段（`idle` / `running`），无牌按待机处理。

### 5. agent-group：只读面

- 写面只在工具 `agent_group`，服务面 `provide("agentGroup")` 只有只读 `status(managerSessionId, groupName?)` → coagent 不写组状态（两个写入者会互相覆盖），只把 `session_id` 交给模型去 `add_member`。

### 6. profile 启动写盘与并发

- 每个子进程启动都会写 `$DSH_HOME/profiles/<name>`：`initProfile`、`removeLinkProjections` 删 `.dsh-module-fallback`、`mkdir` → 多个子进程同时启动会互相删改，属**已知限制**；`fffdsh` 自己还会在启动前跑构建检查（§1）。
- 本次实测：只读沙箱里 `dsh headless --help` 因该目录只读而失败，印证启动期确实做删除式操作。

### 7. 权限、审批与凭据

- 子会话是**完整 TUI**（同 profile、同 `DSH_HOME`），自带审批面板 → 需要审批时人工在那个终端里就能应答，不存在 headless 那种「无 answerer 一律 fail-closed」的问题；coagent 不设 `DSH_PERMISSION_MODE`，也不替它决定权限档。
- 凭据沿用主会话的凭据库（同一 `DSH_HOME`）；但 `fffdsh` 自己还要求 **终端的 shell 环境**里有 `*_API_KEY`（§1），两条是独立门槛。

## 决策

> 决策项 1、2 已作废（2026-10-23 人工裁定），保留原文以示历史；现行决策自第 3 项起。

**决策项 1（作废）：一次性与长驻的默认策略**

- 原文：a 按任务长短自动判定；b 显式 `mode` 参数缺省 `oneshot`；c 只做一次性。当时选定 b。
- 作废依据：2026-10-23 裁定——**只做长驻**，一次性任务已由 `subagent` 覆盖；`mode` 参数随之删除。

**决策项 2（作废）：结果回收主路径**

- 原文：a NDJSON 文件 + 退出码文件；b 屏幕解析；c argv 内联 + stdout。当时选定 a。
- 作废依据：同一次裁定——中间内容与操作不实现，派任务与收结果交给 session-channel，coagent 不再持有任何结果回收代码。

**决策项 3：执行底——一律经 herdr-use 服务面**

- 选项：a 自建 `DispatchDeps`（库面）；b 等 herdr-use 新增共用服务面后经 `ctx.get("herdrUse")` 消费；c 直接调 herdr CLI。
- 选定：**b**。
- 理由：裁定明确「不自己开终端或起进程，一律经 herdr-use 服务面」；服务面带来共享登记表与同一把写锁，归属校验与退出清理才能覆盖 coagent 建的终端（§3）。服务面缺席时本包**不注册工具**并告警（与 herdr-use 缺 herdr 时同姿态），不降级到库面。
- 被拒代价：a 造成第二份登记表与第二把锁，退出后残留清理对不上；c 绕过 guard、归属与 workspace 边界。

**决策项 4：拉起方式——在终端的交互 shell 里发 `fffdsh`**

- 选项：a 自己拼 `dsh --profile fff`；b 在终端的交互 shell 里发 `fffdsh`；c 找到函数定义文件直接执行。
- 选定：**b**。
- 理由：`fffdsh` 是 shell 函数，只能由已加载它的交互 shell 触发（§1）；它还负责构建检查、profile 缺省与重启循环，绕开它等于重写一遍且与用户手起的行为不一致。c 不成立（函数不是可执行文件）。
- 被拒代价：a 丢掉构建检查与重启语义，还要自己维护「和用户手起一致」的 profile / 环境口径，容易在 `PATH` 与 `DSH_*` 上漂移。

**决策项 5：前台与可接管硬约束**

- 选项：a 允许 `nohup` / `setsid` / `&` 与后台终端；b 只允许在**用户可见**的终端里**前台**运行，禁止一切脱管手段；c 不检查、靠约定。
- 选定：**b**。
- 具体守门（写进实现与验收）：① 提交给终端的命令**白名单只有 `fffdsh`**，不做任意命令透传；② 文本自检拒绝 `nohup` / `setsid` / `&` / `disown` / `bg` / `screen` / `tmux` 等脱管痕迹（命中即 `launch_forbidden`）；③ 只操作服务面返回的**自有**终端（`terminal_id` 来自 `create` 回执），不接受调用方传入的 `terminal_id`；④ 不创建隐藏对象——`create` 固定 `foreground: true`，终端一律落在调用方会话绑定的 workspace 内（服务面保证），不用 `foreground: false` 的后台 lane；⑤ `spawn` 回执的 `cmd` 字段固定为 `fffdsh`，验收按它机械断言。
- 被拒代价：a 会让 agent 脱离用户视野（看不到屏、无法接管、退出还可能残留），与「人工随时能看到并接管」直接冲突；c 没有强制手段，等于没有约束。

**决策项 6：profile / DSH_HOME / 凭据——固定沿用主会话**

- 选项：a 参数化（`profile` / `dshHome` / `auth` 三档）；b 固定沿用主会话（`fffdsh` 缺省 `--profile fff`、同一 `DSH_HOME`）。
- 选定：**b**。
- 理由：裁定要求「沿用主会话 profile 与 DSH_HOME」；这也是「可接管」的一部分——用户在那个终端里看到的 dsh 与手起的一模一样，排障与凭据行为一致。旧设计的 `dshHome` / `auth` 参数一并删除。
- 被拒代价：a 会造出「用户不熟悉的 dsh」（不同 profile、不同凭据库、不同审批配置），出问题时无法用主会话经验排障；隔离能力本来就做不到真正的凭据隔离（同用户可读），参数化收益低。
- **诚实边界**：子会话拿到与主会话同一套凭据、同一套工具面；coagent 不是权限边界，也**不承诺**隔离。

**决策项 7：并发与终端治理**

- 选项：a 不限；b 每会话 `maxLive`（缺省 4）超限拒绝、不排队，配 `maxRecords` 与 stale 标记；c 上限 + 排队。
- 选定：**b**（沿用旧决策项 4 的结论，口径改为 `starting` / `ready` / `closing` 计入 live）。
- 被拒代价：a 一次并行拉起会烧掉大量 token 与终端；c 的排队与认领超时叠加会产生「排队中被判失败」的歧义。

**决策项 8（重评旧决策项 5）：失败残留的判定与清理**

- 选项：a 只看终端是否存在；b 证据优先级 = 屏文本（`fffdsh` 报错）> `peers` 在线 > 终端存在性 > 时间；`lost` 独立；失败即回滚（`close` 关终端）；`closeOnExit` 交给 herdr-use 的退出清理 + 记录收尾；c 不判定。
- 选定：**b**。
- 理由：没有退出码可用（§2），屏文本是唯一能区分「`fffdsh` 自己失败」与「会话没被认领」的证据；失败回滚放在 `spawn` 内完成，避免残留；退出清理靠服务面共享登记表（herdr-use 的退出清理覆盖同一批终端），coagent 只负责把记录标成 `closed(reason=parent-exit)`。
- 被拒代价：a 分不清「`fffdsh` 报错」与「慢启动」；c 与「失败回滚」的裁定冲突。
- **修订（2026-10-23）**：本条原定「认领超时落记录、其它失败不落」，人工裁定改为**拉起阶段任何失败都落记录**。为此新增终态 `failed`：拉起中失败的记录一律保留，含失败码与屏摘要供排障；终端仍回滚关闭，不留运行中的残留。仅「尚未建出任何对象」的拒绝（`invalid_params` / `cwd_invalid` / `limit_exceeded` / `session_unavailable` / `herdr_unavailable`）不落记录，避免误操作挤满 `maxRecords`。

**决策项 9（重评旧决策项 6）：与 agent-group 的关系**

- 选项：a 插件内写组状态；b 只交付 `session_id`，由模型调 `agent_group`，coagent 不读也不写组状态；c 自造等级。
- 选定：**b**（比旧设计更窄：连只读耦合都不引入，减少一层失败面）。
- 理由：裁定把「编排与等级」明确划给 agent-group；要不要显示归属，调用方自己查 `agent_group status`。
- 被拒代价：a 两个写入者互相覆盖；c 与既有组语义重复且不互通。

**决策项 10：认领与交接口径**

- 选项：a 认领后由 coagent 转发派任务与结果（旧 `send` / `wait`）；b 认领后只暴露 `terminal_id` / `session_id`，后续一律由调用方用 session-channel / agent-group / herdr-use 完成；c 让调用方自己认领。
- 选定：**b**。
- 理由：裁定 ③④ 明确动作面只剩 `spawn` / `list` / `close`，并把「暴露 sessionId 后如何对接」写成契约；c 要调用方自己轮询 `peers` 并猜哪条新会话是自己，容易认错。
- 被拒代价：a 会在 coagent 里再实现一遍任务表与轮询（与 session-channel 重复）；c 认领错误率随并发上升。

**决策项 11：状态落盘位置**

- 选项：a 只放进程内存；b 会话目录（`sessionPaths.sessionDirFor(父会话)` 下的 `coagent/`，索引原子写 + 每记录一目录）；c memory-base。
- 选定：**b**（沿用旧决策项 10）。
- 理由：重启后要能 `list` 到残留并按 label 清理；会话目录天然按会话隔离且已有 0700 约定。`sessionPaths` 缺席时降级到 `$DSH_HOME/coagent/<父会话 id>/` 并告警一次。

**决策项 12（2026-10-23 修订）：建对象只有 `create`（新 tab），删除 `spawn` 的 `target` 参数**

- 原决策（已并入）：`spawn` 的 `target` 缺省新建 tab，`pane` 则在活动 tab 里切 pane。
- 修订后：服务面只提供 `create`（内部 `tab create`，新 tab + 自带 root pane），**没有**「在活动 tab 里切 pane」的可选面；`target` 只剩一个无意义（且不可实现）的分支，直接删除。`spawn` 一律新建终端。
- 理由：原裁定的「缺省新建 tab」与新契约天然一致；新 tab 不挤占父会话当前 tab 的版面，人工在 tab 列表里更容易认出 `coagent/<id>`；失败回滚 `close(terminal_id)` 整 tab 关掉，不会留下空切分位。

## 规划

### 1. 动作面与回执契约

**公共约定**

- 工具名 `coagent`，三个动作：`spawn` / `list` / `close`（2026-10-23 裁定 ③）。
- 回执口径同 `herdr_run` / `agent_group`：成功 `{ok:true, ...}`；失败 `{ok:false, error, reason, next?}`，`error` 稳定码、`reason` 给人看、`next` 给下一步。
- 每个动作都要求调用方会话（`exec.agent.session`），取不到 → `session_unavailable`。
- `coagent_id` 形如 `c-<8 位 hex>`；终端 label 固定 `coagent/<coagent_id>`（新契约里 tab 标题与 root pane label 是同一个 label），便于人工与 `list` 对账。
- `label` 参数只是**记录里的展示名**（缺省 `coagent-<id>`）：新契约把 tab 标题与 root pane label 合成一个，若允许自定义会丢掉 `coagent/` 归属前缀，故自定义名只落 `meta.json` 与回执，不进 herdr。
- 同一 `coagent_id` 的动作串行；`spawn` 另有一把进程级排他锁（避免并发建终端触发 profile 写竞争）。
- **动作面故意不含**：`send` / `wait` / `cancel`（派任务、等结果、取消任务分别归 session-channel 的 `channel_delegate` / `channel_task` 与 herdr-use 的按键），也不含 `read`（看屏归 `herdr_read`）。

**`spawn`**

| 参数 | 类型 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `cwd` | 绝对路径 | 父会话 cwd | 终端的启动目录；必须存在且是目录 |
| `label` | string | `coagent-<id>` | 记录里的展示名（只落记录与回执；终端 label 固定 `coagent/<id>`） |
| `claimTimeoutSec` | 正整数 | `180` | 认领新会话的上限；`fffdsh` 首次可能触发构建，人工已确认 180 s 足够 |

成功回执：`{ok:true, coagent_id, terminal_id, session_id, state:"ready", cwd, label, cmd:"fffdsh", terminal_label, started_at, claimed_at, paths:{dir}}`。

失败码：`herdr_unavailable` / `session_unavailable` / `invalid_params` / `cwd_invalid` / `limit_exceeded` / `terminal_create_failed` / `launch_forbidden` / `launch_failed` / `claim_timeout` / `record_write_failed`。
失败一律**回滚**：调**一次** `close(terminal_id)` 关掉整个终端，并**落一条 `failed` 记录**（含失败码与屏摘要；2026-10-23 裁定：拉起阶段任何失败都落记录）。唯一例外是 `claim_timeout`：落 `lost` 记录、**不关终端**（屏上可能有排障信息），把清理交给 `close`。

**`list`**

- 参数：`coagent_id?`（单查）、`state?`（过滤）、`probe`（`live` 缺省 / `none`）、`limit`（缺省 20）。
- 回执：`{ok:true, items:[{coagent_id, terminal_id?, session_id?, state, cwd, label, started_at, elapsed_ms, terminal_running?, stale?, pruned?}], live, max_live}`。
- 用途只有一个：**清理与排障**。它不返回任务态、不返回忙闲（忙闲归 session-channel 的 `state`）。
- `probe=live` 对非终态记录各做一次 `info` / `peers` 核对并推进状态；预算上限 `maxLive` 次。`closed` / `failed` / `lost` 为终态，不探测。

**`close`**

- 参数：`coagent_id`、`force`（缺省 false）、`keep`（缺省 false，true = 保留记录目录）。
- 行为（全部经 herdr-use 服务面）：`run(terminal_id, "/quit")` → 轮询 `info` 显示无前台进程或 `peers` 掉线（上限 `graceSec`，缺省 15 s）→ `close(terminal_id)`；`force=true` 直接 `close(terminal_id)`。记录置 `closed`，`keep=false` 时删记录目录、索引留墓碑。对 `failed` / `lost` 记录同样幂等归档（终端已被回滚关闭的 `failed` 记录直接置 `closed`）。
- 回执：`{ok:true, coagent_id, state:"closed", terminal_id?, closed_with:"quit"|"terminal_close", removed_files, already_closed?, archived_from?}`。
- 失败码：`not_found` / `close_failed`（附 `next: force=true`）/ `herdr_unavailable`。重复调用幂等（`already_closed:true`）。

**错误码总表**

| 类别 | 码 |
| --- | --- |
| 参数 / 环境 | `invalid_action` / `invalid_params` / `session_unavailable` / `session_paths_unavailable` / `herdr_unavailable` |
| 前置 | `cwd_invalid` / `limit_exceeded` / `not_found` |
| 拉起 | `terminal_create_failed` / `launch_forbidden` / `launch_failed` / `claim_timeout` / `record_write_failed` |
| 收尾 | `close_failed` |

### 2. 状态机与失败路径

**状态集合（只有长驻一种形态）**：`starting` / `ready` / `closing` / `closed` / `failed` / `lost`。

| 状态 | 判定证据 |
| --- | --- |
| `starting` | 终端已建（`create` 回执带 `terminal_id`）、`fffdsh` 已提交；`peers` 里还没有匹配的新会话 |
| `ready` | 已认领 `session_id`，`peers` 里仍在线，`info` 显示终端有前台进程 |
| `closing` | 已发 `/quit`（或 `close` 已开始），等待进程退出 / 终端关闭 |
| `closed` | `close(terminal_id)` 成功（或终端已不存在）+ 记录收尾 |
| `lost` | `claim_timeout`（`starting` 阶段）/ 终端不存在（`terminal-not-registered`）/ `peers` 掉线且终端无前台进程 |
| `failed` | 拉起阶段失败（F2 至 F5、F10）：终端已回滚关闭（`close` 一次），记录含 `fail_code` 与屏摘要 |

**转移表**

| 起始态 | 事件（驱动者） | 目标态 |
| --- | --- | --- |
| — | `spawn` 通过前置、`create` + `run fffdsh` 成功（spawn） | `starting` |
| `starting` | `peers` 匹配到新会话（spawn 的认领轮询或 list 探测） | `ready` |
| `starting` | 认领超时（spawn） | `lost`（落记录，终端留待 `close`） |
| `starting` | 拉起失败：建终端失败 / `run` 失败 / 屏报错 / 违反前台约束（spawn） | `failed`（落记录 + `close` 回滚终端，回执按失败码） |
| `ready` | `list(probe=live)` 核对仍在线 | `ready`（刷新 `terminal_running`） |
| `ready` | 终端不存在，或 `peers` 掉线且无前台进程（list 探测） | `lost` |
| `starting` / `ready` / `lost` | `close`（close） | `closing` |
| `closing` | 进程退出 + `close(terminal_id)` 成功 | `closed` |
| `closing` | `close(terminal_id)` 失败 | 留在 `closing`，回执 `close_failed` + `next: force=true` |
| 任意非 `closed` | 父进程正常退出（herdr-use 退出清理关掉共享登记表里的终端） | `closed(reason=parent-exit)` |

**失败路径**

| 编号 | 场景 | 判定证据 | 状态落点 | 清理 / 回执 |
| --- | --- | --- | --- | --- |
| F1 | herdr-use 服务面缺席（未挂载或版本无此服务） | `ctx.get("herdrUse")` 取不到 | — | 工具**不注册** + 告警一次（与 herdr-use 缺 herdr 同姿态） |
| F2 | 建终端失败（herdr 拒绝 / workspace 不可用 / 非自有 workspace） | 服务面 `create` 的错误回执 | `failed`（落记录） | 无残留（服务面保证失败不登记）；`terminal_create_failed` + 原文 |
| F3 | `fffdsh` 提交失败（服务面 `run` 报错） | `run` 的非 ok 回执 | `failed`（落记录） | `close(terminal_id)` 一次回滚；`launch_failed` |
| F4 | 终端的 shell 里没有 `fffdsh`（非 bash/zsh、rc 没加载） | 屏文本匹配 `command not found` / `fffdsh: not found` | `failed`（落记录） | `close` 回滚；`launch_failed` + 屏摘要 + `next`：确认终端的登录 shell 会加载该函数 |
| F5 | `fffdsh` 前置失败：缺 `*_API_KEY` | 屏文本匹配 `fffdsh: 环境中缺少 API_KEY` | `failed`（落记录） | `close` 回滚；`launch_failed` + `next`：在 shell rc 里导出 API key（重开终端生效） |
| F6 | 认领超时（构建慢 / profile 未挂 session-channel / 会话没产生事件 / Redis 端点不同） | `peers` 轮询到 `claimTimeoutSec` 仍无匹配 | `lost`（落记录） | **不关终端**（屏上可能有排障信息）；`next: list` + `close`；回执列可能原因与屏摘要 |
| F7 | 用户接管或外部动作（在终端里退出 dsh / 手动 `herdr_close`） | `list` 探测：`info` 报 `terminal-not-registered`，或 `peers` 掉线且无前台进程 | `lost` | 记录收尾；`close` 幂等归档 |
| F8 | 关闭失败（`/quit` 无效、终端关不掉） | `close(terminal_id)` 失败或超过 `graceSec` 仍有前台进程 | 留在 `closing` | `close_failed` + `next: force=true`；`force` 直接 `close` |
| F9 | 父进程退出 | 正常：herdr-use 的 `process.once("exit")` 同步关掉共享登记表里的终端；`kill -9`：钩子不跑 | 正常：记录标 `closed(reason=parent-exit)`；崩溃：留在原态 | 崩溃残留由下次 `list` 按 label / 终端不存在判 `lost` 后 `close` 归档 |
| F10 | 违反前台约束（命令里出现脱管痕迹） | 文本自检命中 `nohup` / `setsid` / `&` / `disown` / `bg` / `screen` / `tmux` | `failed`（落记录，无对象可回滚） | `launch_forbidden`；**不建终端、不提交任何命令** |

**并发与终端治理**

- `maxLive`（缺省 4）：`starting` / `ready` / `closing` 计入；超限 `limit_exceeded`，不排队。
- `maxRecords`（缺省 50）：超出删最老的终态记录（`closed` / `failed` / `lost`）目录，索引留墓碑。
- `staleAfterSec`（缺省 21600）：非终态记录久未推进 → `list` 标 `stale:true`，只标记不自动杀。
- 两把锁：`spawn` 进程级排他（降低并发启动的 profile 目录写竞争）；其余按 `coagent_id` 串行。

**状态落盘**

- 目录：`sessionPaths.sessionDirFor(父会话 id)/coagent/`；缺服务降级到 `$DSH_HOME/coagent/<父会话 id>/` 并告警一次。
- 索引 `index.json`（`{version:1, records:{...}}`，tmp + rename 原子写，目录 0700）；每记录一个目录 `<id>/`：`meta.json`（命令、cwd、label、`terminal_id`、`session_id`、时间线、`fail_code` / `fail_reason` / `terminal_closed` / `rollback_failed`）、`claim.log`（认领轮询摘要）、`screen.log`（失败时的屏摘要）。回滚本身失败时标 `rollback_failed:true`，记录照样落盘。**不再有** `run.sh` / `task.txt` / `overlay.yml` / `stdout.ndjson` / `exit.code`——命令只有一行 `fffdsh`，结果不在本包。

### 3. 对接口径（暴露 sessionId 之后怎么用）

`spawn` 回执就是交接点。此后 coagent 不参与，调用方按用途选工具：

| 要做的事 | 用谁 | 具体调用 |
| --- | --- | --- |
| 派任务、收结果 | session-channel | `channel_delegate({to: session_id, task, timeoutSec})` → `channel_task status` 轮询；任务取消用 `channel_task cancel` |
| 看忙闲 | session-channel | `session_channel state`（`statusOf(session_id)`） |
| 编组、等级、主从指令 | agent-group | `agent_group add_member({group, name, target: session_id})`，之后 `link` / `send` / `check` 全走该工具 |
| 看屏、插话、按键、中断 | herdr-use | `herdr_read` / `herdr_text` / `herdr_key`（同一 `terminal_id`）；中断忙碌回合用 `herdr_key({keys:["ctrl+c"]})` |
| 列终端、确认残留 | herdr-use | `herdr_list`（逐条带 `foreground` / `registered`） |
| 只清终端、不留记录 | herdr-use | `herdr_close({terminal_id})` |
| 停止并清理 | coagent | `coagent close({coagent_id})`；失败时 `force: true` |
| 重新拉起同类会话 | coagent | 再 `spawn` 一次（旧记录的 `session_id` 仍可用于排障） |

契约边界（写进 README 与工具描述，避免模型误用）：

- `coagent` **不接受** `text` / `task` 参数——它不转发任何对话内容；给 `spawn` 传 `task` 得 `invalid_params` 并提示用 `channel_delegate`。已删除的 `target` 参数同样按 `invalid_params` 拒绝。
- `coagent` **不返回**任务结果、不返回忙闲；`list` 只回答「有哪些记录、终端 / 会话还在不在」。
- `close` 是**整会话收尾**，不是取消一条任务；取消单条任务用 session-channel 的 `taskCancel`，中断当前回合用 `herdr_key`。
- `session_id` 唯一来源是 `spawn` 回执与 `list`；调用方不要用 `cwd:` 寻址猜会话（同 cwd 多会话必然歧义）。
- 需要 resume 历史会话：v1 不做；`fffdsh` 的重启循环（退出码 75）由它自己处理，coagent 不介入。

**真机自检 `coagent/scripts/verify-coagent.mjs`（人工跑，不进 CI）**

脚本只做能自动化的部分（跨进程调模型工具没有通路，故不假装跑通全链）：

1. 自检：`bash -ic 'type fffdsh'` 能拿到函数；交互 shell 环境里有 `*_API_KEY`（只报名字）；herdr CLI 在 PATH 上。
2. 本地守门断言（跑 `dist` 产物）：命令白名单是 `fffdsh`；脱管痕迹一律拒；`target` 参数被拒；不存在的 `cwd` 被拒。
3. 打印人工步骤（在挂载了 coagent 的 dsh 会话里执行）：

| 步骤 | 操作 | 判据 |
| --- | --- | --- |
| 1 拉起 | `coagent spawn({cwd: 仓库根})` | 回执 `cmd:"fffdsh"`、`terminal_id` 在场 |
| 2 认领 | `session_channel peers` | `session_id` 在线且与父会话不同 |
| 3 可见 | `herdr_list` | label 为 `coagent/<id>`、`registered:true` |
| 4 交接 | `channel_delegate` → `channel_task status`；`herdr_read` / `herdr_text` | 任务到终态；屏可见、可插话 |
| 5 收尾 | `coagent close` | `closed`；`herdr_list` 无该 label；`peers` 无该会话 |
| 6 残留 | 全量核对 | 不存在带 `coagent/` 前缀却不在记录里的终端 |

负向（脚本自动）：`cwd` 指到不存在的目录（`cwd_invalid`，不建终端）；`spawn` 传 `target` / `task` 确认被 `invalid_params` 拒绝（说明：正常路径没有可注入命令的入口）。

### 5. 包契约与计划改动文件清单

**包契约**

- `coagent/package.json`：`@dsh-toolset/coagent`、`version 0.1.0`、`type: module`、`main: dist/src/index.js`、`scripts` = `build` / `check` / `test` / `verify` / `watch`、`dsh.bundle.patch: ./cordis.patch.yml`、`engines.node >= 22.19.0`。

## herdr-use 服务面契约（2026-10-23 定稿，抄自主分支追踪文档）

> 来源：项目级 `docs/implementation/2026-10-23-herdr-use-terminal-surface.md` §「服务面」（2026-10-23 commit `c061922`，已并入 main）。本节只抄录契约供本包消费；实现由 I 组落地，代码尚未开始。

**形态**：`ctx.provide("herdrUse", service)`，与工具面的十个具名工具共用**同一份登记表、同一把写锁、同一套会话绑定**；服务面**不经** `tools/pre-execute` 的两道闸（进程内可信 API，消费方自负策略）。依赖姿态不变：`ctx.get("herdrUse")` 取不到时本包不注册工具并告警（F1），不降级到库面。

```ts
export interface HerdrUseService {
  dispatch(action: HerdrUseAction, args: Record<string, unknown>, context?: unknown): Promise<ActionResult>;
  list(context?: unknown): Promise<ActionResult>;
  read(terminalId: string, opts?: ReadOptions, context?: unknown): Promise<ActionResult>;
  info(terminalId: string, context?: unknown): Promise<ActionResult>;
  wait(terminalId: string, opts?: WaitOptions, context?: unknown): Promise<ActionResult>;
  create(opts?: CreateOptions, context?: unknown): Promise<ActionResult>;
  close(terminalId: string, context?: unknown): Promise<ActionResult>;
  label(terminalId: string, label: string, context?: unknown): Promise<ActionResult>;
  text(terminalId: string, text: string, context?: unknown): Promise<ActionResult>;
  key(terminalId: string, keys: readonly string[], context?: unknown): Promise<ActionResult>;
  run(terminalId: string, command: string, context?: unknown): Promise<ActionResult>;
  isRegistered(terminalId: string): boolean;
  readonly config: ResolvedConfig;
}
```

- 选项类型：`CreateOptions` = `foreground?` / `cwd?` / `label?`；`ReadOptions` = `source?` / `lines?` / `format?`；`WaitOptions` = `match?` / `regex?` / `stable?` / `settleMs?` / `timeoutMs?` / `source?` / `lines?`。
- 会话上下文：末参 `context` 可为宿主工具 `exec`、`{ session: { id, cwd } }` 或 `{ id, cwd }` 三种形态；都不传时由 `resolveSession` 兜底，仍取不到返回 `session-unavailable`。本包直接传自己的会话对象即可，不必伪造工具 `exec`。
- 暴露面：只给 `isRegistered` 与 `config`，**不暴露 registry**（防外部误写）；通用 `dispatch` 公开，便于未来扩展。
- 错误码改 terminal 口径：新增 `terminal-required` / `terminal-not-registered` / `ambiguous-terminal`；删除 `pane-required` / `pane-not-registered` / `tab-required` / `tab-not-registered` / `foreign-pane` / `approval-denied`。
- 回执统一为 `ActionResult`；文本截断只在工具渲染层做，服务面返回完整文本。
- `create` 回执字段与工具面 `herdr_create` 对齐：`terminal_id` / `label` / `cwd` / `foreground`；`info` 回执含 `running` / `shell_pid` / `foreground_processes`。

**三处影响（2026-10-23 本轮已落进正文，不再是待办）**

1. **终端单层，没有 `closePane` / `closeTab`**：服务面只有一个终端概念（一个 tab + 自带 root pane，`terminal_id` 取 root pane id），关闭只有 `close(terminalId)`（关整个 tab）。故 `spawn` 回执的 `pane_id` / `tab_id` 收敛为 `terminal_id`，失败回滚也只调一次 `close`。落点：§1 回执与失败码、§2 转移表与 F2-F5 / F8、§4 的 T4 / T5 / T6 / T7 / T9 / T10 / T13、§5 `src/herdr.ts`。
2. **建对象只有 `create`（新 tab）**：服务面不接受「在活动 tab 里切 pane」，本包 §1 的 `target: pane` 选项在服务面无可选面；已裁定的「缺省新建 tab」与新契约天然一致，`target` 参数直接删除。落点：§1 `spawn` 参数表、决策项 12（修订）、§3 契约边界、§4 T3。
3. **命名换轨**：服务面方法 camelCase，工具面是十个具名工具（`herdr_create` / `herdr_run` / `herdr_read` / `herdr_info` / `herdr_close` / `herdr_text` / `herdr_key` / `herdr_label` / `herdr_list` / `herdr_wait`）。正文里的 `herdr_use` / `pane_read` / `pane_send_text` / `pane_send_keys` / `closeTab` / `pane_create_failed` 已全部替换；`closed_with` 的 `pane_close` 改 `terminal_close`，`pane_running` 改 `terminal_running`。
