## 调研（已核）

- 现状成因：`unclosedBlockReason()` 逐行只看**行首 ≤3 空格**判开栏，而 CommonMark 的围栏可以落在**列表项 / 引用块内部**（```` - ```sh ```` 的开栏在容器记号之后）。于是相位错开一格：容器里的**缩进闭行**（````  ``` ````）反被当成开栏 →
  - 单个容器项形态（```` - ```sh ```` + `  pwd` + ````  ``` ````）**误拒**（落盘其实不吞节）；
  - 该形态后再跟一行散围栏则**漏拦**（散围栏成开栏且无闭行 → 真吞掉其后全部节）。
- 量化（上一轮审阅 3 行片段 17576 组扫描）：误拒 697 / 漏拦 8，本轮修复面即这两类。
- 规则依据：CommonMark 的容器（blockquote `>`、列表项 `-` / `*` / `+` / `1.`）在解析时被剥离，其内容按剩余缩进进入块级解析——故「按容器前缀剥离后再判开栏」与真实相位一致。

## 决策

1. **剥离容器前缀后再判**：新增 `stripContainerPrefix(line)`，循环剥掉行首的「≤3 空格 + `>`（可带空格）」与「≤3 空格 + 列表记号（`-` / `*` / `+` / `1.`/`1)` + 至少一个空白）」，最多剥到无容器记号为止；**围栏开栏 / 闭行 / 注释开栏**三项判定统一用剥离后的正文，行内代码剥离也在剥离后的正文上做（注释判定不受行内代码干扰）。
1. **不引入容器栈 / 不解析列表归属**：本守卫只需「这一行的相位」而非完整容器树——要求是**不吞节**，不是渲染正确性；用前缀剥离即可，代价小、可解释。
1. **保留既有保守面**：4 空格缩进（缩进代码块）仍不算注释 / 围栏；主题分隔线（`---` / `***`）不因「像列表记号」被剥离（列表记号后必须跟空白）；未闭合判定与错误文案结构不变（仍带「content 内第 N 行」）。
1. **测试口径转变**：上一轮为记录现状而 pin 的两条（一拒一放）现改为**正确期望**（容器内配对 → 放行；容器内围栏 + 散围栏 → 拒绝），并补引用块、嵌套（```` > - ```  ````）、列表内注释、主题分隔线四类用例。

## 审阅（第一轮，2026-10-05）

只读审阅（旧实现副本 + 新实现，同表 17576 组 3 行片段对照、真值 = marked 重解析「丙节是否被吞」）。结论「需修」，两条都已处理：

1. **[阻断] 闭行也剥容器前缀却不记开栏相位** → 顶层围栏会被容器前缀行误当闭行（```` - ```sh ```` + `  pwd` + 「无缩进散围栏」真吞其后节却放行）。→ 已改为**记录开栏相位**、闭行按开栏形态分治（顶层开栏：同字符 + 无 info + 缩进 ≤3 且本行无容器记号；容器内开栏：闭行须落在同相位族 `[phase, phase+3]`）。
1. **[重要] 容器内未闭合围栏一律拒**（实测 marked 在容器结束处截断 → 不吞其后节）→ 误拒膨胀。→ 已改为**放行**（仅在「顶层开栏未闭合」或「出现相位 / 前缀不符的类闭行」时报错）。

## 决策修订（2026-10-05，第二轮）

第一轮修复后自测仍有 5.7% 漏拦 / 9.7% 误拒（4096 组小样本对照 marked 真值）——**字符串启发式无法穷举容器 / 相位组合**（审阅同一结论）。故改为：

- **判据换成解析器本身**：把 content 代进目标节范围重新解析，比较「改前 / 改后」的**节大纲**（拍平 `层级:标题`）；目标节**之后**、且**不在其子树内**的节若有丢失 → `content_invalid`。等价于「其后节是否从节树消失」这一原始目标，且天然覆盖嵌套容器 / 相位 / 其它未知吞并形态。
- **启发式降级为「文案生成器」**：`unclosedBlockReason()` 保留，仅在判据判定丢节时用来给出「第 N 行围栏未闭合」这类可读成因；不再参与判据。
- 语义微调（与判据一致）：目标节是**最后一节**时，未闭合围栏不会再丢别的节 → 放行；目标节子树可整块重写、标题可改名（都不算丢节）。

对照结果（同一 4096 组样本，真值 = marked 重解析）：**漏拦 0 / 误拒 0**（该样本集不含下述 HTML 空行形态）。
