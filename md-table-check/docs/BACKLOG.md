## 条目详情

**1. 漏检形态筛查**（2026-10-15 登记）

**现象 / 现状** —— 插件在本会话已两次活体触发（2026-10-15: 表头 3 列 / 分隔行 2 列 → 注入修正提示）；其中一次表格位于**回复首行、前面无空行**, 同样被检出 → 「首行无空行」不是漏检形态。现有判定 = 逐行扫描（`src/checker.ts:139-198`）: 某行 `splitCells` 非空且下一行为分隔行即成表, 再逐行比对列数; 其余相近形态未系统核查。

**期望** —— 逐形态给出「报 / 不报」结论; 应报而漏报的补判定与断言; 不该报的写进本文件「已裁定不做」或注释。

**待查形态** —— ① 仅数据行列数不符（表头与分隔行一致）; ② 同一回复多张表（逐张报与 `maxTables` 上限口径）; ③ 表格在回复末尾（无尾随空行）; ④ 单元格含转义竖线 `\|` 或行内代码里的竖线; ⑤ 表格位于围栏代码块内（应不报）; ⑥ 分隔行带对齐标记（`:---:`）; ⑦ 表头与分隔行列数一致但均少于数据行; ⑧ 分隔行不足 2 单元格的极短表。

**落点** —— `src/checker.ts`（判定与逐表收集）、`src/main.ts`（消费者接线与注入文案）、`tests/`（`checker.test.ts` / `main.test.ts` / `tuiParity.test.ts`）。

**验收** —— ① 每个待查形态给出结论并落进 README 或注释; ② 应报而漏报者补判定 + 单测; ③ `npm --prefix md-table-check run check` 与测试全绿; ④ 真机至少复验 2 个形态。

**估时** —— 0.5 天。**优先级** —— P2。**来源** —— 2026-10-15 用户报告（「表格检查没有正常触发」, 指「重新列表」回复）+ 同日两次活体测试（均正常触发 → 转为漏检形态筛查）。
