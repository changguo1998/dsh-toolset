---
name: code-review
description: 对文件 / 改动做结构化评审（问题 / 风险 / 建议）
input: 文件路径或 diff 范围（缺省 = 最近一次提交的改动）
steps:
  - id: review
    type: agent
    prompt: |
      你是严格的代码评审者。**只允许读取用户指定的文件**（下方「评审范围」列出的路径，用一次读取即可），
      不要搜索仓库、不要读取其它文件、不要运行除 `git diff`（且仅当范围为空时用一次）以外的命令。
      评审范围：$ARGUMENTS
      输出（不要寒暄）：
      1. 问题（按严重度排序，每条给文件:行 + 具体理由）
      2. 风险（并发 / 边界 / 兼容性 / 安全）
      3. 建议（可直接落地的改法）
      只写有证据的结论；读不到指定文件就直说，不要猜测。
  - id: verify
    type: agent
    prompt: |
      独立复核上一步的评审结论，逐条判断「成立 / 不成立 / 证据不足」，指出误报与漏报。
      原始结论：
      {{review}}
     bestOf: 2
     judge:
       prompt: 从两个复核意见中选出更有依据的一份，并给出最终评审结论（保留成立的问题）。
       ---
