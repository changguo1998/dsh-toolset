## 待办

- **待办** **#1 同一次触发的多条注入合并为一条**：
  - **现象**：同一边界可能同时触发多条规则 / 消费者（例：压缩后 skill 规则与 symbol-normalizer 的开局指南各自注入一条 user 消息），当前逐条插入——同一回合出现多条 `[RULE]` 类消息，占上下文且可读性差；`maxInjectionsPerTurn` 只限条数、不合并。
  - **期望**：同类的注入合并成**一条**消息送达（一次插入内含多段正文，或一条消息内分节），既省上下文也便于阅读。
  - **待查**：① 「同类」的判定口径——同一边界 / 同一送达路径 / 同一 `source.kind`，是否跨「运行时规则」与「消费者」都合并；② 合并后的送达路径与顺序，`source.summary` 与 notice 怎么标（多条摘要如何呈现）；③ 与 `maxInjectionsPerTurn`、`dedupeInRecord`、cooldown 记账的交互（合并是否影响逐规则的命中记账与去重判空）；④ 一条消息内的分节形式（小标题 / 分隔线）与既有正文风格的一致性。
  - **落点**：`src/engine.ts` 的注入装配（`#fire` 与 `inject.ts` 的写入形态）；口径回写 `README.md` / `docs/DESIGN.md`。
  - **验收**：同一边界两条命中 → 记录里只出现一条注入（含两段正文）；补单测覆盖「合并」与「合并后仍受 `maxInjectionsPerTurn` 限制」。
  - **来源·状态·优先级**：2026-10-01 会话中用户要求新增（讨论「两类注入能否用同样行为」时提出：与其让两条注入各走各的，不如同类合并成一条）。**未开工**。优先级 P2。
