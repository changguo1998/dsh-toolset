## 待办

- **待办** **#1 skill 自动加载的触发条件改为「会话记录被压缩后」（当前为「首个工具调用」）**：
  - **现状**：行为 skill 的自动加载由运行时规则 `skill-autoload-on-unlock` 承载（正文与规则定义见 `TUI/docs/DESIGN.md`「解锁后自动加载行为 skill」）。触发面为 `source: "tool-call"` + `predicates: ["always"]`（对齐「首个工具调用」= 锚定解锁点），`cooldownTurns: 10000` **记账在进程内存**——效果是每次重启进程都再注入一次（哪怕 skill 正文仍在重放的会话历史里），而同一进程内随后上下文被压缩、skill 正文被裁掉时反而不会补注入（冷却已吃掉 + 压缩不是 `tool-call`）。
  - **期望**：触发判据由「发生过工具调用」改为「**会话记录（上下文）发生压缩之后**」——skill 正文真正丢失时才注入；未压缩的重载会话不再重复注入。
  - **接取时裁定（待定，3 处）**：① **压缩信号来源**——宿主是否暴露压缩/resume 折叠事件，或只能从会话记录里读可读标记（需调研）；② **匹配面**——rule-engine 新增 source / predicate，或改由 TUI 侧消费压缩事件后直接注入；③ **语义边界**——按字面改判据后，全新会话（尚未压缩）是否仍需在解锁后首次注入？若「只在压缩后注入」，新会话将一直不加载 skill，需确认这是否为预期。
  - **落点**：待定（预计 `rule-engine/src/` 匹配面 + `~/.dsh/rule-engine/rules.json` 的规则正文 / `description`；口径回写 `TUI/docs/DESIGN.md` 同名小节供重建）。
  - **验收**：① 恢复（重载）一个已加载过 skill、记录未被压缩的会话 → 不再注入；② 记录发生压缩后 → 注入一次；③ 同一进程内后续压缩不重复注入；补匹配面 / 记账口径的单测。
  - **来源·状态·优先级**：2026-10-01 会话中按「重载会话的三条自动注入哪些必要」讨论新增（用户指令）。**进行中**（2026-10-01 接取；追踪文档 `rule-engine/docs/implementation/2026-10-01-skill-autoload-compaction.md`）。优先级 P2。
