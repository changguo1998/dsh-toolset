## 待办

**#1 tui 行非热应用配置变更会重建 fiber 并把 dsh 一起带退出（已修 theme，其余键仍会）**（来源：2026-10-13 修〈运行中执行 colortheme 切主题会让 dsh 退出〉时的遗留面）：**现象** —— profile patch（`~/.dsh/profiles/<p>/cordis.patch.yml`）里改 `tui` 行**除 `theme` 之外**的配置（如 `messageGutter` / `model` / `cwd`）时，dsh-hmr 重载配置 → cordis `Fiber.update()` → `restart()` = 卸载 + 重装 → 本插件 effect 清理 → `disposeApp()` → `renderer.close()` → `process.exit(process.exitCode ?? 0)`（`renderer/index.ts:406`）→ **整个 dsh 退出**。`theme` 已由 `main.ts` 的 `makeConfigHotUpdateHandler`（per-fiber `internal/update` 钩子）就地热应用并否决重启，其余键仍走默认重启路径。**期望** —— fiber 重启 ≠ 进程退出：重建后 TUI 重新起来、会话保留（真退出仍由显式退出路径决定）。**候选修法** —— ① 扩大热应用面（把可热应用的键逐个接进钩子，其余键仍重启）；② 让 `exitOnClose` 在「本 fiber 因重建而卸载」时为 false（需在钩子放行重启时置位、`apply()` 重入后复位），把「fiber 卸载」与「进程该结束」解耦。**风险** —— ② 动 renderer 退出语义与启动器 `75` 号重启契约（`/restart` 依赖 `process.exit` 透传退出码），需真机验证「/quit、Ctrl+D 退出确认、/restart」三条仍按预期结束进程。**落点**：`TUI/src/main.ts`（钩子 + 重启置位）、`TUI/src/renderer/index.ts`（`exitOnClose` 语义）、`TUI/src/app/index.ts`（dispose / finishDispose 的退出职责）。**验收**：dsh 运行中改 `messageGutter` → 进程不退、会话保留、配置生效；`/quit`、双击 Ctrl+C → 退出确认 → 退出；`/restart` 仍以 75 退出；全量 `npm run test:tui` 绿 + 新增用例覆盖「fiber 重启不退出进程」。**估时**：2-4 h。**优先级**：P3（非默认路径，但会丢会话）。〔待办：2026-10-13 登记，详细内容待开工时补〕
