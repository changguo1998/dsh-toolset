## 待办

**#1 盒子缓存失效的回归用例**（来源：2026-10-12 宽度条目收尾）：实测宽度覆盖是「带外输入」，`boxes.ts` 的 `boxCache` 已注册进 `clearLayoutCaches`（提交 `8a53372`），但缺一条用例锁住「宽度覆盖变化 → 盒子缓存失效」。**落点**：`TUI/tests/`（pipeline 层）。**验收**：改前红 / 改后绿。**估时**：0.5 h。**优先级**：P3。〔待办：2026-10-12 登记，尚未写〕

**#2 状态列恢复真滚动（`PgUp`/`PgDn` 现在无作用）**（来源：2026-10-12 状态列 Box 改造的顺带发现, 见 `TUI/docs/archived/2026-10-12-status-column-boxes.md`「实现记录」; **用户 2026-10-12 裁定：走「恢复滚动」**——原「承认不滚动、删键位」方案不采用）：**现状** —— 键位与状态链都在（`PgUp`/`PgDn` → `index.ts:203`/`:220` 的 `status-column-scroll` → `state.statusColumnScroll` → `renderStatusColumn` 的 `scroll` 形参）, 但可见行恒是内容首部：`renderStatusColumn` 先按帧高折叠（L0→L3 逐级尝试, 全放不下才 `capRows` 截到 h 行）, 折叠产物长度**必 ≤ h** → `statusStartFor(len, offset, h)` 在 `len ≤ rows` 时恒返回 0, 偏移永不生效（既有用例「总高超窗口时折叠而非滚动——隐藏条目滚动不可找回」描述的正是这一现状）。**期望** —— `PgUp`/`PgDn` 能滚到被折叠 / 被截断的条目, 且**默认视图（`scroll == 0`）与今天逐字一致**（零回归: 折叠分级、`…(+N项已隐藏)` 计数、`…(+N行)` 兜底都不变）。**口径候选（开工时定稿, 倾向 A）** —— A. **滚动即展开**: `scroll == 0` 走今天的折叠视图; `scroll != 0` 时改在**不折叠的完整行集**（等价地逐级 L3→L2→L1→L0 展开）上开窗, `PgUp` 回 0 即恢复折叠视图; L0 也放得下时 `PgDn` 为无操作（确无更多内容）。B. **状态列恒 L0 内容 + 纯滚动**: 不再按帧高自动折叠, 溢出只在窗口边缘提示——改动小但去掉既有折叠分级（README「状态列」/ `SPEC.md` §15.1 / `DESIGN.md` 与 4 条折叠用例要一并改口径）。C. 只让 `capRows` 截掉的行可滚: 改动最小, 但被 L1/L2 折叠掉的条目（多数情况）仍够不到, 大概率不满足诉求。**落点**：`TUI/src/app/layout.ts`（`renderStatusColumn` / `statusStartFor` / `capRows`）、`TUI/src/app/state.ts`（`statusColumnScroll` 目前只有非负 clamp, 需按实际可滚上限收敛）、`TUI/src/app/index.ts`（键位转发已通, 确认 PgUp/PgDn 步长口径）、`TUI/src/app/layout/hints.ts`（如需状态列焦点下的键位提示）。**验收**：`npm run test:tui` 全绿 + 帧级断言（每行显示宽恒为 `statusColWidth`、无控制字符）+ **默认视图零回归**（对照 `tests/fixtures/status-column-old.ts` 的等价性用例仍全绿）+ 新增「状态列焦点下 `PgDn` 能滚到被 L1/L2 折叠的条目、`PgUp` 回 0 恢复折叠视图」。**估时**：1-2 h（A）。**优先级**：P3。〔待办：2026-10-12 登记；滚动口径开工前与用户确认一次（A/B/C）〕
