#### 活动区渲染

- **待办** **#1 活动区正文换行/空行处 `┃` 标记条断开（对齐历史区口径）**：
  - **现象**：活动区（流式）里 assistant 正文在换行、段间空行处左缘蓝色标记条 `┃` 出现断口；同一段正文定稿进历史区后 `┃` 是连续的。
  - **现状**：历史区把整段正文作为**一个**节点（含显式换行）交付渲染层，`fill.ts:284-307` 的 `decorateRows` 对每个物理行（含空行）都加前缀 → `┃` 连续；活动区是流式分片逐行入 buffer（`state.ts:842` 按 `\n` 拆行），纯空白分片在 `state.ts:853-856`（`dropBlankChunk`）被丢、step 行前的拖尾空行再被 `build-box.ts:484`（`absorbActivityBlank`）吸收，且 `kind=assistant` 的空行节点走 `build-box.ts:307-311` 的「无竖线纯空」→ 这些行没有 `┃`，视觉上即断口。
  - **期望**：活动区的 assistant 正文与历史区**同口径**——空行照常排版渲染（每个物理行、含段间空行都连续带 `┃`）；**思考/推理行保持现状**（只打印不渲染：空思考行跳过、紫色 `┃`、紧凑单行等既有语义不变）。
  - **待确认**：断口是「纯空白分片被丢」还是「空行节点无前缀」造成——复现时对照缺口位置（模型输出两段带空行的正文即可）。
  - **落点**：`TUI/src/app/state.ts`（`dropBlankChunk` / `streamBreak` 判据——需区分「宿主每步补发的空锚点」与「正文内部空行」）、`TUI/src/app/layout/build-box.ts`（`absorbActivityBlank` 与非 final / 空行分支）、必要时 `fill.ts` 的前缀策略。
  - **验收**：真机——活动区正文含段间空行与长行软折行时 `┃` 连续无缺口；历史区与思考行行为不变；补渲染帧用例，断言「正文块内每个物理行（含空行）均以 `┃` 起」。
  - **来源·状态·优先级**：用户 2026-10-01 指令（「活动区换行时标记条会断，要和历史区一样即使空行也正常排版渲染；思考、推理的内容不变，只打印不渲染」）。**进行中**。优先级 P2，工作量约 1 h。

#### 焦点框

- **待办** **#4 焦点框只改颜色：不得覆写内容列、不得新增边框（含状态列）**：

#### 历史区内容

- **待办** **#6 正文被思考/工具行打断时只有最后一段进历史区，前段被丢**：
  - **现象**：一条回复的正文若被思考行（或工具 / notice 行）打断成多段，**只有最后一段**进历史区；前面的正文段先留在活动区，下一次用户输入触发 `turn-begin(clearActivity=true)` 时被整类清除 → 永久丢失。真机实例（2026-10-01）：回复首行 `## 机制本体…` 之后出现一句思考 `Let me write it.`，该首行此后再未出现在历史区。
  - **现状**：`state.ts:1075-1095` 的 `markFinalSummary`（`turn-end` 调用）只把「本回合最后一段连续 assistant 行」标 `final: true`；`state.ts:1136-1149` 的 `appendTurnSeparator(clearActivity=true)` 会 `filter` 掉 `thinking` / `tool` / `notice` / **非 final 的 assistant** 行；`build-box.ts:298` 按 `line.final` 分流两个 pane。三者叠加即「前段正文永久消失」。与 `state.ts:835` 的既定口径（思考 / 正文分属活动区与历史区两个窗口 = 正文应进历史区）不一致。
  - **期望（用户 2026-10-01 两次裁定后的最终口径）**：历史区只放**最后的总结与正式回复**；工具调用前后的简短说明不进历史。**分块边界 = `[step 变化 | 工具调用行]`**（thinking / notice / 空行**不**切割），**取最近一块的正文**移入历史区（整块全部行，不再受「≤6 行」或「连续段」限制）；更早的块留在活动区（下回合随活动区清空）。因 thinking 不再是边界，原「被思考打断即丢前段」的问题自然消失。
    - **实现含义**：buffer 行需带 step 标（append 时取当前 `state.stepGroup.step`，`step/start` 已在维护，见 #7）；`markFinalSummary` 改为「按 `[step 变化 | 工具调用行]` 切块 → 取最近一块的全部 assistant 行标 `final`」（比"末步"更准：同一步内工具调用之后的正文会切成新块）。
    - **边界**：① 最近一块只有宿主补发的 `"\n\n"` 空锚点时无内容可移（正常）；② 正式回复若跨两个 step（中途夹工具调用），只有最后一块进历史（用户已认可）。
