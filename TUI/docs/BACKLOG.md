**#2 状态列内容改为 Box 构建（复用排版库）**（来源：2026-10-12 真机复核 + 用户裁定「也走排版流水线」, 「只需要构建好 box, 后续排版可以复用」）：**现象** —— 状态列某一行只显示到一半, 右缘竖线与该行右侧区域内容全空, 内容没有被挤到下一行; 按 `Ctrl+S` 隐藏状态列后恢复正常。**根因（已定位, 原诊断作废）** —— `goalHistoryRows`（`layout.ts:800`）对完整 objective 直接 `wrapLine`, 未先按 `\n` 切分; 宿主 objective 含 `\n` 时裸换行被终端执行成真实换行, 该行 `ESC[K` 之后不再回填、后半截写到下一行又被下一行重绘覆盖。同类缺口（机制不同, 只有本条有真机实证）: `todoItemRows`（`:821`）、`agentItemRows`（`:894`→`wrapWithHanging`）、`jobItemRows`（`:849`, 完全不折行）。**现状** —— 状态列不走六步流水线: `renderStatusColumn`（`:1177`）自建行, 宽度取自 `metricsFor` 公式而非 `measure` / `allocate`; 2026-10-09 决定明确把状态列 / 标题栏 / 输入区 / 提示区 / 面板排除在节缓存外（`docs/archived/2026-10-09-layout-segment-cache.md:288`）。**期望** —— 状态列内容构建成 Box（Paragraph / StyledText / v / h / spacer）, 复用 `measure` → `allocate` → `fillToList` 出行（照 `fillPanelBox`, `layout.ts:1294-1304`）; 排版库自带物理行切分（`measure.ts:80`、`fill.ts:475`、`build-box.ts:88`）, 裸 `\n` 类问题随之消除。**顺带修正**: `SPEC.md:94` 与 `DESIGN.md:173` 两句描述与代码不符（写成像已进 Box 排版管线）, 收尾时对齐。**落点**: `src/app/layout.ts`（状态列块构建与出行）、`src/app/components/`（如需 Box 生成器）。**验收**: 全量 `npm test` 绿 + `npm run check` 干净 + `npm run build` 通过 + 帧级断言（状态列每行宽恒为 `statusColWidth`、行文本不含控制字符）+ 真机目视（多行 objective 的历史 goal）。**估时**: 4-8 h。**优先级**: P1。〔开工: 2026-10-12, 追踪文档 `docs/implementation/2026-10-12-status-column-boxes.md`; 实现方案已定, 见该文档「决策」D1-D5〕
