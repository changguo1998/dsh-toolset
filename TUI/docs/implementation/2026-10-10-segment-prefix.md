# 段级前缀：容器 `prefix` 下传到后代叶子 + 行级前缀上提（接取条目：`TUI/docs/BACKLOG.md`）

状态：调研 / 决策（实现待接续）　　开启：2026-10-10　　关闭：—
本文件是本任务唯一的过程记录与文档变更落点；计划外的文件不改。

## 目标

同一正文段被拆成多个叶子（markdown 段落 / 代码块 / 引用 / 列表 / 表格）时，**每行都带且只带一个段前缀**（如思考 `┃`、引用 `│`、列表 `•`），段容器自身产生的行（子块之间的空行）也带；窄列 `prefix.minWidth` 降级照常生效；既有帧断言不回归。

## 调研（走读 + 行号定位）

- **前缀当前挂在叶子上**：`box.ts:26-33` 的 `prefix { text, style, minWidth }` 是 `BoxBase` 字段，`fill.ts` 的 `decorateRows`（`:268-295`）把 `p.prefix` 拼到**该叶子的每一行**前（`:271-273`），所以「单叶子内折行不打断」已经成立。
- **一段多叶子时各自为政**：`build-box.ts` 五处行级前缀——`:333`（思考）、`:416`、`:473` / `:479`（引用 / 列表，`bar` 复用）、`:607`（另一处渲染分支）——都挂在具体行 / 叶子上。
- **容器不带前缀**：段容器是 `boxes.ts:342-352` 造的 `kind:"layout"` + `role:"block"` 盒；它只负责把条目盒子按到达顺序装进去，自身没有 `prefix`，因此**容器产出的行**（子块之间的空行、表格与段落之间）没有前缀。
- **测量按叶子扣前缀宽**：`fill.ts:365-367` / `:415-417` 用 `prefixW = displayWidth(p.prefix.text)` 从可用宽里扣；`SPEC.md` §2（`:22`、`:102-103`）的测量规则也是按叶子写的。
- **与已关闭条目〈边界空行丢竖线〉互补**：那条管 **pane 边界空行**（不属于任何盒子，已在 `rows.ts` 的 `fillBoundaryBars` 处理）；本条管**段内多叶子**的一致性。若将来把「段间留白」也改为由段容器产出，可顺带覆盖前者。

## 决策

- **D1 前缀升级为「段」的属性**：把 `prefix` 放到 `role: "block"` 的容器盒上（`boxes.ts` 组装段容器时设置），语义 = 该段的每一行都带。
- **D2 fill 下传**：容器布局时把自身 `prefix` 传给**全部后代叶子**；叶子自带 `prefix` 时**叶子优先**（如工具行首行 `○`），避免容器覆盖特殊行。
- **D3 容器自有行也带**：容器在两个子块之间产出的空行同样挂前缀（这正是「段内空行也带」的验收点）。
- **D4 行级前缀上提**：`build-box.ts` 的五处行级 `prefix` 改为**在段容器上设置一次**（同一段内不再逐叶子挂）——否则下传后会出现两个 `┃`。
- **D5 测量口径一并上提**：可用宽由**容器**扣一次前缀宽，子叶在扣减后的 rect 内排版；叶级 `prefixW` 逻辑保留给「叶子自带前缀」的情形（工具行悬挂缩进）。`SPEC.md` §2 的两处测量规则同步改写。
- **D6 `minWidth` 降级不变**：`prefixVisible` 的判据（`vw < minWidth` 不挂）保持，只是判定发生在容器层（窄列整段一起降级，不再出现「同一段里有的叶子有竖线、有的没有」）。
- **D7 分两步提交**（实现时）：① 容器前缀 + 下传 + 测量上提 + 五处上提（一条提交，行为一次到位，避免中间态出现双前缀或丢前缀）；② 文档（SPEC §2）与回归用例补齐。
