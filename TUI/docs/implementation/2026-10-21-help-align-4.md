# /help 列表改为 4 空格档位缩进（接取条目：TUI/docs/BACKLOG.md「`/help` 的列表条目按字母表顺序排列, 缩进对齐以 4 个空格为单位」）

状态：规划　　开启：2026-10-21　　关闭：—
本文件是本任务唯一的过程记录与文档变更落点；计划外的文件不改。

## 目标

`/help` 的两段列表（开头「按键：」段、其后「本地命令：」段）改为按 4 个空格为单位对齐描述列——每行独立落档、行首缩进保持现状 2 列、命令与描述之间至少 1 空格；折行续行仍悬挂到**该行**描述列。命令段继续保持字母序（已具备），按键段保持固定功能序（用户 2026-10-21 裁定）。

## 调研

（来源：源码 `TUI/src/app/layout/help.ts`、`TUI/src/app/index.ts`、`TUI/src/app/layout/build-box.ts`；测试 `TUI/tests/help.test.ts`、`TUI/tests/pipeline-app.test.ts`；规格 `TUI/docs/SPEC.md` §15.6、`TUI/README.md`）

1. **排版实现**（`help.ts`，共 107 行）：`helpTableLines(rows)` 为纯函数，输出 `{ text, hanging, noCompact }[]`。现状常量——行首缩进 `HELP_MARGIN = 2`、命令列与描述列之间固定 2 列间距 `HELP_GAP = 2`、命令列宽 = `min(全表最长命令显示宽, HELP_CMD_MAX = 10)`。命令显示宽超上限时拆成两条独立行（命令独占一行 + 描述另起一行、缩进到描述列起点），避免单个长命令把整表撑宽；补白按 `displayWidth`（CJK 安全）。
2. **两段的描述列现状**：「按键：」段最长键宽 9（`PgUp/PgDn` / `$ / < / !` / `Backspace`）→ 描述列 = 2 + 9 + 2 = **13**；「本地命令：」段有 `/provider、/effort (/thinking)`（30 列）、`/verbose think|tool|step`（23）、`/symbol-unify on|off`（20）、`/clearscreen (/cls)`（19）等超上限命令 → 列宽封顶 10 → 描述列 = 2 + 10 + 2 = **14**。两段不一致，且 13 / 14 都不是 4 的倍数。
3. **消费面**：`App.helpLines()`（`index.ts:5495-5680`）产出「段标题 + 表中行 + 段尾」结构化行；按键段数据手写固定功能序（`index.ts:5622-5625` 注记），命令段经 `sortHelpRows` 排序（`index.ts:5675`，`sortHelpRows` 按首个命令名去 `/` 大小写不敏感稳定排序，`help.ts:98`）。两段都走 `helpTableLines`，`/help` 经 slash 本地表 `notice` 的 `lines` 字段进入渲染。
4. **渲染口径**：`hanging` / `noCompact` 随节条目带进流水线（`pipeline/{sections,rows,boxes,types}.ts`），`build-box` notice 分支把 `hanging` 落到 `StyledText.hanging`，描述超 pane 宽时续行停靠描述列、`noCompact` 行在 `/collapse on` 下仍完整折行。`BufferLine.hanging` 只在 `/help` 生效。
5. **测试现状**：`tests/help.test.ts` 共 8 例，其中 5 例直接 import `HELP_MARGIN` / `HELP_GAP` / `HELP_CMD_MAX` 并用「全表最长命令宽 + 固定间距」拼期望前缀；2 例走 `buildContentRows` 断言渲染层续行缩进；1 例锁定字母序与排序键。`tests/pipeline-app.test.ts:487` 只断言 `hanging` 是数字（不锁值），其余引用 `/help` 的用例只断言出现「本地命令：」等文本。
6. **文档现状**：`SPEC.md` §15.6「/help 双列表格」写明「每行 = 行首 2 列缩进 + 命令 + 补白 + 2 列间距 + 描述」「描述列起点 = 2 + 上限(10) + 2 = 14 列」；`README.md:273` 的 `/help` 行只描述续行对齐与按键段，未写列宽口径；`DESIGN.md:342` 只提到「帮助文本与 `/help` 双列表格同源」，无数字。

## 决策

1. **档位规则**（用户 2026-10-21 裁定 **b**：每行独立落档；行首缩进「保持现在的不变, 4 缩进相对行首」）：`stops(w) = 4 × (⌊min(w, HELP_CMD_MAX) / 4⌋ + 1)`，描述列 = `HELP_MARGIN + stops`（`w` = 该行命令的 `displayWidth`）。因 `stops` 恒大于 `w`，命令后至少 1 空格。示例：`/a`（2）→ 4（补 2 空格, 绝对列 6）、`/bb`（3）→ 4（补 1 空格, 同列）、`/ccc`（4）→ 8（补 4 空格, 绝对列 10）、宽 9 / 10 → 12（绝对列 14）。
2. **拆行与封顶**：`w > HELP_CMD_MAX` 仍拆两行；描述行缩进取**封顶后的档位**（`4 × (⌊10/4⌋ + 1) = 12`，绝对列 14），命令行 `hanging` 同值——否则 30 列的命令会把描述列推到 34 列。`HELP_CMD_MAX = 10` 与 `HELP_MARGIN = 2` 保持原值。
3. **字母序**：命令段继续用 `sortHelpRows`（已具备, 不改代码）；按键段保持固定功能序（用户 2026-10-21 裁定 **a**，沿用 2026-10-16 的「按功能相邻好查」裁定），不改字母序。
4. **常量面**：新增导出常量 `HELP_UNIT = 4`（档位单位）；删除 `HELP_GAP`（新规则下无固定间距，最小 1 空格由档位保证）；`HELP_MARGIN` 与 `HELP_CMD_MAX` 保留（后者继续承担拆行阈值与档位封顶）。
5. **接口不变**：`HelpRow` / `HelpTableLine` 与 `helpTableLines(rows)` 签名不变；`hanging` 由「全表一个值」改为「逐行取值」，其余字段语义不变。
6. **CJK 与宽字符**：档位按 `displayWidth` 计算（与现状同口径），不按码点数；宽 2 的顿号、全角括号照常计入。
7. **可接受后果**：描述列不再全表一列——宽命令的描述在 14 列、短命令在 10 列（`/help`、`/quit`、`/copy`、`/jobs`、`/init`、`/fork`、`/task`、`/goal`、`/loop` 等宽 5 的命令；`/guard`、`/agents` 宽 6/7 → 10），视觉上呈阶梯状；这是用户选定口径的直接结果，记入「偏差」节备案。

### 步骤

1. 改 `help.ts`：`stops = HELP_UNIT * (Math.floor(Math.min(w, HELP_CMD_MAX) / HELP_UNIT) + 1)`，`descCol = HELP_MARGIN + stops`；未超宽行 `text = 缩进 + 命令 + (descCol − HELP_MARGIN − w) 空格 + 描述`；超宽行拆两条、两条 `hanging = HELP_MARGIN + stops(HELP_CMD_MAX)`。

### 验收

- 三例逐字符成立：`/a` + 2 空格、`/bb` + 1 空格（两者描述列相同, 绝对列 6）、`/ccc` + 4 空格（绝对列 10），行首缩进均为 2。
