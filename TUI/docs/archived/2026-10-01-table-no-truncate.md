# 历史区表格不截断：取消格内 `…`（过窄退普通文本行）（接取条目：`TUI/docs/BACKLOG.md`「历史区表格不截断：格内不再出现 `…`」）

状态：已完成　　开启：2026-10-01　　关闭：2026-10-01
本文件是本任务唯一的过程记录与文档变更落点；计划外的文件不改。

## 目标

表格单元格**永不截断**（不再出现格内 `…`，内容不丢）；列宽求解中「连最小列宽 `minW` 都放不下」的分支由「按 minW 比例分配 + 格内省略号截断」改为**放弃表格**（`tableBox` 返回 `null`，调用方沿用既有的「过窄退回普通文本行」降级）。

用户裁定（2026-10-01，追问确认）：`…` 截断是问题（不出现格内省略号）；该分支的展现形态用户明确「不用管这种情况」→ 按既有兜底处理、不新增形态。

## 计划改动文件清单

代码：

- `TUI/src/app/layout/table.ts`：`fitCols` 返回 `number[] | null`（`minSum > avail` → `null`）；`tableBox` 在 `null` 时返回 `null`；`cellLeaf` / `rowBox` 去掉 `truncate` 参数与格内截断分支；移除 `truncateSegs` 依赖。

测试：

- `TUI/tests/table.test.ts`：「极窄」用例改为断言 `tableBox(...) === null` + 集成路径退回普通文本行（无 `…`、内容完整可读）。

文档：

- `TUI/docs/SPEC.md` §3.2（窄终端压缩 / minW 下限）与 §15.6（markdown 表格·列宽求解）口径同步；`TUI/docs/BACKLOG.md` 条目状态维护与收尾清理。
- 本文件。

## 设计

- **单一降级出口**：宽度不足只有两种结局——① 自然宽 / 水位线压缩（可折行，内容完整）；② 容不下 `minW` → `null`（普通文本行）。不再有「第三种」截断形态，`tableBox` 的 `null` 语义与既有「可用宽过窄」路径完全一致（调用点 `build-box.ts` 已有 `if (parsed && box)` 兜底）。
- **不新增降级形态**：没有引入横向滚动 / 溢出裁剪 / 列表化等新形态（用户「不用管这种情况」）。
- **活动区同样生效**：非 final 表格走同一 `tableBox`（宽度预算为活动 pane 宽），故活动区也不截断。
