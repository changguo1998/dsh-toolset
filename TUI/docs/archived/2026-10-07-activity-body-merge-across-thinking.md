# 思考/正文交错时正文分片连排（接取条目：`TUI/docs/BACKLOG.md`「思考 / 正文交错时，正文分片拼接被插入多余换行」）

状态：关闭　　开启：2026-10-07　　关闭：2026-10-07
本文件是本任务唯一的过程记录与文档变更落点；计划外的文件不改。

## 目标

provider 交替发 reasoning-delta 与 text-delta（`正文A → 思考 → 正文B`）时，当前渲染成 `A / 空行 / 思考块 / 空行 / B`，同一段正文被拆开。改成：**只被 thinking / notice 行隔开的相邻正文行连排为一段（直接相接、不插换行）**，并豁免该切点的类型间隔空行；**工具 / step / 用户行 / 分隔线仍是硬边界**。

## 调研（2026-10-07，源码 + 既有文档）

1. **buffer 侧**（`state.ts:896-939` `appendStream`）：首个段落只并入**紧邻同类末行**（`:918-925` 的 `last.kind === kind`）→ 末行是 `thinking` 时正文分片只能 `push` 新行（`:931`）；P5 的 `dropBlankChunk`（`:907-910`）只丢「整段纯空白且上一行异 kind」的分片，正文分片非空白故不受影响。⇒ buffer 里就是 `assistant(A) / thinking / assistant(B)` 三行（子代理 `reduceState` 实测确认）。
1. **渲染侧**（`layout/build-box.ts`）：① `noteActKind`（`:214-231`）在 thinking ↔ assistant 互切处插 1 行空行 → 得到现象里的两处空行（实测两处空行 kind 均为 `plain`，无其它来源）；② 每条非 final assistant 行**各自**产一个叶（普通单行路径产叶点 `:567`），叶文本 = 该行 text，**无跨行拼接**（`:413` 注释明示「buildBox 不做块级连排后处理」）。
1. **既有工具与先例**：`absorbActivityBlank`（`:672-696`）/ `stripTrailingNewline`（`:698-719`）已在做「结构层等价变换」，且工具 run 落盘前、step 分割行前都已有吸收拖尾空行的语义——本条目沿用这套「渲染期等价变换」的路子。
1. **边界语义**：`user`（`:334`）/ `separator` / `step` 头 / 工具行（`toolRun` + `flushToolRun`，`:237` / `:314`）都是独立分支；另实测 `kind === "step"` / `"shell"` 是**独立 kind**（`:587` / `:597`），step 头是 tool-kind 行（`isStepHeader`）⇒ 它们天然是硬边界。
1. **文档口径**：`TUI/docs/SPEC.md:724-731`（活动区类型间隔 #5：语义 / 工具类不插 / step 紧排 / 不算边界 / 实现 / 回归）与 `TUI/docs/DESIGN.md:167`（活动区段同口径）需回写新增的合并/豁免规则；`TUI/docs/archived/2026-10-02-turn-type-gap.md` 是历史记录、不改；`TUI/README.md` 无该口径、不改。
1. 条目原文已给定首选/备选：**首选渲染期合并（不动 state 与滚动锚点）**；备选 `state.ts` 跨行回填的代价是「正文显示顺序提到思考块之前」——子代理实测备选形态渲染为 `[┃AB, 空行, ┃思考]`，正是该代价 ⇒ 首选必须把合并段落在**思考块之后**。

## 决策

**D1｜落点** → **渲染期合并**（`build-box.ts`），不动 `state.ts`、不动 buffer 与滚动锚点（`seq` 稳定、锚点语义不变）。理由：条目首选 + 改 buffer 会把正文显示顺序提到思考块之前（备选方案的已知代价）。

**D2｜合并语义** → 把「只被 thinking / notice 行隔开」的**相邻非 final assistant 行**合并为**一个叶**，叶文本 = 各分片**直接相接**（不插换行、不插空格）；叶**落点 = 该 run 的最后一个正文分片处**（即其间的思考块之后）。⇒ 交错流的渲染顺序变为「思考块 … → 整段正文」。（子代理两轮实测裁定：这是唯一自洽解读——只删空行保留 `A / 思考 / B` 违反「直接相接」；把思考块移到正文后等价于备选代价。）

**D3｜类型间隔豁免** → 被合并的切点**不逐处插** `noteActKind` 的空行；合并时把本 run 记账过的间隔空行**收敛为「只保留 1 行（若原本有），置于合并叶正前方」**（子代理实测：按字面「两处都删」会得到 `[┃思考, ┃AB]`——缺思考↔正文间隔、违反 SPEC #5 与验收④，且既有全量测试抓不住，只有新用例能抓）；合并叶之后按 `lastActKind = "assistant"` 记账，使 run **之后**的思考块仍能拿到「正文 → 思考」间隔。

**D4｜可穿透行与硬边界** → 穿透行 = `thinking`（含空文本与档位过滤者）+ `notice`（条目原文）；硬边界 = `user` / `separator` / `step`（含 step 头）/ `shell` / 任何工具行 ⇒ 遇到硬边界先关闭 run，绝不跨边界合并。

**D5｜参与合并的行** → 仅「**单行、非空、非 fence、非表格/结构化 markdown 路径** 的普通正文分片」，且**只在「已被 ≥1 个穿透行隔开」时才并入**：

- **直接相邻的正文分片不合并**（同一 delta 内含 `\n` 时 `appendStream` 本就产相邻 assistant 行，如列表 / 代码块分片；合并会破坏 markdown 结构 —— 子代理实测按字面实现会红 `tests/layout4.test.ts:1642` / `:1702`、`tests/activity-type-gap.test.ts:42`）；
- 空正文行（`:414`）、含内部换行的行（`:400`）、fence 开关与围栏内行（`:421+`）、表格 / markdown 结构路径（`:529+`）**不参与，且按硬边界处理**（不穿透）。
- **`final` 行也是硬边界**（`build-box.ts:395` 已把 final 与 activity 分流）：不是怕标记差异（子代理实测 `A→思考→B` 无工具/step 边界时 A、B 同属一块、同标 `final`；`A→思考→tool→B` 时只有 B final，但 tool 本是硬边界），而是防实现把 final 当穿透行、把 run 推迟过它。

**D6｜实现形态：合并时才移动（不缓冲正文）** → **正文分片照旧立即产叶**（时间序与流式可见性不变、单分片 run 完全不变），只在**真的发生合并**的那一刻改动已产出的叶：

- run 状态（`bodyRun`）= 「上一个普通正文叶的引用」+「已累计原始文本 `raw`（紧凑模式按整段重新压行）」+「自它以来产出的**穿透行**计数」+「本 run 插入的间隔空行（按节点引用）」；
- 当下一个**普通正文分片**到来且 run 成立（穿透行 ≥1）→ **合并**：把上一个正文叶从 `activityLeaves` 摘出 → 其文本**直接相接**新分片（不插换行/空格）→ 移到当前末尾（即穿透行之后）→ **把本 run 记账过的间隔空行全部摘掉（按节点引用删除，容忍 `indexOf === -1`：可能已被 `absorbActivityBlank` 吸收），只保留 1 行（若原本有）、放在合并叶正前方，并把该空行登记进新 run 的 gaps** → **不产新叶**；叶与 `meta` 沿用**首个**分片（节点原地复用，活动区不消费 `seq` / `line` / `blockId`；`kind` 仍是 assistant）；文本仍走 `actText(..., 1)`（紧凑模式压缩口径不变）；
- 遇硬边界（tool / step / shell / user / separator / final / 含内部换行 / 空行 / fence / 表格与非普通路径 / `inFence` 行）→ run 关闭，之后一切按既有流程。
- **为什么不用「正文入缓冲 + flush」**（子代理模拟的初版）：那会让**单分片 run 也被推迟**——`A, thinking` 渲染成 `[┃思考, 空行, ┃A]`、`A, notice, B` 渲染成 `[提示, ┃AB]`，且 `tests/app.test.ts:4096`（activity-scroll）实测因 tail window 位移变红；更要紧的是流式期正文会「先隐身」直到 flush。改成「立即产叶 + 合并时移动」后，未合并路径**逐字节不变**（子代理 26 例对照实测），只有真发生合并的那一帧把正文段从思考块之前挪到之后；并且合并叶相对**其后的**穿透行仍保持时间序（`A,思考,B,notice` → `[┃思考, 空行, ┃AB, 提示]`，初版会挪到 notice 之后）——这正是 `app.test.ts:4096` 保持绿的原因，也更贴合 D2「落点 = 最后一个正文分片处」。

**验收（单测）**：① `正文→思考→正文` 合并为一个叶、文本相接（不插换行）且思考块仍在活动区；② 工具 / step / 用户 / 分隔线仍切割（不跨边界合并）；③ 空行 / 含内部换行的分片 / fence 行不参与合并且中断 run；④ 帧级：交错场景的活动区行数由「5 行」降为「3 行」；⑤ 既有用例不回归（子代理实测确认仅需**新增**用例）。
