# 无效键提示改到用户输入区（BACKLOG: TUI#3.3.8）

状态：关闭　　开启：2026-09-26　　关闭：2026-09-26

本文件是本任务唯一的过程记录与文档变更落点；计划外的文件不改。

## 目标（人工验收重新梳理的布局约定）

- 活动区 = 面板（问题 / 选项）。
- **用户输入区是绝对位置**：正常模式以 `>` 开头；面板态下切换为临时消息显示区（不显示 `>`），位置在按键提示区**正上方**。
- 按键提示区在用户输入区**下方**，内容始终是常规按键文案。
- **无效键提示显示在整个屏幕左下 —— 即用户输入区那一行**（不是活动区面板内，也不是按键提示区内）。

## 决策

- 撤销 3.3.6 的错误落点：`components/ApprovalPrompt.ts` 的 `ApprovalView.hint` 与面板内提示行整段移除（行分配恢复为 `bodyRows = maxBody`），`layout.ts` 不再向面板传 `hint`。
- 改为复用 3.1.1 的输入区通道：`layout.ts` 的 `noticeFooterLines(...)` 在 `state.approvalHint` 非空时**优先**把该行渲染成 `[无效键] …`（黄色、左对齐、按 footer 宽折行），否则维持原「最近 notice 行」视图；`approvalHint` 由有效键清空后自动切回。

## 测试与证据

- `tests/app.test.ts` 用例改为「审批无效键：提示落在用户输入区（按键提示正上方），面板内不含提示」：断言提示行在面板下方、按键提示区位于其下方、面板区间内不再出现 `[无效键]`、提示内容左对齐。
- 全量 `node --experimental-transform-types --test tests/*.test.ts`：**1142 pass / 0 fail**；`demo --smoke` 43 pass / 0 fail；冻结基线重跑无新增差异；`check` / `build` 通过。

## 收尾

- 条目 3.3.8 标「完成」（3.3.6 的面板内落点已撤销，其条目保留历史记录）；文档回写 `docs/SPEC.md` §7.1 与 `docs/IMPLEMENTATION.md`；本追踪文档归档 `TUI/docs/archived/`。
- 未做：问答面板的无效键提示（问答面板现状本就吞键无提示；如需对齐另立条目）。

## 人工复验结果（2026-09-26，重启后）

全部通过：
- `[无效键] …` 出现在**用户输入区**那一行（平时 `>` 的位置），紧接按键提示区上方；
- 面板内（标题 / 草稿 / 选项之间）不再出现提示；
- 按键提示区保持常规文案（`▶选项·[Enter]提交·…`）；
- 倒计时从 `(30s)` 起（取自 `tui.config.json` 的 `approval.timeoutMs`），按任意键后消失且面板不再自动关闭。
